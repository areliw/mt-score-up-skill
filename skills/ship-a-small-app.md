# MT ทำเครื่องมือเล็กให้ทีมใช้

ตัวช่วยตัดสินใจตอนอยากทำเครื่องมือเล็ก (calculator คำนวณ dilution/dose, แบบฟอร์มเก็บข้อมูล, mini-dashboard, ตัวช่วยแปลผล) ให้ทีมใช้จริง — เน้น "เลือกวิธี + ส่งให้ใช้ได้จริง + ไม่รั่วข้อมูล" ไม่ใช่สอน deploy ทีละปุ่ม

> **กฎ #1:** เริ่มจาก **"เล็กสุดที่ใช้ได้จริง" (1 หน้า 1 งาน)** + ลอง **no-code/low-code ก่อน**เขียนเอง — อย่าสร้างระบบใหญ่ตั้งแต่แรก (ส่วนใหญ่ตายก่อนเสร็จ)
> **กับดัก #1 (ขั้น hard):** แอปที่เก็บ/แสดง **ข้อมูลคนไข้** ต้องคิด **auth + PDPA + ที่เก็บข้อมูล ตั้งแต่แรก**. แอปที่ "ใครเปิด URL ก็เห็นข้อมูล" = ผิด. ไม่ชัวร์เรื่อง security → **อย่าใส่ข้อมูลจริง** (ใช้ค่า de-identified/สมมุติ) (เชื่อม `digital-judgment`)

> **verify-first:** decision-support ไม่ใช่คำตอบสุดท้าย — เช็คข้อเท็จจริงก่อนเชื่อ (คู่กับ `anti-hallucination`) · สูตรที่กระทบการตัดสินใจต้อง verify

## ใช้เมื่อ
- มีไอเดียเครื่องมือเล็กแต่ไม่รู้ทำด้วยอะไร/จะให้ทีมใช้ยังไง
- กลัวข้อมูลคนไข้รั่วถ้าเอาขึ้นเน็ต
- ทำเครื่องคำนวณทางคลินิกแล้วกลัวสูตรผิด

## วิธีใช้
วาง skill นี้ + เล่าว่าเครื่องมือทำอะไร/ใครใช้/มีข้อมูลคนไข้ไหม/มีเวลา-ทักษะแค่ไหน → AI ช่วยเลือกวิธีสร้าง + เตือน security/PDPA + ชี้จุดที่ต้องมีคนตรวจ

## วิธีตัดสินใจ (AI: ทำตามนี้)

### Fork 1 — no-code/low-code vs code
- **No-code**: Google Forms + Sheets, AppSheet, Glide — ฟอร์มเก็บข้อมูล/calculator ง่าย, เร็ว, ไม่ต้องเขียน
- **Low-code (โค้ดน้อย, ให้ AI ช่วย)**: Streamlit / Gradio — interactive, คำนวณ, mini-dashboard
- **เว็บเต็ม/แอปจริง** — มักเกินจำเป็นสำหรับเครื่องมือทีมเล็ก (เลือกเฉพาะเมื่อต้อง scale จริง)
- เลือกตาม: ความซับซ้อน · ทักษะที่มี · ใครดูแลต่อ

### Fork 2 — hosting (ตามความอ่อนไหวของข้อมูล)
- **ไม่มีข้อมูลคนไข้** (calculator ล้วน) → cloud ฟรี (Streamlit Cloud/Vercel) ได้
- **มีข้อมูลคนไข้** → **ภายใน รพ.เท่านั้น** (intranet/เครื่องตัวเอง) หรือมี auth จริง — อย่า public cloud ฟรีที่ไม่มีการป้องกัน
- ถามตัวเอง: ถ้าลิงก์หลุด ใครเห็นอะไรได้บ้าง?

### Fork 3 — security ขั้นต่ำ
- **auth** (ใครเข้าได้) · ไม่ฝัง key/secret ในโค้ด · validate input · HTTPS · **ลบข้อมูลทดสอบจริงออกก่อน deploy** (เชื่อม `vibe-coding-safely`)

### Fork 4 — ให้ AI ช่วยสร้าง
- ขอ AI เขียน Streamlit/ฟอร์ม + อธิบายโครง
- **verify ทุกการคำนวณที่กระทบการตัดสินใจ** — calculator dose/dilution/หน่วย ผิด = อันตราย → ต้องมีคนตรวจสูตร + ลองเคสรู้คำตอบ (เชื่อม `anti-hallucination`)

### Fork 5 — ดูแลต่อ (อย่าให้ตาย)
- ใครแก้ได้ถ้าพัง · ใครอัปเดต · มี backup ข้อมูลไหม
- เครื่องมือที่ทีมพึ่งพาแต่คนเดียวดูแล (bus factor 1) = เสี่ยงสูง → เขียน doc สั้นๆ + สอนอีกคน

## กับดัก (Anti-patterns)
- #1 สร้างใหญ่/ครบทุกฟีเจอร์แต่แรก → ไม่เสร็จ/ไม่มีใครใช้
- #2 ข้อมูลคนไข้บน public cloud ไม่มี auth (กับดัก #1)
- #3 ฝัง API key/รหัสในโค้ดที่แชร์
- #4 calculator ทางคลินิก (dose/dilution) ไม่ verify สูตร + ไม่มีคนตรวจ
- #5 ไม่ลบข้อมูลทดสอบจริงก่อน deploy
- #6 ไม่คิด PDPA/security จนสร้างเสร็จแล้วค่อยแปะทีหลัง
- #7 ไม่มีคนดูแลต่อ/ไม่มี doc → พังแล้วจบ
- #8 ไม่ validate input → ผู้ใช้กรอกมั่ว แอปคำนวณเพี้ยน

## ช่องสำหรับผู้เชี่ยวชาญเติม
> - เครื่องมือที่ทีมคุณอยากได้จริง (และตอนนี้ทำมือ/Excel กันอยู่)
> - นโยบาย IT รพ.: อะไร host ภายในได้, อะไรห้ามออกเน็ต, ขอ auth/เซิร์ฟเวอร์ในยังไง
> - สูตร/ตรรกะทางคลินิกในเครื่องมือ ใครเป็นคนรับรองความถูกต้อง

NOTE: ขั้นตอน deploy/เซ็ตเซิร์ฟเวอร์ละเอียด → ถาม AI แยก/ดูคู่มือ tool; skill นี้ช่วย "เลือกวิธี + กัน security/PDPA + รู้ว่าต้องมีคนตรวจตรงไหน"
