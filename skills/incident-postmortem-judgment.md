# ถอดบทเรียนหลังเหตุ + CAPA

หลังเกิด incident / NC / near-miss ในแล็บ — ช่วยวางกรอบสอบสวนให้เจอ **root cause ตัวจริง** แล้วออก CAPA ที่ปิดเหตุได้จริง ไม่ใช่แค่ "เตือนคนให้ระวัง" แล้วปล่อยให้ระบบเดิมพังซ้ำ

> **กฎข้อ 1:** แยก **root cause** ออกจาก **symptom** ให้ขาด ก่อนเขียน CAPA. "เจาะผิดคน" คืออาการ — root cause คือ "ระบบ verify ตัวตน 2 ตัวระบุไม่บังคับใน SOP" → ถ้าแก้แค่อาการ (ตักเตือนคนเจาะ) เหตุจะกลับมากับคนถัดไป.
> **กับดักข้อ 1:** ออก CAPA เป็น "อบรมซ้ำ + เพิ่มความระมัดระวัง" = แก้ที่คน ไม่ใช่ระบบ → audit ไม่ผ่าน + เกิดซ้ำ. action ที่ระบบบังคับให้พลาดยากขึ้น (barcode บังคับ scan, double-check ล็อกใน LIS, ตัดขั้นที่พึ่งความจำ) > action ที่พึ่งวินัยคน.

## ใช้เมื่อ
- เกิด incident จริง: ปล่อยผลผิด, sample swap/เจาะผิดคน, ลงค่าผิด, แจ้ง critical ช้า/ไม่แจ้ง
- near-miss / catch-before-release — จับได้ทันแต่ต้องถอดบทเรียนกันซ้ำ
- NC จาก internal audit / EQA fail / ข้อร้องเรียนจาก ward-แพทย์-คนไข้
- ต้องเขียน CAPA report / RCA ส่ง QM ตามรอบ ISO 15189 / LA
- ของหมดอายุหลุดใช้, QC ผ่านแต่ผลคนไข้พลาด — "หลุดมาได้ยังไง"

## วิธีใช้
วาง skill นี้ + เล่าเหตุ (เกิดอะไร, จับได้ตอนไหน, ผลกระทบถึงคนไข้รึยัง) → AI จะช่วยไล่ timeline, ขุด root cause ด้วย 5-whys/fishbone, แยก correction/corrective/preventive, แล้วร่าง CAPA ให้ปิดที่ระบบ

---

## ก่อนเริ่ม — เช็ค 4 อย่าง (ขาดอันไหน บอกก่อน อย่าเพิ่งสรุป root cause)
- [ ] **เหตุการณ์ชัด + timeline ได้** — ใคร/อะไร/เมื่อไหร่/จับได้ตอนไหน (ไม่ใช่ "เหมือนจะมีปัญหา")
- [ ] **ผลกระทบประเมินแล้ว** — ถึงคนไข้รึยัง? ต้องเรียกผลคืน/แจ้งแพทย์/look-back ไหม (correction ด่วนต้องทำ **ก่อน** สอบสวนสาเหตุ)
- [ ] **หลักฐานยังอยู่** — LIS log/audit trail, QC chart, หลอด/ฉลาก, lot/expiry, ใบ request (อย่าให้ถูกลบ/ทับ)
- [ ] **คุยแบบ blameless** — คนที่อยู่ในเหตุยอมเล่าตามจริง (ถ้ากลัวโดนลงโทษ จะปิดข้อมูล → root cause หาย)

## วิธีหา root cause (AI: ทำตามนี้)

### ขั้น 1 — Timeline ก่อนเสมอ
เรียงเหตุการณ์ตามเวลา: รับ sample → ลงทะเบียน → ตรวจ → QC → verify → รายงาน → จับเจอ. ทำให้เห็น "จุดที่ควรจับได้แต่หลุด" ชัดขึ้น ก่อนจะไปขุดสาเหตุ

### ขั้น 2 — แยก 3 ระดับให้ขาด (อย่าหยุดที่ชั้นแรก)
| ระดับ | คำถาม | ตัวอย่าง (sample swap) |
|---|---|---|
| **Symptom** (อาการ) | เห็นอะไรผิด? | ผล Hb คนไข้ A ไปอยู่ใน report คนไข้ B |
| **Direct cause** (สาเหตุตรง) | อะไรทำให้เกิดอาการ? | หลอด 2 คนวางคู่กัน ฉลากเขียนมือ สลับตอน aliquot |
| **Root cause** (รากระบบ) | ทำไมระบบยอมให้เกิด? | SOP ไม่บังคับ scan barcode ทุกขั้น + ไม่มี 2-identifier check |

### ขั้น 3 — 5-Whys (ขุดจนถึงระบบ ไม่ใช่ถึงคน)
ถาม "ทำไม" ซ้ำจนคำตอบเป็น **ระบบ/กระบวนการ** ไม่ใช่ "เพราะคนไม่ระวัง". ถ้าคำตอบสุดท้ายลงที่ "คนพลาด/คนลืม" = ยังขุดไม่ถึงราก → ถามต่อ "ทำไมระบบถึงปล่อยให้คนพลาดตรงนี้ได้"

### ขั้น 4 — Fishbone เมื่อเหตุซับซ้อน/หลายปัจจัย
แตกสาเหตุตาม 6M: **Man · Machine · Method/SOP · Material(น้ำยา/lot) · Measurement(QC/cal) · Environment**. ใช้เมื่อ 5-whys เส้นเดียวไม่พอ (เช่นปล่อยผิดจากหลายเหตุประกอบกัน)

### ขั้น 5 — "หลุดมาได้ยังไง" (defense ที่ควรจับ แต่ไม่จับ)
ถามแยกอีกชั้น: **ทำไม QC/verify/double-check/LIS-flag ถึงไม่ดักไว้?** นี่คือชั้นที่สำคัญสุดของ ISO spirit —
- QC ผ่านแต่ผลคนไข้พลาด → QC คุม precision แต่ไม่จับ pre-analytical/post (หลอดผิด, ลงค่าผิด) → ดู `clinchem-judgment`
- auto-verify ปล่อยค่าผิดผ่าน → rule/delta-check หลวมไป
- ไม่มีใครจับ → ขั้นนั้นไม่มี defense เลย = ช่องโหว่ระบบ

### ขั้น 6 — แยก 3 ชนิด action (อย่าสับ — audit ดูตรงนี้)
| ชนิด | นิยาม | ตัวอย่าง |
|---|---|---|
| **Correction** (แก้เฉพาะหน้า) | ดับไฟเหตุนี้ทันที | เรียกผลผิดคืน, ออกผลแก้, แจ้งแพทย์, look-back คนไข้ที่กระทบ |
| **Corrective** (แก้ราก กันเหตุเดิมซ้ำ) | ปิด root cause ของเหตุนี้ | บังคับ scan barcode ทุกขั้นใน SOP + LIS lock |
| **Preventive** (กันเหตุประเภทเดียวกันที่อื่น) | กวาดความเสี่ยงคล้ายกันทั้งระบบ | ตรวจทุก workflow ที่ยังเขียนฉลากมือ แล้วแก้พร้อมกัน |

> **VERDICT:** CAPA ที่มีแต่ Correction = ยังไม่ปิดเหตุ. ที่ผ่าน audit ต้องมี **Corrective ที่แก้ระบบ** + ระบุ **เจ้าของ + กำหนดเสร็จ + วิธีพิสูจน์ว่าได้ผล (effectiveness check)** ไม่ใช่แค่ "ดำเนินการแล้ว"

### ขั้น 7 — ปิดวงด้วย effectiveness check
CAPA ไม่จบตอนทำเสร็จ — ต้องนัดทวนภายหลัง (เช่น 1-3 เดือน) ว่าเหตุไม่กลับมา + ตัวชี้วัดดีขึ้นจริง. ถ้ากลับมา = root cause ผิด ขุดใหม่

## กับดัก (Anti-patterns)
- **หยุดที่ "human error" แล้วออก CAPA = อบรม/ตักเตือน** — แก้ที่คน ระบบเดิมยังพัง → เกิดซ้ำกับคนถัดไป (กับดักอันดับ 1)
- **ปิดที่อาการไม่ใช่ราก** — แก้เคสนี้แต่ root cause ยังอยู่ (เช่นออกผลแก้ แต่ workflow ฉลากมือยังเดิม)
- **โทษคน/ปิด blame** — คนกลัวโดนลงโทษ → ปิดข้อมูลจริง → root cause หาย → เกิดซ้ำ (เสีย safety culture)
- **มี Correction ไม่มี Corrective** — ดับไฟแล้วถือว่าจบ ไม่ปิดราก
- **ข้ามขั้น "หลุดมาได้ยังไง"** — ไม่ถามว่าทำไม defense (QC/check/LIS) ไม่จับ → ช่องโหว่เดิมเปิดอยู่. รวมถึงเชื่อว่า "QC ผ่าน = ปลอดภัยทุกชั้น" ทั้งที่ QC คุมแค่ analytical precision ไม่จับ pre/post (sample swap, ลงค่าผิด, แจ้ง critical ช้า)
- **CAPA ไม่มีเจ้าของ/กำหนดเสร็จ/effectiveness check** — เขียนสวยแต่ไม่มีใครรับผิดชอบ + ไม่รู้ว่าได้ผลจริงไหม
- **สอบสวนช้าจนหลักฐานหาย** — LIS log ถูกทับ, หลอด/lot ถูกทิ้ง → สร้าง timeline ไม่ได้

## ช่องสำหรับผู้เชี่ยวชาญเติม
> เติมเคสจริงในแล็บคุณ เช่น:
> - *"(MT/QM) incident ที่เคยถอดบทเรียนแล้วเจอ root cause ลึกกว่าที่คิด คือ... แก้ระบบด้วย..."*
> - *"CAPA ที่ผู้ตรวจ ISO 15189 ตีกลับเพราะ 'แก้ที่คน' คือ... ผมเขียนใหม่เป็น..."*
> - *"near-miss ที่ดีใจว่าจับทัน แต่พบว่า defense จริงๆ ไม่มี คือ..."*
