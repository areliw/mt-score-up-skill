# ให้ AI เขียนโค้ดให้ แบบปลอดภัย (vibe coding)

ตัวช่วยสำหรับ MT ที่ไม่ใช่โปรแกรมเมอร์ แต่ให้ AI เขียนโค้ดให้ — เน้น "ใช้โค้ด AI ยังไงไม่ให้พัง/ไม่รั่ว/ไม่หลอกตัวเอง" ไม่ใช่สอนเขียนโปรแกรมตั้งแต่ศูนย์

> **กฎ #1:** โค้ดที่ **"รันได้" ≠ "ถูก"**. AI เขียนโค้ดที่รันผ่านแต่ logic/นับผิดได้ง่ายมาก → **verify output กับเคสที่รู้คำตอบ** ก่อน trust ทุกครั้ง
> **กับดัก #1 (ขั้น hard):** **paste ข้อมูลคนไข้จริง / API key / รหัส ลงแชต AI สาธารณะ = รั่ว** (อาจถูกเก็บ/เทรนต่อ). ใช้ข้อมูลปลอม/แค่โครงสร้างคอลัมน์; key เก็บแยก ไม่ฝังในโค้ดที่จะแชร์ (เชื่อม `digital-judgment`)

> **verify-first:** decision-support ไม่ใช่คำตอบสุดท้าย — เช็คข้อเท็จจริงก่อนเชื่อ (คู่กับ `anti-hallucination`)

## ใช้เมื่อ
- ให้ AI เขียนสคริปต์/สูตร/เครื่องมือให้ แต่ไม่แน่ใจมันถูก/ปลอดภัยไหม
- กลัวรันแล้วลบไฟล์/เขียนทับ/ข้อมูลรั่ว
- อยากรู้ว่าควร trust โค้ด AI แค่ไหน + ตรวจยังไง

## วิธีใช้
วาง skill นี้ + โค้ด/คำสั่งที่ AI ให้มา + บอกว่ามันจะรันกับอะไร → AI (อีกตัว/ตัวเดิม) ช่วยอธิบาย + ชี้จุดเสี่ยง + เสนอวิธี verify แล้วชี้ให้คุณทดสอบเองก่อนใช้จริง

## วิธีตัดสินใจ (AI: ทำตามนี้)

### Fork 1 — ก่อนรันโค้ดที่ไม่ได้เขียนเอง
- ให้ AI **อธิบายทีละส่วนว่าทำอะไร** + มันแตะ/ลบ/เขียนทับไฟล์อะไรบ้าง
- **อย่ารันคำสั่งที่ไม่เข้าใจ** โดยเฉพาะที่ลบ/เขียนทับ (`rm`, `del`, overwrite, DROP, format) (เชื่อม `safety-guard`)
- รันกับ **สำเนา/ข้อมูลทดสอบก่อน** ไม่ใช่ไฟล์จริงครั้งเดียวจบ

### Fork 2 — verify ด้วย known-answer
- ป้อน input ที่ **รู้คำตอบ** → เช็ค output ตรงไหม
- ลอง **เคสขอบ**: ค่าว่าง, 0, ค่าสุดโต่ง, ข้อมูลซ้ำ, ภาษาไทย/อักขระพิเศษ
- เทียบผลกับการทำมือ 2–3 เคส (เชื่อม `python-testing` หลักการ — "test กับเคสจริง")

### Fork 3 — กันพังเงียบ
- โค้ดควร **error ดังๆ เมื่อ input แปลก** ไม่ใช่คืนค่ามั่วเงียบ → อย่ายอมรับ `try/except: pass` ที่กลบทุก error (เชื่อม `error-handling`)
- ถ้าผลออกมา "ดูแปลก" อย่าเชื่อเพราะคอมพิวเตอร์คำนวณ — สงสัยไว้ก่อน

### Fork 4 — ข้อมูล + secret
- ข้อมูลจริง = รันบนเครื่องตัวเอง/intranet เท่านั้น; **de-identify** ก่อนถ้าต้องส่งออก/ขอ AI ช่วย
- **key/password/token ไม่ commit ไม่ paste** ใน chat/โค้ดสาธารณะ → เก็บแยก (env/ไฟล์ที่ไม่แชร์)

### Fork 5 — ให้ reuse + ส่งต่อได้
- ขอ AI ใส่คอมเมนต์ว่าแต่ละส่วนทำอะไร · ตั้งชื่อสื่อความ
- **backup ก่อนรันกับข้อมูลจริง** เสมอ · อย่าให้มีแค่คุณคนเดียวที่เข้าใจ (bus factor 1)

### Fork 6 — รู้ขีดจำกัด
- งานที่ผิดแล้วกระทบ **คนไข้/เงิน/กฎหมาย** (คำนวณ dose, รายงานผล, จัดการ PHI) → **ให้คนมีความรู้ตรวจ** อย่า vibe-code ล้วนแล้วใช้เลย

## กับดัก (Anti-patterns)
- #1 เชื่อ "รันได้ = ถูก" โดยไม่ verify known-answer (กับดัก #1)
- #2 paste ข้อมูลคนไข้/API key ขึ้น AI สาธารณะ
- #3 รันคำสั่งที่ไม่เข้าใจ (ลบ/เขียนทับ) กับไฟล์จริงเลย
- #4 `except: pass` / กลบ error → พังเงียบ
- #5 ไม่ลองเคสขอบ (ว่าง/0/ซ้ำ/อักขระไทย) → พังกับข้อมูลจริง
- #6 ไม่ backup ก่อนรันกับข้อมูลจริง
- #7 พลาดบั๊กคลาสสิกที่ AI ก็พลาด (off-by-one, mutable default, ปัดเศษ, timezone) เพราะไม่ตรวจ
- #8 โค้ดที่คนเดียวเข้าใจ → ทีมพึ่งพาแต่กู้ไม่ได้
- #9 vibe-code งานคำนวณทางคลินิกแล้วใช้เลยโดยไม่มีคนตรวจสูตร

## ช่องสำหรับผู้เชี่ยวชาญเติม
> - งานที่คุณให้ AI เขียนบ่อย + จุดที่เคยเจอผลผิด/เกือบพลาด
> - นโยบาย รพ. เรื่อง secret/ข้อมูล: เก็บที่ไหน, อะไรห้ามออกนอกเครื่อง
> - มีใครในทีมช่วยรีวิวโค้ดงานที่กระทบคนไข้ได้บ้าง

NOTE: การเขียนโค้ด/ดีบักเชิงลึก → ใช้ `python-coach` หรือถาม AI แยก; skill นี้คือ "ใช้โค้ด AI อย่างปลอดภัย" สำหรับคนไม่ใช่ dev
