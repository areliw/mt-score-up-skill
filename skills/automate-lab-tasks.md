# MT automate งานซ้ำ

ตัวช่วยตัดสินใจว่า "งานนี้ควรให้ code/AI ทำแทนไหม + ทำยังไงไม่ให้ผิดเงียบ" — ไม่ใช่สอนเขียน Python/macro ทีละบรรทัด

> **กฎ #1:** automate เฉพาะงานที่ **ซ้ำ + กฎชัด + ทำบ่อย**. ถ้ากฎยังไม่นิ่ง หรือทำปีละครั้ง → ทำมือคุ้มกว่า (เวลาที่เสียเขียน+ดูแล > เวลาที่ประหยัด)
> **กับดัก #1 (ขั้น hard):** automation ที่ **"ผิดเงียบ"** อันตรายกว่าทำมือ — output ที่ไม่มีใคร verify + ไม่มี alert เวลาพัง = ผิดสะสมโดยไม่รู้ตัว (ค่าผล/รายงาน QC). ทุกจุดที่กระทบคนไข้ต้องมี check + คนยืนยัน

> **verify-first:** decision-support ไม่ใช่คำตอบสุดท้าย — เช็คข้อเท็จจริงก่อนเชื่อ (คู่กับ `anti-hallucination`) · งานเป๊ะที่ AI ทำ ต้อง verify กับ source

## ใช้เมื่อ
- งานซ้ำกินเวลา (รายงานรายเดือน/คำนวณ/จัดเวร/ดึง-แปลงไฟล์) → ควร automate ไหม ใช้อะไร
- เขียน/ให้ AI เขียน automation แล้วกลัวมันพังหรือผิดเงียบ
- ไม่แน่ใจว่างานไหน "ให้ code ทำ" งานไหน "ให้ AI ทำ" งานไหน "ทำมือ"

## วิธีใช้
วาง skill นี้ + เล่างานซ้ำที่อยากลดมือ (ทำบ่อยแค่ไหน/กฎคืออะไร/มีข้อมูลคนไข้ไหม) → AI ช่วยชั่ง ROI + เลือกวิธี + เตือนจุดที่ต้องมี verify/alert แล้วชี้ให้คุณตรวจเอง

## วิธีตัดสินใจ (AI: ทำตามนี้)

### Fork 1 — ควร automate ไหม (ROI)
- คุ้ม = (เวลาต่อครั้ง × ความถี่ × อายุงานที่จะใช้) **มากกว่า** (เวลาเขียน + เวลาดูแลต่อ)
- **คุ้ม**: ทำทุกสัปดาห์/เดือน + กฎนิ่ง + จะใช้ไปอีกนาน · **ไม่คุ้ม**: ทำครั้งเดียว, กฎเปลี่ยนตลอด, ปริมาณน้อย → ทำมือ
- เริ่มที่งาน "น่าเบื่อ + เสี่ยง human error" (copy-paste ตัวเลขเยอะๆ) ก่อน

### Fork 2 — ใครทำ (เลือกเครื่องมือ)
- **Excel formula/macro** — อยู่ในไฟล์ที่ใช้อยู่แล้ว, งานในตาราง
- **Power Automate / Zapier / Apps Script** — no-code เชื่อมแอป (อีเมล→Sheet, แจ้งเตือน)
- **Python script** — ยืดหยุ่นสุด, งานซับซ้อน/ปริมาณมาก (ให้ AI ช่วยเขียน → คู่ `vibe-coding-safely`)
- **AI ทำ adhoc** — สรุป/จัดรูป/จัดหมวด text (งาน fuzzy)

### Fork 3 — งานเป๊ะ vs งาน fuzzy (แบ่งงานให้ถูกมือ)
- **งานเป๊ะ** (คำนวณ/จัดเวร/dedupe/นับ) → **code ทำ, AI/คนคุม** — อย่าให้ AI เดาเลขที่ต้องตรง
- **งาน fuzzy** (สรุป/ร่าง/จัดหมวด/อ่าน free-text) → **AI ทำ, คนตรวจ**
- ผสม: AI ร่าง logic → code รันจริง → คน verify ผล

### Fork 4 — กัน automation พัง (ขั้นต่ำ)
- **validate input** (รูปแบบ/ช่วงค่าที่รับได้) ก่อนประมวลผล
- **error ดังๆ + alert** เมื่อเจอของแปลก — ห้ามคืนค่ามั่วเงียบ (เชื่อม `error-handling` หลักการ)
- **idempotent**: รันซ้ำแล้วผลเหมือนเดิม ไม่ซ้ำซ้อน · เก็บ **raw ไว้ rollback**
- **test กับเคสจริง + เคสขอบ** ก่อน trust (เชื่อม `vibe-coding-safely`)

### Fork 5 — ข้อมูลคนไข้
- ไม่ส่งข้อมูลจริงไป cloud service/AI สาธารณะ → de-identify / ใช้ตัวอย่างปลอม
- automation ที่แตะ PHI ต้องคิด auth + ที่เก็บ (เชื่อม `digital-judgment`)

## กับดัก (Anti-patterns)
- #1 automate งานที่ทำครั้งเดียว/กฎเปลี่ยนตลอด → เสียเวลามากกว่าทำมือ
- #2 ไม่มี verify/alert → ผิดเงียบสะสม (กับดัก #1)
- #3 ให้ AI คำนวณเลขที่ต้องเป๊ะแล้วไม่ตรวจ → ค่าผิดหลุดออกไป
- #4 hardcode ค่าที่เปลี่ยนได้ (cutoff/ราคา/รหัส) กลางสคริปต์ → พังเงียบเมื่อค่าเปลี่ยน
- #5 ไม่ validate input → ข้อมูลแปลกเข้าไปทำ output เพี้ยน
- #6 ไม่เก็บ raw / ไม่ idempotent → กู้ไม่ได้, รันซ้ำพัง
- #7 ส่ง PHI ขึ้น service สาธารณะ
- #8 automation ที่คนเดียวเข้าใจ (bus factor 1) → คนนั้นลา = ทีมพัง
