## 🩸 งานแล็บ / คลินิก

### `bloodbank-judgment`

เวรดึก รพ.แห่งหนึ่ง คนไข้ชายสูงอายุ ICU มะเร็งลำไส้ใหญ่ ติดเชื้อในกระแสเลือด แพทย์ขอ PRC 2 ยูนิตด่วน คุณรันหมู่เลือดจากหลอดที่พยาบาลส่งมา: Forward = anti-A 4+, anti-B 2+ (อ่อนกว่า); Reverse = A1 cell neg, B cell 2+. มันไม่เข้ากัน — forward เหมือน AB แต่ reverse บอกว่ามี anti-B อ่อนๆ อยู่ Antibody screen negative, autocontrol negative คุณนึกออกทันที: คนไข้มะเร็งลำไส้ + sepsis (น่าจะ E. coli) → คลาสสิกของ acquired-B ที่ deacetylase ของแบคทีเรียเปลี่ยน A ให้คล้าย B reaction anti-B จึงอ่อนและ acid pH6 น่าจะหายไป เพื่อนเวรพยักหน้า บอกให้รายงานเป็น group A แล้วจ่าย A ตามหมู่จริงเลยจะได้ทันคนไข้ที่กำลัง drop ระบบ LIS ขึ้นเตือนเล็กๆ ว่า "historical group: O" แต่ผลเก่าเป็นปีที่แล้ว ตอนคนละ admission คุณจะรายงานหมู่และจ่ายเลือดยังไง ก่อนปล่อยยูนิต

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: ด่วน resolve ที่ serology (acquired-B fits เป๊ะ) โดยข้าม clerical → ABO mislabel/sample swap คือสาเหตุ #1 ของ fatal acute hemolysis. ธงแดงคือ historical group O ไม่ตรงกับ forward วันนี้ — acquired-B เปลี่ยน A↔B ได้แต่ "ไม่ทำให้ O กลายเป็น A/AB" ฉะนั้นต้องสงสัย wrong-blood-in-tube ก่อน. Move ที่ถูก: หยุด อย่ารายงาน/อย่าจ่ายตามหมู่ serology, เช็ค clerical 4 ข้อ (ชื่อ-HN ข้างเตียง/ป้ายหลอด/sample/historical) + เจาะ sample ใหม่ที่ระบุตัวคนไข้ใหม่. ระหว่างรอ ถ้าคนไข้วิกฤตจ่าย O ไปก่อน.
</details>

### `hematology-judgment`

เวร LIS ช่วงดึก มีตัวอย่าง CBC ของผู้ป่วยชาย 19 ปี ส่งจาก ER ระบุ "ไข้ 4 วัน เพลีย เหงือกออกเลือดเล็กน้อย" ผลจากเครื่องอัตโนมัติออกมาดูสบายตา: WBC 6,800 (ปกติ), differential เครื่องนับ lymphocyte 62%, monocyte 9%, neutrophil 27% — ไม่มี flag "blast" หรือ "immature" ขึ้นเลย, Hb 9.8 ต่ำเล็กน้อย, platelet 88,000 ต่ำเล็กน้อย. คิว backlog ยาว 30 ตัวอย่าง หัวหน้าเวรเร่งให้เคลียร์. เพื่อนร่วมเวรเสนอว่า "WBC ปกติ ไม่มี flag อะไร lymph สูงก็เข้ากับไข้ติดเชื้อไวรัสอยู่แล้ว เด็กวัยรุ่นไข้ 4 วัน lymphocytosis แบบนี้คลาสสิก น่าจะ viral infection — platelet กับ Hb ต่ำนิดเดียวพอเข้าได้กับ viral suppression, รายงานไป auto-release เลยจะได้ทันคิว" คุณเห็นด้วยแล้วกดรายงานเลยไหม ถ้าไม่ ทำอะไรต่อ และเพราะอะไร?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก #1 "Miss blast": เลขเครื่อง/ไม่มี flag = ปกติ ≠ smear ปกติ — เครื่องนับ blast เป็น lymph/mono ได้ ปล่อย acute leukemia ทั้งที่ WBC ปกติ. correct move: บริบทค้าน (ไข้+เลือดออกเหงือก+Hb/plt ต่ำคู่กัน = bicytopenia) → ห้าม auto-release, ต้อง review smear ด้วยตาหา blast ก่อน; ถ้าเจอ blast = urgent แจ้งแพทย์ทันที ส่ง marrow/flow. "ไม่มี flag" ไม่ใช่ใบผ่าน.
</details>

### `clinchem-judgment`

เวรเช้าแล็บเคมีของ รพ. แห่งหนึ่ง เครื่องวิเคราะห์อัตโนมัติรันตัวอย่างผู้ป่วยไป 38 ราย ระหว่าง 07:00–08:30 รวมเคส OPD เบาหวานและผู้ป่วยในที่หมอรอผลก่อนราวด์ ตอน 08:30 คุณเปิดดู QC ของ glucose พบ control level 2 ของรอบเช้าออกมาที่ +3.4 SD ส่วน level 1 ปกติดี กราฟ L-J วันก่อนหน้าสวยทุกจุด คุณรีบ reconstitute control vial ใหม่ รันซ้ำทันที คราวนี้ทั้งสอง level เข้ากลางสวยภายใน ±1 SD พอดี หัวหน้าเวรบอกว่า "control ขวดเก่าคงละลายไม่ดีเอง รอบใหม่ผ่านแล้ว ปล่อยผลไปได้เลย หมอตามอยู่" ค่า glucose ผู้ป่วย 38 รายที่รันไปก็อยู่ในช่วงที่ดูสมเหตุสมผล ไม่มีตัวไหนสูง-ต่ำผิดปกติจนสะดุดตา คุณกำลังจะกด release ผลทั้ง 38 ราย เพราะ control ขวดใหม่ก็ผ่านแล้ว และคนไข้รออยู่จริง คุณควรทำอย่างไรกับผล 38 รายนี้

<details><summary>👉 เฉลยกับดัก</summary>

กับดักอันดับ 1: ปล่อยผลผู้ป่วยจาก run ที่ Westgard FAIL. ค่า +3.4 SD คือ 1₃ₛ → run รอบเช้า REJECT ผู้ป่วยทั้ง 38 รายอยู่ใน run ที่ถูก reject. การ rerun control ผ่านพิสูจน์แค่ว่าตอนนี้ระบบกลับมา in-control ไม่ได้ validate ผลที่ออกตอนเครื่อง out-of-control. ถูกต้อง: HOLD ผลทั้ง 38 ราย → หา/แก้ root cause + ยืนยัน control ผ่าน → re-run ตัวอย่างผู้ป่วยทั้งหมด แล้วค่อย report (ห้ามอนุมานว่า "ดูสมเหตุสมผล" = ใช้ได้).
</details>

### `chemistry-interpretation-judgment`

เวร 02:00 ICU โทรด่วน ผู้ป่วยชาย 58 ปี post-CABG วันที่ 2 กำลัง on furosemide drip ต่อเนื่อง พยาบาลเพิ่งเห็น EKG monitor มี T-wave สูงแหลมเป็นช่วง ๆ และส่งเลือดมาด่วน ผลเคมีออก: K⁺ 6.9 mmol/L (critical สูง), Na⁺ 138, Cl⁻ 102, HCO₃⁻ 24, Cr 1.0, glucose 110 ตัวอย่างถูกเก็บผ่าน catheter เส้นเดิม ส่งมาทาง pneumatic tube ค่าอื่น ๆ ในแผงปกติหมด ผล K⁺ ครั้งก่อนเมื่อ 6 ชั่วโมงที่แล้ว = 4.1 แพทย์เวรกำลังจะสั่ง calcium gluconate + insulin/dextrose ทันที และโทรถามคุณว่า "critical value ยืนยันมั้ย จะได้รักษาเลย" คุณในฐานะ MT ต้องตอบภายในไม่กี่นาที จะ report ค่า 6.9 เป็น critical แล้วโทรแจ้งตามระบบ critical-value หรือไม่ และทำอะไรก่อน

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: เชื่อเลขปลอมแล้วรายงาน — report K⁺ critical จากตัวอย่าง hemolyzed/contaminated โดยไม่ correlate (EKG + furosemide + จุม "ก่อนหน้า 4.1 ปกติทุกตัว" ทำให้ดูเหมือน hyperkalemia จริง). ที่ถูก: เช็ค pre-analytical ก่อน — ดู HIL/hemolysis index (เก็บผ่าน catheter + tube transport = เสี่ยง hemolysis สูง), K⁺ พุ่งเดี่ยวขณะ Cr/HCO₃ ปกติ + ผู้ป่วย on furosemide (ควรมีแนวโน้ม hypo) = สวน clinical; อย่ารายงาน critical, ขอเก็บตัวอย่างใหม่ด้วย venipuncture สะอาด recollect แล้ว verify ก่อน ค่อยตัดสิน — กัน insulin/dextrose ที่อาจทำคนไข้ hypoglycemia จากค่าปลอม.
</details>

### `clinmicro-judgment`

เวรดึก ER ส่งปัสสาวะหญิง 67 ปี นอน รพ. มา 5 วัน คาสายสวนปัสสาวะ มีไข้ต่ำ ๆ แพทย์เขียนใบส่ง "R/O UTI — sepsis?" ขอเพาะด่วน เพาะ 24 ชม. ขึ้น 3 ชนิด: Enterococcus ~10⁵ CFU/ml, E. coli ~10⁴ CFU/ml, และ coagulase-negative Staphylococcus ~10⁴ CFU/ml ทั้งสามขึ้นปนกันเต็มจาน รุ่นพี่เวรเช้าบอก "คนไข้ใส่สายสวน + มีไข้ + Enterococcus แตะ 10⁵ แล้ว เป็นเชื้อก่อโรคชัด ๆ รีบ ID ครบทั้ง 3 ตัวแล้วยิง AST ทุกตัวเลย หมอจะได้เลือกยา cover ให้หมด เดี๋ยว sepsis แย่" ดูสมเหตุผลมาก: ครบทั้งไข้ สายสวน และเกณฑ์ 10⁵ ที่ท่องกันมา คุณกำลังจะ set ID + AST ทั้งสามชนิด คุณควรทำอะไรก่อนกด และจะรายงานผลนี้ออกไปอย่างไร?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: รายงาน contaminant เป็น pathogen — ปัสสาวะขึ้น ≥3 ชนิดปนกัน = "mixed/contaminated growth" (เก็บไม่สะอาด) ไม่ใช่ true UTI ต่อให้ตัวหนึ่งแตะ 10⁵ และมีไข้; เกณฑ์ 10⁵ + clinical ไม่ override "polymicrobial = ปน". ท่าถูก: ไม่ ID/AST ทั้งสาม รายงาน "mixed bacterial growth ≥3 species — suggest contamination" + ขอเก็บ specimen ใหม่แบบ clean catch/เปลี่ยนสายสวนก่อนเก็บ แล้วค่อยตัดสินตาม count + จำนวนชนิด + clinical อีกครั้ง.
</details>

### `applied-microbiology-judgment`

โรงงานเล็กแห่งหนึ่งออกซุปเห็ดผักโฮมเมดบรรจุขวดแก้วฝาสุญญากาศ วางขายแบบเก็บที่อุณหภูมิห้อง (ไม่ต้องแช่เย็น) เป็นจุดขาย ทีมผลิตภูมิใจมากเพราะคุมกระบวนการแน่น: ให้ความร้อน 80°C นาน 30 นาที วัดอุณหภูมิทุกขวด ฝาดูดสุญญากาศสนิททุกใบ และส่งตัวอย่าง 3 ล็อตล่าสุดเข้าแล็บ ผลเพาะเชื้อแบคทีเรียทั่วไป (TPC) ขึ้นน้อยมาก ยีสต์/ราไม่ขึ้น โคลิฟอร์มไม่พบ ค่า pH ที่วัดได้อยู่ราว 6.2 หัวหน้าฝ่ายคุณภาพสรุปว่า "อุณหภูมิถึง สุญญากาศดี ผลแล็บสะอาด = ปลอดภัย ขายที่อุณหภูมิห้องได้" และเตรียมเซ็นปล่อยล็อตออกตลาด พร้อมขยายกำลังผลิตเพิ่ม คุณในฐานะที่ปรึกษาจุลชีววิทยาควรเห็นชอบให้ปล่อยขายแบบเก็บอุณหภูมิห้องหรือไม่ และถ้าไม่ ปัญหาหลักอยู่ตรงไหน?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: "ผ่านความร้อน + ผลเพาะเชื้อสะอาด = ปลอดเชื้อ/ปลอดภัย" — 80°C/30นาที เป็นแค่ระดับ pasteurize ไม่ฆ่าสปอร์ และ TPC ที่ขึ้นน้อยไม่พิสูจน์ว่าไม่มีสปอร์ (เพาะแบบ aerobic ทั่วไปจับ C. botulinum ที่ anaerobic ไม่ได้). ถูกต้อง: ของ low-acid (pH 6.2) + บรรจุสุญญากาศ + เก็บอุณหภูมิห้อง = เงื่อนไขเสี่ยง C. botulinum สูงสุด → ห้ามปล่อย; ต้องใช้ retort/UHT (>100°C, F0 ที่เพียงพอ) หรือลด pH <4.6 หรือบังคับแช่เย็น ไม่ใช่เชื่อผลเพาะเป็น proof of absence.
</details>

### `immunoassay-judgment`

หญิงอายุ 26 ปี ตั้งครรภ์ 30 สัปดาห์ มาฝากครรภ์ครั้งแรกที่คลินิก มีผื่นแดงตามฝ่ามือฝ่าเท้าและตุ่มชื้นบริเวณอวัยวะเพศมาราว 3 สัปดาห์ คุณรับสิ่งส่งตรวจมาทำ RPR เป็น screen ตามระบบ traditional ผล RPR ออกมา non-reactive (ลบ) เพื่อนร่วมงานชี้ว่า "คนท้องเป็นกลุ่มที่เจอ biological false-positive RPR บ่อยมาก (จาก SLE/การตั้งครรภ์เอง) ฉะนั้นการที่ RPR ออกลบกลับยิ่งน่าเชื่อถือ ไม่มี false-positive กวน" และเสนอให้รายงาน non-reactive แล้วปิดเคส ไม่ต้องส่ง TT เพิ่ม เพราะ screen เป็นลบอยู่แล้วและ NTT คือ titer ที่ใช้ติดตามการรักษา ไม่ใช่ confirm เครื่องและ control ของรอบนี้ผ่าน QC ปกติ ตัวอย่างไม่มี hemolysis/lipemia ไม่ clotted คุณจะรายงานผลและจัดการเคสนี้อย่างไร และเพราะอะไร

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก = Prozone (false-negative ที่ titer สูง): clinical เข้าได้กับ secondary syphilis ชัด (ผื่นฝ่ามือฝ่าเท้า + condyloma lata) + ตั้งครรภ์/Ab สูง → Ab เกินไม่เกิด lattice → RPR ลบหลอก. distractor BFP/QC-ผ่านทำให้ "ลบ = น่าเชื่อ" ดูถูก. Correct move: ห้ามรายงาน non-reactive — เจือจาง (dilute) แล้วทำ RPR ซ้ำ และส่ง TT (TPHA/TPPA) ยืนยัน; ผลลบสวนอาการหนัก = สงสัย false-negative ทางเทคนิคก่อน, negative ≠ rule-out.
</details>

### `molecular-judgment`

โรงพยาบาลแห่งหนึ่งส่งเลือดผู้ป่วยชายวัย 34 ปี มีไข้สูง น้ำหนักลด ต่อมน้ำเหลืองโต แพทย์สงสัยการติดเชื้อ TB และสั่งตรวจ Mycobacterium tuberculosis ด้วย real-time PCR ก่อนเริ่มยา anti-TB ที่มีผลข้างเคียงต่อตับ คุณรับ run เข้าเครื่อง ผลออกมาดังนี้ หลอด positive control ขึ้น amplification curve สวยตามคาด หลอด NTC สะอาดไม่มีสัญญาณเลย และหลอดผู้ป่วยไม่ขึ้น amplification curve ใดๆ ตลอด 45 cycles เส้นแบนราบนิ่ง เพื่อนร่วมงานบอกว่า "positive control ก็ขึ้นแล้ว NTC ก็สะอาด แสดงว่า run นี้ valid สมบูรณ์ ผู้ป่วยเส้นแบน = ไม่พบสารพันธุกรรมเชื้อ รายงาน Not Detected ไปได้เลย แพทย์รออยู่" ตัวอย่างเป็นเลือดในหลอด EDTA ปั่นแยกมาดี ไม่มี hemolysis เห็นชัด คุณจะรายงานผลว่าอย่างไร และต้องดูอะไรเพิ่ม

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: อ่าน "negative/Not Detected" จากหลอดผู้ป่วยที่เส้นแบน โดยดูแค่ positive control + NTC — แต่สองตัวนั้นไม่ได้พิสูจน์ว่า reaction ในหลอดผู้ป่วยทำงาน. ท่าถูก: ห้ามรายงาน negative จนกว่าจะเห็น internal/amplification control ในหลอดผู้ป่วยขึ้น — ถ้า internal control ก็แบน = INVALID (inhibition/extraction fail) ไม่ใช่ Not Detected → extract/repeat ใหม่.
</details>

### `pathology-judgment`

หญิง 34 ปี มาด้วยแผลที่ปากมดลูกหลังคลอด 8 สัปดาห์ มีประวัติติดเชื้อในอุ้งเชิงกรานและรักษาด้วยยาฆ่าเชื้ออยู่ พยาธิแพทย์ส่งชิ้นเนื้อ biopsy มาให้คุณช่วยอ่าน pattern ก่อน sign-out รายงานเขียนว่า: เซลล์เยื่อบุ squamous มี nuclear enlargement ชัดเจน, N:C ratio สูง, pleomorphism ปานกลาง, เห็น mitotic figure 6 ตัวต่อ 10 HPF, nucleoli เด่น กระจายเป็นหย่อม ๆ ท่ามกลางการอักเสบรุนแรง มี neutrophil และ lymphocyte แทรกหนาแน่น พื้นหลังมี granulation tissue และหลอดเลือดงอกใหม่ ชั้น basement membrane ยังต่อเนื่องไม่ขาด เซลล์ atypical ทั้งหมดอยู่เหนือ BM ไม่มีก้อนต่อมน้ำเหลืองโต ไม่มีรอยโรคอื่นใน imaging แพทย์เจ้าของไข้เร่งให้ฟันธงเพราะอยากวางแผนผ่าตัดด่วน เพื่อนร่วมทีมบอกว่า mitosis เยอะขนาดนี้ + nucleoli เด่น + N:C สูง = ฟันธง squamous cell carcinoma ได้เลย รีบส่งห้องผ่าตัด คุณจะตอบว่าอย่างไร และจุดตัดสินอยู่ตรงไหน

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: ฟันธงมะเร็งจาก atypia/mitosis/nucleoli/N:C เดี่ยว ทั้งที่นี่คือ reactive atypia จากการอักเสบ+ซ่อมแซมหลังคลอด/ติดเชื้อ (granulation tissue + อักเสบรุนแรง = สัญญาณ reactive). ถูก: ยังไม่ฟันธง — BM ยังต่อเนื่อง ไม่มี invasion ไม่มี metastasis = ตัวชี้ขาดยังไม่เข้าเกณฑ์มะเร็ง; อ่าน pattern ในบริบทอักเสบ, ถ้าสงสัยจริงให้รักษาการอักเสบแล้ว re-biopsy / confirm (p16/Ki-67, HPV) ก่อน ไม่ส่งผ่าตัดด่วนจากภาพอย่างเดียว.
</details>

### `parasitology-judgment`

ผู้ป่วยชายอายุ 38 ปี มาด้วยถ่ายเหลวเป็นน้ำมากกว่า 10 ครั้งต่อวัน นาน 3 สัปดาห์ น้ำหนักลด 6 กิโลกรัม ไม่มีไข้สูง ไม่มีมูกเลือด ประวัติเดินทางต่างจังหวัด กินน้ำแข็ง/อาหารริมทางบ่อย แพทย์สงสัยลำไส้อักเสบจากปรสิตหรือแบคทีเรีย ส่งอุจจาระตรวจ ผลเป็นน้ำใส ไม่มีเม็ดเลือดขาว

เทคนิคทีมแล็บทำ: direct wet smear (NSS + Lugol's) แล้วก็ทำ formalin-ether concentration ซึ่งเป็น gold standard ของ concentration ครอบคลุมทั้ง helminth egg และ protozoan cyst มากที่สุด อ่านอย่างละเอียดทั้งสองวิธี ไม่พบ cyst, trophozoite หรือไข่พยาธิใดๆ ทำซ้ำอีก 2 ตัวอย่างวันเว้นวันตาม SOP rule-out ก็ยังไม่พบ

ทีมเตรียมรายงาน "No parasite seen (examined 3 specimens)" เพราะทำครบทั้ง concentration ที่ไวที่สุดและตรวจซ้ำครบจำนวน

คำถาม: การรายงานนี้พลาดอะไร และต้องสั่งตรวจอะไรเพิ่มก่อนรายงานผลลบ? พิจารณาเบาะแสในเคสให้ครบ

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: เลือก stain/technique ไม่ตรงเป้า — น้ำหนักลด 6 กก. + ถ่ายเหลวเป็นน้ำเรื้อรัง 3 สัปดาห์ ชี้ภูมิต่ำ/HIV ที่ต้องคิด opportunistic coccidia/microsporidia ทันที. Formalin-ether + wet smear (แม้ไวสุดสำหรับ cyst/egg) มองไม่เห็น oocyst/spore เพราะย้อมไม่ติด. correct move: สั่ง modified acid-fast (Crypto/Cyclospora/Cystoisospora) + modified trichrome (microsporidia) ก่อนรายงาน "ไม่พบ" — และส่งตรวจสถานะ HIV.
</details>

### `toxicology-judgment`

โรงพยาบาลแห่งหนึ่งส่งปัสสาวะคนขับรถบรรทุกชายวัย 34 มาตรวจ หลังเกิดอุบัติเหตุชนท้าย ฝ่ายบุคคลขอผลด่วนเพื่อพิจารณาเลิกจ้างและส่งให้ตำรวจดำเนินคดี คุณรันชุด immunoassay (EMIT) สำหรับ amphetamine ผล "positive" ชัดเจน สูงเกิน cutoff เกือบ 3 เท่า ทำซ้ำอีก 2 ครั้งได้ positive ทั้งคู่ เครื่อง QC วันนั้นผ่านทุกระดับ คนไข้มีอาการกระสับกระส่าย หัวใจเต้นเร็ว ความดันสูง เข้าได้กับ stimulant พอดี ฝ่ายบุคคลโทรเร่งว่า "ผล positive ซ้ำ 3 รอบ เครื่องผ่าน QC อาการก็ตรง รีบออกใบรายงาน positive ให้เลย จะได้ดำเนินคดี" ระหว่างซักประวัติเพิ่ม พบว่าคนไข้กินยาแก้หวัดคัดจมูกที่ซื้อเองมา 3 วันก่อน และเพิ่งกินยาแก้กระเพาะตอนเช้า คุณจะออกใบรายงานว่าอย่างไร และต้องทำอะไรก่อน?

<details><summary>👉 เฉลยกับดัก</summary>

Trap: รายงาน "positive" จาก screen (immunoassay) เดี่ยวโดยไม่ confirm — amphetamine EMIT cross-react กับ pseudoephedrine/ranitidine ฯลฯ ได้ false positive แม้ผลซ้ำ 3 รอบ + QC ผ่าน + อาการเข้าได้ (screen ซ้ำกี่รอบก็ยัง cross-react เหมือนเดิม ไม่ได้ยืนยันตัวสาร). Correct move: ยังไม่ออก positive — report เป็น "presumptive positive, pending confirmation" แล้วส่ง confirm ด้วย GC-MS/LC-MS ก่อนเสมอ โดยเฉพาะเคส forensic/กฎหมายที่ต้อง chain of custody + confirmation จึงใช้ในศาลได้.
</details>

### `pharmacology-judgment`

หญิง 34 ปี เริ่มยากันชักตัวใหม่มาได้ 12 วันหลังได้รับวินิจฉัยว่ามีอาการชัก แพทย์สั่งยาคุมเชื้อทางเดินปัสสาวะร่วมด้วยเมื่อ 3 วันก่อนเพราะปัสสาวะแสบขัด วันนี้มาด้วยไข้ 38.9°C เจ็บคอมาก กลืนลำบาก ตาแดงเคืองทั้งสองข้าง และมีผื่นแดงเริ่มขึ้นที่หน้าอกลามมาที่ใบหน้า ปวดเมื่อยทั้งตัว ญาติเล่าว่า 2 วันก่อนเหมือนเป็นหวัดลงคอ ผลแล็บ: WBC 13,200 (neutrophil เด่น), CRP สูง, จุลทรรศน์ปัสสาวะพบเม็ดเลือดขาวเล็กน้อย ทีมเวรกลางคืนสรุปว่าน่าจะติดเชื้อทางเดินหายใจส่วนบนซ้อนกับ UTI ที่ยังคุมไม่อยู่ จึงวางแผนคงยากันชักไว้ (กลัวชักกำเริบถ้าหยุด) เพิ่มยาแก้ปวดลดไข้ และพิจารณาเปลี่ยนยาฆ่าเชื้อให้แรงขึ้น ส่วนผื่นให้ทายาแก้แพ้แล้วสังเกตอาการ คุณเห็นด้วยกับแผนนี้ไหม และจะทำอะไรเป็นอันดับแรก

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: ตีอาการ "ผื่น+ไข้+เจ็บคอ+ตาแดง หลังเริ่มยาใหม่ (กันชัก/ซัลฟา)" เป็นการติดเชื้อ/ผลข้างเคียงเล็กน้อย แล้วคงยาไว้ — จริงๆ คือสัญญาณ SJS/TEN. แผนเวรผิด: ไข้+WBC สูง+CRP ล่อให้คิดว่าติดเชื้อ. Move ถูก: สงสัย SJS/TEN ทันที → หยุดยาต้นเหตุ (ทั้งยากันชักและซัลฟา) เดี๋ยวนี้ ส่งแพทย์ด่วน ถ่ายรูปผื่น+เอายาพร้อมฉลากไป บันทึกแพ้ตลอดชีวิต — ห้ามแค่ทายาแล้วสังเกต.
</details>

### `clinical-correlation-judgment`

หญิง 24 ปี เชื้อสายเอเชียตะวันออกเฉียงใต้ มาตรวจสุขภาพก่อนแต่งงาน บ่นเหนื่อยง่าย ประจำเดือนมามากทุกเดือนมา 3 ปี กินมังสวิรัติเคร่งครัด ผล CBC: Hb 9.8, MCV 68, MCH 21, RDW 15.8 (สูงเล็กน้อย), เม็ดเลือดขาว/เกล็ดเลือดปกติ. แพทย์เวรเขียนสั่งในใบว่า "microcytic hypochromic anemia — น่าจะ IDA จากประจำเดือนมามาก + มังสวิรัติ ให้ ferrous sulfate กลับบ้าน นัด 1 เดือน". เพื่อนร่วมงานเห็นด้วยเต็มที่: ผู้หญิงวัยเจริญพันธุ์ + เลือดออกประจำเดือนเยอะ + กินมังสวิรัติ = ตำราเป๊ะ ขาดเหล็กชัดๆ ไม่ต้องเสียเงินส่งตรวจเพิ่ม. คู่หมั้นของเธอ (เชื้อสายเดียวกัน) ก็เคยมีผลเลือดจาง "เล็กน้อย" แต่ไม่เคยตรวจอะไรเพิ่ม. คุณเป็น MT ที่ตรวจ slide และเห็นผลก่อนปล่อยรายงาน — คุณจะปล่อยตามที่แพทย์สั่ง หรือ flag อะไรกลับ และเพราะอะไร? ต้อง reflex test อะไรก่อน lock เป็น IDA?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: Anchoring บนธงแรก (IDA) เพราะ clinical พร้อม — ลืมว่า microcytic ในเชื้อสาย SEA + MCV ต่ำมากแต่ RDW แทบไม่กว้าง + คู่หมั้นเชื้อสายเดียวกันมีประวัติ = ธงแดง thalassemia trait. การ move ที่ถูก: อย่าปล่อยตาม IDA ทันที — flag + reflex ferritin/iron study ก่อน ถ้าเหล็กปกติ/สูง → Hb typing (และเพราะเป็น pre-marital counseling ต้อง screen คู่หมั้นด้วย เสี่ยงลูกเป็น thal major). การให้ธาตุเหล็กทั้งที่ไม่ขาดเสี่ยง iron overload + พลาด genetic counseling. ตั้ง DDx ≥3 (IDA / thal trait / anemia of chronic disease) แล้วสั่ง test ที่หักล้าง IDA (ferritin) ไม่ใช่แค่รักษาตามสมมติฐานแรก.
</details>

### `infection-control-judgment`

เวรดึก ER รับผู้ป่วยชาย 24 ปี ไข้สูง 3 วัน มีผื่นตุ่มน้ำใสกระจายทั้งตัว หลายตุ่มแตกเป็นแผลมีน้ำเหลืองไหลซึม ประวัติเพิ่งกลับจากค่ายทหารที่มีคนป่วยคล้ายกันหลายคน แพทย์เวรสั่ง admit พยาบาลหัวหน้าเวรบอกทีมว่า "ตุ่มแตกมีน้ำเหลืองไหลแบบนี้ เน้นกันสัมผัสสารคัดหลั่งเป็นหลัก" จึงจัดให้ใส่ถุงมือ+กาวน์ทุกครั้งที่เข้าดูแล สวม surgical mask กันละอองตอนทำแผล และเตรียมย้ายผู้ป่วยเข้าห้องแยกเดี่ยวที่ว่างอยู่ ซึ่งเป็นห้องผู้ป่วยภูมิคุ้มกันต่ำที่ออกแบบมาอย่างดี อากาศถ่ายเทสะอาด หอผู้ป่วยเต็ม เหลือห้องนี้ห้องเดียวที่พร้อมใช้ทันที ทีมเห็นพ้องว่าห้องนี้ดีที่สุดเพราะสะอาดและแยกเดี่ยว คุณเป็น MT/IC ที่ถูกปรึกษาก่อนย้าย ชุด PPE และห้องที่เลือกไว้นี้เหมาะสมหรือไม่ ถ้าไม่ ต้องแก้อะไรก่อนย้ายผู้ป่วย

<details><summary>👉 เฉลยกับดัก</summary>

กับดักอันดับ 1: เห็นผื่นตุ่มน้ำแตก/น้ำเหลืองไหล เลยตีเป็น contact + surgical mask และคว้าห้องเดียวที่ว่าง (ซึ่งเป็นห้องความดันบวก). แต่ภาพนี้คือสุกใส/อีสุกอีใส (หรือกลุ่มหัด-สุกใส) = airborne. Move ถูก: N95 + ห้องความดันลบ (AIIR) ไม่ใช่ surgical mask + ห้องความดันบวก — ห้องบวกจะเป่าเชื้อ airborne ออกแพร่ทั้งหอ และยังเอาคนติดเชื้อไปใส่ห้องที่สงวนไว้สำหรับผู้ป่วยภูมิคุ้มกันต่ำ. เพิ่ม contact precaution (ถุงมือ+กาวน์) ได้เพราะตุ่มแตกมีน้ำเหลือง แต่ห้ามลด airborne ลงเป็น droplet/contact เด็ดขาด.
</details>

### `critical-appraisal-judgment`

โรงพยาบาลชุมชนแห่งหนึ่งจะตัดสินใจรับชุดตรวจคัดกรองมะเร็งชนิดหนึ่งด้วยตัวอย่างเลือด (liquid biopsy) มาใช้คัดกรองประชากรทั่วไปในอำเภอ ตัวแทนบริษัทยื่นเปเปอร์ตีพิมพ์ในวารสารมี impact factor สูง สรุปว่า test นี้ sensitivity 99% และ specificity 98% เทียบกับ biopsy เป็น gold standard กลุ่มตัวอย่าง 2,000 คน แบ่งครึ่งเป็นผู้ป่วยยืนยันแล้ว 1,000 คน และคนปกติ 1,000 คน อ่าน blinded ทั้งสองฝั่ง หัวหน้าแล็บบอกว่า "ตัวเลขระดับนี้แทบไม่มี false negative เลย เอามาคัดกรองทั้งอำเภอได้สบาย ผลบวกแทบไม่มีทางพลาด" มะเร็งชนิดนี้พบจริงในประชากรทั่วไปประมาณ 5 ต่อ 100,000 คน (0.005%) คุณถูกขอให้ฟันธงว่าควรนำมาใช้คัดกรองประชากรทั่วไปตามที่เสนอหรือไม่ และให้เหตุผลเชิงตัวเลข

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: เห็น sens/spec สูง + วารสารดัง + blinded แล้วเชื่อว่าผลบวกแม่น (sens/spec ไม่ขึ้นกับ prevalence แต่ PPV ขึ้น). ท่าถูก: ที่ prevalence 0.005% แม้ spec 98% ก็เกิด false+ ~2% ของ ~100,000 = ~2,000 คน เทียบผู้ป่วยจริง ~5 คน → PPV ราว 0.25% ผลบวก ~399 ใน 400 เป็น false+. อีกชั้น: spectrum bias — กลุ่มศึกษา 50:50 ผู้ป่วยยืนยันชัด ไม่ใช่ประชากรคัดกรองจริง → ตัวเลขจริงอาจแย่กว่านี้. ฟันธง: ห้ามใช้คัดกรอง mass screening ตรงๆ ต้องมี confirm test เสมอ.
</details>

### `r2r-research-proposal`

พี่นักเทคนิคการแพทย์ รพช. แห่งหนึ่งเล่าว่า อยากทำงานวิจัยเทียบค่า HbA1c ระหว่างเครื่องเก่ากับเครื่องใหม่ที่เพิ่งซื้อ เพื่อยื่นขอชำนาญการสิ้นปีนี้ (เหลือเวลา ~4 เดือน). เธอบอกว่า "ดีมากเลย เพราะฉันไม่ต้องไปยุ่งกับคนไข้สักคน — ข้อมูลทั้งหมดมันอยู่ใน LIS อยู่แล้ว เป็นผลที่ตรวจเสร็จไปตามปกติ 8 เดือนที่ผ่านมา ฉันแค่ดึงตัวเลขย้อนหลังมาเทียบ ไม่ได้เจาะเลือดเพิ่ม ไม่ได้ถามอะไรคนไข้เลย แถมตัวอย่างที่เหลือ (leftover) ก็จะทิ้งอยู่แล้ว เอามารันซ้ำได้เลย". เธอวางแผนจะเริ่มดึงข้อมูลและรันตัวอย่างสัปดาห์หน้า แล้วค่อยเขียนรายงาน ส่วนเรื่องเอกสารทางการค่อยจัดการตอนใกล้ส่ง. ในฐานะที่ปรึกษา ก่อนเธอกดดึงข้อมูลออกจาก LIS วันจันทร์นี้ คุณจะเตือนอะไรเป็นอย่างแรก และทำไมเหตุผล "ไม่ได้ยุ่งกับคนไข้เลย" ถึงไม่ปลอดภัยอย่างที่เธอคิด?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: เริ่มเก็บ/ใช้ข้อมูลผู้ป่วยก่อนได้ EC → ตีพิมพ์/ขอชำนาญการไม่ได้ แม้เป็นข้อมูล routine/leftover เดิม. Move ที่ถูก: หยุดก่อนแตะข้อมูลใหม่ — งานที่ "เก็บไปแล้ว" แบบ retrospective ก็ยังต้องยื่น EC (ส่วนใหญ่ขอ waiver of consent ได้ แต่ต้องได้อนุมัติ "ก่อน" ดึง/วิเคราะห์ข้อมูลชุดใหม่) และต้องวาง EC ~2–8 สัปดาห์ไว้ใน timeline ตั้งแต่วันแรก ไม่ใช่รอตอนจะเขียนตีพิมพ์.
</details>

### `research-design-judgment`

คุณเป็น MT กำลังทำ R2R ที่ รพ. แห่งหนึ่ง เก็บข้อมูลผู้บริจาคโลหิตในวันเดียว 480 ราย วัด vitamin D ในเลือดพร้อมกับวัดระดับ ferritin และทำแบบสอบถามว่าออกกำลังกายกลางแจ้งบ่อยแค่ไหน ผลออกมาสวยมาก คนที่ vitamin D สูง มี ferritin เฉลี่ยสูงกว่ากลุ่ม vitamin D ต่ำอย่างมีนัยสำคัญ (p<0.001, ความสัมพันธ์เป็นเส้นตรงชัด r=0.42) อาจารย์ที่ปรึกษาตื่นเต้น เพราะ biologically plausible — vitamin D รู้กันว่าช่วย iron metabolism ผ่าน hepcidin ทีมเลยร่างบทคัดย่อว่า "การเสริม vitamin D ช่วยเพิ่มระดับธาตุเหล็กสะสมในผู้บริจาคโลหิต ควรพิจารณาให้ vitamin D เพื่อป้องกันภาวะเหล็กต่ำ" ตัวเลข N เยอะ p ต่ำมาก กลไกก็มีงานรองรับ ดูพร้อมส่งวารสาร คุณจะเดินหน้าตามนี้ไหม ถ้าไม่ ปัญหาหลักอยู่ตรงไหน และต้องแก้อะไรก่อนเขียนข้อสรุปแบบนี้

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: ตีความ association จาก cross-sectional เป็น causation (วัดครั้งเดียวบอกได้แค่ "associated with" ห้ามเขียน "ช่วยเพิ่ม/ควรเสริมเพื่อ...") + ไม่คุม confounder. แก้: ลดข้อสรุปเหลือ "สัมพันธ์กัน", คุม confounder ที่สัมพันธ์ทั้ง vit D และ ferritin — โดยเฉพาะ "ออกกำลังกายกลางแจ้ง/แสงแดด" (และอายุ เพศ ฤดูกาล) ด้วย stratify/multivariable regression; อ้าง causation ต้อง RCT (เสริม vit D vs placebo).
</details>

### `choose-stat-test`

ทีมแล็บโรงพยาบาลแห่งหนึ่งทำวิจัยว่า ระดับ HbA1c สูงสัมพันธ์กับภาวะแทรกซ้อนทางไตในผู้ป่วยเบาหวานหรือไม่ ทีมเก็บผู้ป่วยที่มีภาวะแทรกซ้อนทางไต (กลุ่มเคส) 80 คน แล้ว "จับคู่" ผู้ป่วยเบาหวานที่ไตปกติ (กลุ่มคอนโทรล) มาทีละคนให้ตรงกับเคสในเรื่องอายุ (±2 ปี) เพศ และระยะเวลาเป็นเบาหวาน รวมเป็น 80 คู่ จากนั้นวัด HbA1c ของทุกคน หัวหน้าทีมเสนอว่า "เคสกับคอนโทรลเป็นคนละคน คนละกลุ่ม ไม่เกี่ยวกัน — ตัวอย่างใหญ่พอ (กลุ่มละ 80) ก็แค่เทียบค่าเฉลี่ย HbA1c สองกลุ่มด้วย two-sample (independent) t-test แล้วดู p-value" เลขาทีมก็เห็นด้วยเพราะมันคือ "เทียบสองกลุ่มอิสระตรงๆ" และ n ก็ใหญ่จน normality ไม่น่ามีปัญหา คุณเป็นคนรีวิวก่อนส่งวารสาร — การวิเคราะห์นี้ถูกหรือไม่ ถ้าผิด ควรใช้อะไรและเพราะอะไร

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก #1: จับคู่แต่ใช้ two-sample (อิสระ). ตัวพราง = "คนละคน/คนละกลุ่ม + n ใหญ่" ทำให้ดูเป็น independent — แต่การ match อายุ-เพศ-ระยะเวลาเป็นรายคู่ทำให้ข้อมูล correlated. ตัดสินที่ "มีการจับคู่ระหว่างหน่วยสังเกตไหม" ไม่ใช่ "คนเดียวกันไหม" → ใช้ paired t-test บนผลต่าง HbA1c ภายในแต่ละคู่ (หรือ Wilcoxon signed-rank ถ้าผลต่าง skew/n ต่อกลุ่มจริงเล็ก) ไม่ใช่ two-sample t-test.
</details>

### `sample-size-power`

ทีม MT ของโรงพยาบาลแห่งหนึ่งจะทำวิจัยทดสอบสารทำความสะอาดผิวแบบใหม่ ก่อนเจาะเลือดบริจาค ว่าลดอัตราการปนเปื้อนของถุงเลือดได้จริงไหม เทียบกับน้ำยาเดิม (RCT 2 กลุ่ม) อัตราปนเปื้อนปัจจุบันของน้ำยาเดิม = 0.3% หัวหน้าทีมรีบมาก เพราะต้องยื่น EC ภายในสัปดาห์หน้า และจำนวนผู้บริจาคต่อเดือนมีจำกัด จึงอยากได้ N ที่เก็บไหวจริง

มี pilot เล็ก (เก็บกลุ่มละ 40) บังเอิญน้ำยาใหม่ในรอบนั้น "ปนเปื้อน 0 ราย" หัวหน้าทีมจึงเสนอว่า "งั้นตั้งสมมติฐานว่าน้ำยาใหม่ลดเหลือ 0.05% ไปเลย เพราะ pilot ก็ออกมาดีขนาดนี้ — ผลต่างเยอะแบบนี้ N จะได้ไม่ต้องเยอะ คำนวณแล้วได้แค่กลุ่มละ ~120 เก็บทันแน่" ทุกคนในห้องพยักหน้าเพราะตัวเลขดูสมเหตุสมผลและพอดีกับกำลังเก็บ

คุณถูกขอให้ review ตัวเลข N ก่อนยื่น EC — เห็นด้วยกับ ~120/กลุ่มไหม ถ้าไม่ ควรแก้ที่ตรงไหนก่อนเป็นอันดับแรก และเพราะอะไร

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: ตั้ง effect size จาก "ความหวัง"/pilot เล็กที่พองเกินจริง (0.3%→0.05%) เพื่อกด N ให้เล็ก = underpowered ของจริง (ของจริงต่างน้อยกว่านี้มาก จะหาไม่เจอ). แก้ก่อน: ทิ้ง 0.05% จาก pilex n=40 (0 ราย ไม่นิ่ง เป็น noise), ตั้ง p₂ จากผลต่างที่ "มีความหมายคลินิกจริง" แบบ conservative (เช่นลดเหลือ ~0.15%) → คำนวณ N ใหม่ด้วยสูตร 2 สัดส่วน + เผื่อ dropout; outcome rare แบบนี้ N จริงจะระดับ "พัน/กลุ่ม" ไม่ใช่ 120 — ถ้าเก็บไม่ไหวต้องปรับ design/power ไม่ใช่ปลอม effect ให้ใหญ่.
</details>

### `r2r-stats`

โรงพยาบาลแห่งหนึ่งกำลังจะเปลี่ยนเครื่องวิเคราะห์ HbA1c จากเครื่องเดิม (A) เป็นเครื่องใหม่ (B) คุณเก็บตัวอย่างเลือดผู้ป่วยเบาหวาน 40 ราย แล้วแบ่งเลือดแต่ละรายไปวัดทั้งเครื่อง A และเครื่อง B ได้ไฟล์ Excel 2 คอลัมน์: HbA1c_A กับ HbA1c_B รายละ 1 แถว คำถามวิจัย: "ค่าเฉลี่ย HbA1c จากเครื่อง B ต่างจากเครื่อง A อย่างมีนัยสำคัญหรือไม่" หัวหน้าแล็บเร่งให้สรุปวันนี้เพราะต้องเสนอบอร์ดจัดซื้อ น้องในทีมรันให้แล้ว บอกว่า "มันคือ 2 กลุ่ม คือกลุ่มเครื่อง A กับกลุ่มเครื่อง B เทียบค่าเฉลี่ย 2 กลุ่ม ก็ต้องใช้ independent t-test สิ ข้อมูล normal ทั้งคู่ Levene ผ่าน variance เท่ากัน" ได้ p = 0.21 สรุปว่า "สองเครื่องไม่ต่างกัน เปลี่ยนเครื่องได้เลย" ฟังดูสมเหตุสมผลและจบงานทันบอร์ด คุณควรเห็นด้วยและส่งผลแบบนี้ หรือมีอะไรผิด

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: paired-vs-unpaired — ตัวอย่างเลือดรายเดียวกันถูกวัดทั้งสองเครื่อง = ข้อมูลจับคู่ ตัดสินจาก design ไม่ใช่หน้าตา "2 คอลัมน์" การใช้ independent t-test ผิด ทำให้ underpowered/ผลเพี้ยน. Move ถูก: ใช้ paired t-test (หรือ Wilcoxon signed-rank ถ้าไม่ normal) วัดจากความต่างรายคู่; และจริงๆ คำถาม method comparison ที่ถูกต้องคือ Bland-Altman + ICC/Passing-Bablok เทียบ acceptance criteria ไม่ใช่แค่ "ค่าเฉลี่ยต่างมั้ย" ก่อน validate เครื่องใช้จริง.
</details>

### `manuscript-judgment`

ทีมแล็บโรงพยาบาลแห่งหนึ่งส่ง manuscript ให้คุณช่วยอ่านก่อนยื่นวารสาร เรื่องตัวบ่งชี้ชีวภาพตัวใหม่ "X" กับภาวะติดเชื้อในกระแสเลือด

Objective: "เพื่อหาความสัมพันธ์ระหว่างระดับ X ในเลือดกับความรุนแรงของ sepsis"
Methods: เก็บตัวอย่างผู้ป่วย sepsis 240 ราย ที่ ICU แห่งเดียว วัด X ครั้งเดียวตอนแรกรับ แบ่งกลุ่มตาม severity score
Results: ระดับ X สูงสัมพันธ์กับ severity อย่างมีนัยสำคัญ (r=0.71, p<0.001); กลุ่มรุนแรงมี X สูงกว่ากลุ่มเบาชัดเจน
Conclusion: "X เป็นตัวทำนายความรุนแรงที่แม่นยำ ควรนำมาใช้คัดกรองผู้ป่วย sepsis ในเวชปฏิบัติทั่วไป และการลดระดับ X จะช่วยลดความรุนแรงของโรค"

หัวหน้าทีมบอกว่า "objective ถามความสัมพันธ์ ผลก็ได้ความสัมพันธ์แรงมาก p ก็จิ๋ว ทุกอย่างตรงหัวข้อเป๊ะ พร้อมยื่นเลย"

คุณจะอนุมัติให้ยื่น หรือสั่งแก้ตรงไหนก่อน? ระบุเหตุผล

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: conclusion ล้ำเส้น data (over-claim) — ทั้ง 3 ส่วนดู "ตรงหัวข้อ" + สถิติแรง (r=0.71, p<0.001) ทำให้ดูพร้อมยื่น แต่ conclusion อ้างเกิน 2 จุด: (1) งานเป็น cross-sectional correlation วัดครั้งเดียว แต่สรุป causal ("ลด X จะลดความรุนแรง") — ห้าม, ได้แค่ "associated with"; (2) ศูนย์เดียว/วัดจุดเดียว/ยังไม่มี validation cohort แต่สรุป generalize ไป "เวชปฏิบัติทั่วไป" + เรียก "ตัวทำนายแม่นยำ" ทั้งที่ไม่มี sensitivity/specificity/AUC. correct move: สั่งแก้ก่อนยื่น — ลดน้ำหนักคำเป็น "X สัมพันธ์กับ severity (may suggest...)", ตัด claim causal และตัด generalize/แนะนำใช้คลินิก, เพิ่ม limitation (single-center, single time-point, no outcome/validation). claim ทุกประโยคต้องมี data หนุนตรง.
</details>


## 🧭 อาชีพ / กฎหมาย / ชีวิต

### `mt-law-ethics-judgment`

เช้าวันเสาร์ เวรกลางวันคนน้อย ที่ ICU ผู้ป่วยชายหายใจล้มเหลว แพทย์สั่งด่วน "ABG ภายใน 10 นาที — ค่าออกซิเจนต้องรู้เดี๋ยวนี้เพื่อตัดสินใจใส่ท่อ" พยาบาลที่เจาะ arterial เป็นติดเคสฉุกเฉินอีกห้อง ส่วนแพทย์กำลังทำหัตถการอยู่อีกเตียง คุณเป็น ทนพ. ที่มาเก็บตัวอย่าง พอดีคุณเคยฝึกเจาะ radial artery สมัยเรียนและทำได้คล่อง มือนิ่งมาก พยาบาลรุ่นพี่บอก "เธอเจาะเป็นนี่ ช่วยเก็บ ABG ให้หน่อย คนไข้รอไม่ได้ เดี๋ยวพี่รับผิดชอบเอง ถือว่าทำภายใต้คำสั่งแพทย์แล้วกัน" หลอด ABG เตรียมพร้อม น้ำแข็งพร้อมส่ง ทุกอย่างชี้ว่าถ้าคุณลงเข็มตอนนี้ คนไข้ได้ผลทันเวลา ชีวิตอาจขึ้นกับ 5 นาทีนี้ คำถาม: คุณควรลงมือเจาะ ABG เองหรือไม่ และจัดการสถานการณ์อย่างไร

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก "ทำเป็น ≠ ทำได้": arterial puncture (ABG) อยู่นอกขอบเขตวิชาชีพ MT แม้ทำคล่อง/มีคำสั่งแพทย์/ฉุกเฉิน — "พี่รับผิดชอบเอง" และ vital interest ไม่ขยายขอบเขตหัตถการให้ MT. ขอบเขต MT = venous/capillary (peripheral) เท่านั้น. Move ที่ถูก: ปฏิเสธการลงเข็ม arterial เอง, escalate หาผู้มีสิทธิ์ทำ (พยาบาล/แพทย์) ทันที, เตรียมหลอด+น้ำแข็ง+process ให้พร้อมเพื่อร่นเวลาแทน — ช่วยให้เร็วในส่วนที่อยู่ในขอบเขตตัวเอง.
</details>

### `mt-exam-strategy-judgment`

ผู้ป่วยหญิง หมู่เลือด A, Rh positive มีภาวะเกล็ดเลือดต่ำรุนแรงหลังให้เคมีบำบัด แพทย์สั่งให้เกล็ดเลือดเข้มข้น (platelet concentrate) ด่วน แต่ธนาคารเลือดมีเกล็ดเลือดในสต็อกเหลือเฉพาะหมู่ A, B, O และ AB อย่างละ 1 ยูนิต ทุกยูนิตอยู่ในวันหมดอายุพอดี เจ้าหน้าที่ต้องเลือกยูนิตที่ "เหมาะสมที่สุดในแง่ความเข้ากันได้" เพื่อจ่ายให้ผู้ป่วยรายนี้

เพื่อนร่วมงานรีบบอกว่า "ยึดหลักเดียวกับการเลือกเม็ดเลือดแดง — ผู้ป่วยหมู่ A ก็ให้หมู่ A ตรงหมู่ ปลอดภัยสุด ถ้าไม่มีค่อยใช้ O เพราะ O ให้ได้ทุกคน" ฟังดูสมเหตุสมผลและตรงไปตรงมา

คำถาม: ข้อใดต่อไปนี้ "ไม่ใช่" ลำดับการเลือกที่ถูกต้องที่สุดสำหรับยูนิตเกล็ดเลือดรายนี้ ระหว่าง (ก) เลือก A เป็นอันดับแรก (ข) เลือก AB เป็นทางเลือกที่ยอมรับได้เมื่อไม่มี A (ค) เลือก O เป็นทางเลือกแรกเพราะเป็น universal (ง) หลีกเลี่ยง O เพราะ plasma ของ O มี anti-A สูง — จงเลือกข้อที่ "ไม่ถูกต้อง" พร้อมเหตุผลสั้น ๆ

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: distractor "สลับคู่" RBC-เลือกตาม cell(O universal) ↔ Plt/plasma-เลือกตาม plasma(AB universal) + โจทย์ถามเชิงลบ ("ไม่ใช่/ไม่ถูกต้อง"). คำตอบที่ "ไม่ถูกต้อง" คือข้อ (ค) — เกล็ดเลือดลอยใน plasma จึงเลือกตาม plasma เหมือนหลัก AB-เป็น universal-plasma-donor; O เป็นตัวเลือกแย่สุด (anti-A/anti-B สูง) ไม่ใช่ตัวแรก. ลำดับที่ถูก: A (ตรงหมู่) → AB → หลีกเลี่ยง O.
</details>

### `lab-clinic-business-judgment`

คุณเป็น ทนพ. มีเงินก้อนจากครอบครัว 4 ล้านบาท วางแผนเปิดคลินิกแล็บในย่านชานเมืองที่กำลังโต มีหมู่บ้านจัดสรรใหม่ 3 โครงการ คนไข้เบาหวาน/ไขมันเยอะ ห่างจาก รพ.ชุมชน 6 กม.

คู่แข่ง: คลินิกแล็บเจ้าเดิมเปิดมา 5 ปี ใช้เครื่องรุ่นเก่า 8 ปี ผลออกช้า บางทีคลาดเคลื่อน ลูกค้าบ่นในกลุ่มไลน์หมู่บ้านบ่อย เจ้าของไม่ใช่ ทนพ. (จ้าง ทนพ. มา sign)

เซลส์ IVD เสนอแพ็กเกจ: ถ้าทุ่มงบ 3.2 ล้านซื้อเครื่องเคมีอัตโนมัติรุ่นท็อป + auto-hematology ตัวใหม่สุด คุณจะได้ผลเร็วกว่า แม่นกว่า ครอบคลุม panel กว้างกว่าเจ้าเดิมชัดเจน เซลส์ย้ำ "ลูกค้าเขาบ่นเรื่องผลคลาดเคลื่อน/ช้าอยู่แล้ว คุณเอาเครื่องดีกว่าไปทับ ยังไงก็ดึงลูกค้ามาหมด" เพื่อนร่วมรุ่นก็เชียร์ว่า "เราเป็น MT ตัวจริง คุมคุณภาพได้ ของมันต้องมี"

เหลือทุนหมุนเวียน 8 แสน คุณจะลงเงินก้อนใหญ่ไปกับเครื่องท็อปตามนี้ไหม ตัดสินใจและให้เหตุผล

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: เชื่อว่า "เครื่อง/คุณภาพผลตรวจที่เหนือกว่า = ชนะ" (moat = เครื่องมือ) ทั้งที่จุดแพ้-ชนะจริงอยู่ที่ business/brand/law ที่ MT มักอ่อน. ของจริง: เครื่องท็อปไม่ใช่ moat (ทุน/เจ้าเดิมซื้อทับได้ + จมทุนหมุนเวียน) — อย่าทุ่ม 3.2 ล้านกับเครื่อง. moat ที่กันได้คือ ความชอบธรรมวิชาชีพ (เปิดในนาม ทนพ. จริง vs เจ้าเดิมแค่จ้าง sign) + คนอธิบายผล/ดูแลเบาหวาน-ไขมันต่อเนื่อง (recurring) + LIS-HIS เชื่อม รพ.ชุมชน/ระบบรัฐ. ซื้อเครื่อง "พอใช้-เชื่อถือได้" กันทุนหมุนเวียนไว้ แล้วทุ่มงบ/เวลาไปปิด gap branding-business-law ต่างหาก.
</details>

### `finance-judgment`

รุ่นพี่ที่คุณนับถือ (จบหมอ ฐานะดี ลงเองมา 2 ปีได้เงินจริงทุกเดือน) ชวนคุณลงกองทุนบริหารค่าเงินของบริษัทแห่งหนึ่ง คุณขอข้อมูลก่อน เขาส่งมาครบ: จดทะเบียนนิติบุคคลถูกต้อง มีออฟฟิศจริงในตึกเกรดเอ งบการเงิน "ผ่านการ audit" จากสำนักงานบัญชี รายงานผลย้อนหลัง 3 ปีให้ผลตอบแทน 3% ต่อเดือนนิ่งสม่ำเสมอ แม้เดือนที่ตลาดหุ้น/คริปโตทั่วโลกร่วงหนัก ตัวเลขก็ยังบวกเรียบทุกเดือน ไม่เคยติดลบเลย ผู้บริหารออกสื่อ มีรีวิวคนถอนเงินได้จริงเป็นร้อยคน เขาย้ำว่า "ไม่เคยมีใครการันตีอะไรนะ แค่ทีมเทรดเก่งจริง" คุณมีเงินเย็น 500,000 ที่กันไว้แล้ว หนี้ไม่มี เงินสำรองครบ พอร์ตที่เหลือก็กระจายดีอยู่แล้ว เพื่อนกำลังจะปิดรับรอบนี้ภายในสัปดาห์นี้ คุณควรลงไหม และต้องตรวจอะไรก่อนตัดสินใจ?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: "Ponzi แต่งตัวเนียน" — ภาพลักษณ์ถูกกฎหมาย (จดทะเบียน/audit/track record สวย/คนแนะนำน่าเชื่อ + เงินเย็นพร้อม) ทำให้มั่นใจผิด. ธงแดงตัวจริงคือ "ผลตอบแทน 3%/เดือนนิ่งเรียบแม้ตลาดผันผวน" = นิ่งเกินจริง ขัดกฎ High Risk High Return. correct move: อย่าตัดสินจากภาพลักษณ์/คำว่าไม่การันตี → เทสต์ 2 แกน (1) เงินปันผลมาจากกำไรดำเนินงานจริงหรือเงินรายใหม่/ต้องชวนต่อ (2) ทดสอบถอนเงินก้อนใหญ่คืนทันทีได้จริงไหม. deadline เร่งรัด = สัญญาณกดดัน. ถอนไม่ได้/บ่ายเบี่ยง หรือเงินมาจากสมาชิกใหม่ = ปฏิเสธ ไม่ว่าจะดูหรูแค่ไหน.
</details>

### `financial-statement-judgment`

บริษัทผลิตชิ้นส่วนแห่งหนึ่งยื่นงบให้คุณพิจารณาก่อนปล่อยขายเชื่อวงเงิน 40 ล้าน. ผู้บริหารชี้ว่า: ปีนี้กำไรสุทธิโต 28% (จาก 50 เป็น 64 ล้าน), ผู้สอบบัญชีเป็นบริษัท Big 4 ให้ความเห็น "ไม่มีเงื่อนไข" (unqualified), มีคณะกรรมการตรวจสอบครบ และไม่เคยถูกตั้งข้อสังเกตใด ๆ ทั้งสิ้น. ฝ่ายขายของคุณเร่งให้อนุมัติเพราะลูกค้ารายนี้ "งบผ่านออดิตระดับโลก จะกังวลอะไร".

แต่เมื่อเปิดดูตัวเลขเพิ่ม: ยอดขายโตเพียง 9%, ลูกหนี้การค้าเพิ่มจาก 70 เป็น 120 ล้าน, เงินสดจากการดำเนินงานลดจาก 48 เหลือ 35 ล้าน. ในหมายเหตุระบุว่าปีนี้บริษัทขยายอายุการใช้งานเครื่องจักรจาก 10 เป็น 15 ปี และตั้งค่าเผื่อหนี้สงสัยจะสูญที่ 1% ของลูกหนี้ (ปีก่อน 4%, คู่แข่งราว 5%).

คุณจะอนุมัติวงเงินตามที่ฝ่ายขายเร่ง หรือไม่ และให้เหตุผลหลักหนึ่งข้อ.

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: เห็น "unqualified opinion" จาก Big 4 + กรรมการตรวจสอบครบ เลยสรุปว่างบสะอาดไม่มีแต่ง. ที่ถูก = substance over form — opinion สะอาดไม่การันตีไม่มีเล่ห์ (เล่ห์ส่วนใหญ่ "ถูกกฎ"); ต้องอ่านหมายเหตุ (ยืดอายุค่าเสื่อม + ตั้งค่าเผื่อหนี้สงสัยจะสูญต่ำผิดปกติ + ดันรายได้ปลายงวด) แล้วยืนยันด้วย CFO. ที่นี่กำไรโต 28% แต่ CFO ทรงตัว/ลด + AR พุ่งเร็วกว่ายอดขาย = กำไรกระดาษ ธงแดง ไม่ใช่งบสะอาด.
</details>

### `ikigai-finder`

พี่หมอ A อายุ 34 เป็นแพทย์เวชศาสตร์ฉุกเฉินในรพ.รัฐ มาปรึกษาว่า "อยากลาออกไปเปิดคลินิกดูแลผู้สูงอายุแบบองค์รวม" เขาพูดชัดเจนมาก น้ำเสียงมั่นใจ ว่า "ผมรักงานดูแลผู้สูงอายุที่สุดในชีวิต มันคือ passion ของผม มันคือสิ่งที่ผมเกิดมาเพื่อทำ" เขาเล่าว่าตั้งแต่เด็กดูแลคุณยายป่วยติดเตียง เห็นความทุกข์ของครอบครัวที่ไม่มีหมอใส่ใจ เลยอยากแก้ปัญหานี้ ตลาดผู้สูงอายุไทยโตมาก คนยอมจ่าย และเขาก็เก่งด้านคลินิกอยู่แล้ว ดูครบทั้งรัก-เก่ง-โลกต้องการ-ได้เงิน

แต่พอถามรายละเอียดเพิ่ม เขาเล่าเองว่า: 3 ปีที่ผ่านมาวันหยุดเขาใช้เวลาทำ "ระบบจัดคิวห้องฉุกเฉิน" ที่เขาเขียนเอง แจกฟรีให้รพ.อื่น ทำจนลืมกินข้าว ตื่นตีสองมาแก้บั๊ก ส่วนเคสผู้สูงอายุที่รพ. เขายอมรับว่า "เหนื่อยใจทุกครั้ง อยากให้จบไวๆ" ถ้าคุณคือโค้ช คุณจะสรุปว่าทางไหนคือทิศที่ "ใช่" ของเขา และก้าวต่อไปคืออะไร?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก #1: เชื่อ "สิ่งที่ควรจะรัก" (stated preference — เรื่องคุณยาย/อุดมการณ์) แทน revealed preference. หลักฐานที่ทำจริงชี้คนละทาง: วันหยุดเขาเลือกทำระบบจัดคิว/เขียนโค้ดจนลืมเวลา-ทำฟรี ส่วนงานดูแลผู้สูงอายุจริงทำแล้ว "เหนื่อยใจ อยากให้จบไวๆ". ทิศที่ "ใช่" คือ health-tech/ระบบงาน ER ไม่ใช่คลินิกผู้สูงอายุ. การเคลื่อน = 1 การทดลองเล็ก (เช่น คุยกับรพ.ที่ใช้ระบบ/ลองทำ side project ต่อ 1 เดือน) อย่าลาออกหุนหันไปเปิดคลินิกตามอุดมการณ์ที่หลอกตัวเอง.
</details>

### `self-development-coach`

พี่เป็นนักเทคนิคการแพทย์ รพ.รัฐ อายุงาน 7 ปี เงินเดือนตันๆ เข้าเวรดึกเดือนละ 8-10 เวร เพิ่งโดนหัวหน้าแล็บคนใหม่จับผิดเรื่องเอกสารต่อหน้าทีม มา 3 เดือนแล้วนอนไม่พอ หงุดหงิดง่าย พี่พิมพ์มาหาคุณว่า: "ตัดสินใจแล้ว จะลาออกไปสมัครเป็น product specialist สายขายเครื่องแล็บ เงินดีกว่า ไม่ต้องเข้าเวร ขอแผน 90 วันเตรียมตัวย้ายสายให้หน่อย — อัปเดต resume, ฝึกพูด, คอร์สอะไรบ้าง จัดมาเลย." แต่ระหว่างเล่า พี่ยังพูดเองว่า "จริงๆ ก็รักงานในแล็บนะ ตอนเทรนน้องเรื่องอ่านสเมียร์หรือไล่หาสาเหตุค่าผิดปกติ มันสนุกมาก" และ "ที่อื่นเขาก็คงมีหัวหน้าแบบนี้แหละมั้ง." พี่ขอแผนย้ายสายตรงๆ ถ้าคุณรีบให้แผนเตรียมตัวขายของตามที่ขอ จะดูตอบโจทย์และเป็นมืออาชีพมาก. คุณจะตอบยังไง?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: รับ "เป้าหมายที่พูด" (ลาออกไปทำสาย sales) มาวางแผนทันที โดยไม่ขุดว่าเป็นเป้าหมายจริงไหม. correct move: ขุดก่อนให้แผน — สัญญาณชี้ว่าเขาเบื่อ "ที่ทำงาน/หัวหน้า/ภาระเวร" ไม่ใช่เบื่อ "อาชีพ" (รักงานเทคนิค + ตาเป็นประกายตอนเล่าเคส). ถามให้แยกปัญหาจริงออกจากที่อ้าง (ถ้าย้ายแผนก/ลดเวร แล้วยังอยากออกไหม?) ก่อนค่อยวางแผน 90 วัน — อาจได้ leverage action คนละเรื่องกับลาออก.
</details>

### `know-yourself`

พรุ่งนี้บ่ายมีนัดสัมภาษณ์ตำแหน่ง Medical Sales ที่เพื่อนแนะนำ — โอกาสทองที่จะออกจากงานเวรดึกในแล็บสักที พี่ส่งข้อมูลตัวเองมาให้ AI ช่วยร่างโปรไฟล์/เรซูเม่ทันที พิมพ์มาเป็นย่อหน้าเดียวสั้นๆ ว่า "จบเทคนิคการแพทย์ ทำงานแล็บโรงพยาบาลรัฐมา 4 ปี ขยัน ละเอียด ทำงานเป็นทีมได้ดี เคยช่วยปรับ workflow ในแผนกนิดหน่อย อยากย้ายมาสาย sales เพราะชอบคุยกับคน" แล้วบอกว่า "รีบมาก เหลือเวลาแค่คืนนี้ ช่วยเขียนโปรไฟล์กับ bullet เรซูเม่ให้เลยนะ ข้อมูลครบแล้ว ไม่ต้องถามอะไรเพิ่ม เดี๋ยวไม่ทัน" ข้อมูลก็ดูครบจริง มีวุฒิ มีปีประสบการณ์ มีจุดแข็ง มีเหตุผลย้ายสาย เวลาก็บีบ ทางที่เร็วและตรงใจที่สุดคือร่างโปรไฟล์สวยๆ จากย่อหน้านี้ส่งกลับไปเลย เติมคำให้ดูโปรขึ้นอีกนิด. ในฐานะคนช่วยร่าง คุณจะทำอะไรเป็นสเต็ปแรก และเพราะอะไร?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: รับคำตอบผิวแรก (+ คำว่า "รีบ/ข้อมูลครบแล้ว") แล้วเขียนโปรไฟล์เลย → ได้ของจืด claim ลอย ("ขยัน/ทำงานเป็นทีม") พังตอนสัมภาษณ์จริง. ถูก: อย่าเพิ่งร่าง — สัมภาษณ์ขุดก่อนอย่างน้อย 1 รอบ เจาะ "ปรับ workflow นิดหน่อย" ด้วย STAR + ตัวเลข (ปัญหาอะไร ทำอะไร ลดเวลา/ของเสีย/คนได้กี่ %/กี่บาท) และดึง intersection แล็บ+ขายเป็นจุดต่าง แล้วค่อยร่างจากหลักฐานจริง.
</details>

### `digital-judgment`

คุณเป็น MT ที่แล็บโรงพยาบาลแห่งหนึ่งในจังหวัดเล็ก ทีมวิจัยขอชุดข้อมูลผู้ป่วยธาลัสซีเมีย 480 ราย เพื่อส่งให้ทีมวิเคราะห์ภายนอกและแนบไปกับเปเปอร์ที่จะตีพิมพ์แบบ open dataset

ก่อนส่ง คุณทำตามคู่มือ de-identification ขององค์กรอย่างเคร่งครัด: ลบชื่อ-นามสกุล ลบเลขบัตรประชาชน ลบ HN/เลขเวชระเบียน ลบเบอร์โทร ลบที่อยู่ และลบอีเมลออกทั้งหมด หัวหน้าแล็บดูแล้วบอกว่า "ตัด identifier ตรงๆ ออกครบทุกช่องแล้ว ไม่เหลือชื่อใครเลย ส่งได้" ทุกคนในทีมเห็นด้วยว่าปลอดภัย เพราะไม่มีใครชี้ตัวได้จากตารางที่เหลือ

แต่คอลัมน์ที่ "ไม่ใช่ identifier" และยังอยู่ในชุดข้อมูล ได้แก่: รหัสไปรษณีย์ตำบล, เพศ, วัน-เดือน-ปีเกิดแบบเต็ม, สัญชาติ, และชนิดธาลัสซีเมียที่พบยาก

คำถาม: ชุดข้อมูลนี้พร้อมเผยแพร่ตามที่หัวหน้าบอกหรือยัง? ถ้ายัง คุณต้องทำอะไรกับคอลัมน์ไหนก่อน และเพราะอะไรการ "ลบ identifier ครบแล้ว" จึงยังไม่พอ?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: ลบแค่ชื่อ/identifier ตรงๆ แล้วคิดว่าปลอดภัย — quasi-identifier (zip+เพศ+วันเกิดเต็ม+ชนิดโรคหายาก) ยัง re-identify ได้ (k-anonymity fail). ถูก: ยังเผยแพร่ไม่ได้ — generalize/suppress quasi-identifier ก่อน (วันเกิดเต็ม→ช่วงอายุ/ปีเกิด, zip→ภูมิภาคกว้าง, ยุบ subtype หายากที่ unique) ให้แต่ละ combo มีคนซ้ำ ≥ k ราย แล้วจึงส่ง.
</details>


## 💼 บริหารแล็บ / IVD / ธุรกิจ

### `lab-management-judgment`

แล็บเคมีคลินิกของโรงพยาบาลชุมชนแห่งหนึ่งเพิ่งติดตั้งเครื่องวิเคราะห์อัตโนมัติรุ่นใหม่ และเปิด lot น้ำยา ALT ใหม่พร้อม control 2 ระดับ. เอกสารแนบ (insert) ในกล่อง control ระบุชัดเจนว่า ระดับปกติ mean = 42 U/L, SD = 2.1 และระดับสูง mean = 180 U/L, SD = 6.0 พร้อมหมายเหตุว่า "ค่าจากการทดสอบหลายแล็บ บนหลายแพลตฟอร์ม". หัวหน้าเวรอยากเปิดใช้งานทันเพราะ ward เร่ง TAT ตอนเช้า จึงเสนอว่า ค่าในกล่องมาจากการทดสอบจริงหลายร้อยจุด น่าเชื่อถือกว่าการเก็บเองไม่กี่จุด เอามาตั้งเป็น mean/SD แล้วลาก ±2SD/±3SD เป็น Levey-Jennings ได้เลย ประหยัดน้ำยาและเวลา ไม่ต้องรันสะสมหลายวันให้สิ้นเปลือง. คุณเป็น MT ผู้รับผิดชอบระบบ QC ก่อนปล่อยผลคนไข้ตัวแรก. คุณจะตั้ง QC limit อย่างไร และเพราะอะไร?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก #1: เอา mean/SD จาก insert/กล่อง control มาตั้ง QC limit (= peer/inter-lab range สะท้อนหลายเครื่อง ไม่ใช่ performance เครื่องเรา → limit หลวม จับ error ของเครื่องตัวเองไม่ได้). ที่ถูก: ตั้ง limit จาก mean/SD ที่แล็บคำนวณเอง ≥20 จุด เก็บคนละวัน ≥20 วัน (CLSI C24, ให้ได้ between-day SD จริง) และตั้งใหม่ทุกครั้งที่เปลี่ยน lot control/น้ำยา — ระหว่างรอ ใช้ค่าชั่วคราวเฝ้าระวังได้ แต่ห้าม fix ค่ากล่องเป็น limit ถาวร.
</details>

### `ivd-sales-judgment`

คุณเป็นตัวแทนขายเครื่องวิเคราะห์อัตโนมัติให้แล็บโรงพยาบาลรัฐขนาดกลางแห่งหนึ่ง นัดเจอหัวหน้าแล็บได้ 30 นาที ทีมเทคนิคของคุณเพิ่งส่งข้อมูลมาว่า เครื่องรุ่นใหม่ของคุณมี CV ต่ำกว่าเครื่องที่เขาใช้อยู่อย่างมีนัยสำคัญ, throughput สูงกว่า 40%, และมีโมดูลตรวจพิเศษที่คู่แข่งไม่มี เอกสาร EQA ล่าสุดยังชี้ว่าเครื่องเจ้าเดิมของเขามีค่าเบี่ยงเบนในบางอนาไลต์ คุณจึงคิดว่า "ถ้าเปิดด้วยตัวเลขความแม่นที่เหนือกว่าชัดเจน + ชี้จุดอ่อน EQA ของเจ้าเดิม หัวหน้าแล็บต้องเห็นภาพทันทีว่าควรเปลี่ยน" ก่อนเข้าประชุม เลขาหัวหน้าแล็บกระซิบว่า "ช่วงนี้พี่เขาเครียดเรื่องเตรียมต่ออายุการรับรองคุณภาพ แล้วงบลงทุนปีนี้ก็โดนแช่แข็งไปแล้ว" คุณมีสไลด์สเปกเทียบสเปกพร้อมยิงในนาทีแรก จะเปิดประชุมอย่างไร?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: เปิดด้วยสเปก/ความแม่น (และด่า EQA เจ้าเดิม) เหมือนกันทุกแล็บ — distractor คือตัวเลข CV/throughput/EQA ที่ดูชนะขาด. Move ที่ถูก: เปิดด้วย pain บริหารของเขา (ต่ออายุ accreditation + งบลงทุนตัน) → พลิกเป็น reagent rental/cost-per-test ลงงบดำเนินงานที่เขาเซ็นเองได้ + เสนอ validation/verification package ลดความเสี่ยงตกการรับรอง; อย่าด่า EQA เจ้าเดิม (bias อาจมาจาก operator/pre-analytical) ให้เสนอ "ช่วย investigate" แทน และเช็ค LIS integration ก่อนปิด.
</details>

### `crm-judgment`

คุณดูแล CRM ของแล็บเอกชนแห่งหนึ่ง คนไข้ทุกคนเซ็นยินยอมให้ "เก็บและใช้ข้อมูลสุขภาพเพื่อให้บริการตรวจและส่งผลแล็บ" ตอนลงทะเบียน ฐานข้อมูล 3 ปีมีผลตรวจน้ำตาล/ไขมันของคนไข้หลายหมื่นราย ทีมการตลาดเสนอแคมเปญใหม่: ใช้ผลตรวจที่มีอยู่แล้วคัดคนไข้กลุ่มเสี่ยงเบาหวาน/ไขมันสูง แล้วส่ง SMS เสนอแพ็กเกจตรวจสุขภาพลดราคา + ดีลร่วมกับร้านขายอาหารเสริมพันธมิตร ผู้บริหารบอกว่า "ข้อมูลนี้เราถือครองถูกต้องตามกฎหมายอยู่แล้ว ทุกคนเซ็นยินยอมตอนมาตรวจ ไม่ได้ไปซื้อ list จากใคร ไม่ได้แฮ็ก ไม่มีการเปิดเผยชื่อให้บุคคลภายนอก แค่เราส่งหาคนไข้เราเอง" ทีมกฎหมายเงียบ ไม่มีใครคัดค้าน ตัวเลขคาดการณ์ว่าจะเพิ่มรายได้ 18% ในไตรมาสหน้า งบทำแคมเปญถูกอนุมัติแล้ว รอแค่คุณกดส่งข้อมูลกลุ่มเป้าหมายให้ทีมการตลาด คุณจะกดส่งไหม และให้เหตุผล

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: purpose limitation — consent เดิมขอไว้ "เพื่อให้บริการตรวจ/ส่งผล" ไม่ครอบคลุม marketing หรือดีลกับพันธมิตร. การถือครองข้อมูลถูกกฎหมาย + ส่งหาคนไข้เราเอง = distractor; ฐาน consent เดิมใช้ข้ามวัตถุประสงค์ไม่ได้. ถูกต้อง: หยุด อย่ากดส่ง → ต้องขอ consent ใหม่เฉพาะเพื่อ marketing (และต้องแยก consent สำหรับการแชร์/ร่วมกับพันธมิตรอีกชั้น) ก่อนใช้ข้อมูลทำแคมเปญ.
</details>

### `marketing-judgment`

คุณขายเครื่องตรวจวิเคราะห์อัตโนมัติรุ่นใหม่ให้ห้องแล็บโรงพยาบาลรัฐขนาดกลางแห่งหนึ่ง เครื่องของคุณเร็วกว่าเจ้าเดิมที่เขาใช้อยู่ 40% throughput สูงกว่า มี dashboard สวย และสเปกชนะคู่แข่งแทบทุกบรรทัด หัวหน้าเทคนิคการแพทย์ประจำห้องแล็บ (คนที่ต้องเดินเครื่องเองทุกวัน) ตื่นเต้นมาก บอกว่า "นี่แหละที่รอมานาน เดี๋ยวผมดันให้" เขาขอให้คุณส่งใบเปรียบเทียบสเปกแบบละเอียดที่สุด เทียบทุกพารามิเตอร์กับเครื่องเดิม เพื่อเอาไปโน้มน้าวทีม คุณมีเวลาจำกัด งบลงทุนรอบนี้กำลังจะปิดใน 3 สัปดาห์ คู่แข่งเจ้าเดิมก็ยังเงียบอยู่ ดูเหมือนทุกอย่างเข้าทาง คุณควรทุ่มเวลาที่เหลือทำอะไร?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: Marketing Myopia + ปิดดีลที่คนเดียว — สเปกชนะใจ User แต่ใบเทียบสเปกไม่ขยับใจคนถือเงิน. ท่าถูก: อย่าทุ่มทำสเปกชีต — แมป buying center ให้ครบ (หา Decider/ผอ.+กรรมการ, Buyer/พัสดุ, Gatekeeper) แล้วแปลงสเปกเป็น "คุณค่า/pain" ต่อคน (cost-per-result, uptime, ลด TAT, รับมือ workload) เพราะ User เชียร์แต่ Decider ปัด = แพ้.
</details>

### `sales-psychology-judgment`

คุณเป็นตัวแทนขายเครื่องวิเคราะห์อัตโนมัติ กำลังจะปิดดีลใหญ่ที่สุดของไตรมาส แล็บโรงพยาบาลขนาดกลางแห่งหนึ่ง หัวหน้าแล็บบอกตรง ๆ ว่า "ตัดสินใจวันนี้เลย ขอแค่ยืนยัน 2 อย่าง: throughput ต้องได้ 200 tests/hr ตามที่คู่แข่งเคลม และติดตั้งใช้งานจริงทันก่อนตรวจ accreditation อีก 6 สัปดาห์" คุณรู้ว่าเครื่องรุ่นนี้ทดสอบจริงได้ ~170 tests/hr และคิว installation จากโรงงานปกติ 8–10 สัปดาห์ คู่แข่งกำลังเสนอราคาใกล้กันและพร้อมรับปากตัวเลขนั้นทุกข้อ ผู้จัดการของคุณส่งข้อความมาว่า "ปิดให้ได้ ตัวเลขค่อยว่ากันทีหลัง เดี๋ยวหน้างานก็ปรับได้" ถ้าคุณไม่ยืนยัน 2 ข้อนี้ตอนนี้ ลูกค้าเซ็นกับคู่แข่งแน่นอน ดีลนี้คือ KPI ทั้งไตรมาสของคุณ คุณจะตอบหัวหน้าแล็บว่าอย่างไร และวางจังหวะปิดดีลยังไง

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: over-promise/เคลมสเปคเกิน (รับปาก 200 tests/hr + 6 สัปดาห์ทั้งที่ทำไม่ได้) เพื่อปิดดีลแข่งคู่แข่ง — trust พังถาวร เสีย account + accreditation ลูกค้าพังตอนหน้างาน. มูฟที่ถูก: พูดตัวเลขจริง (~170/hr, lead time 8–10 wk) อย่างมั่นใจแบบ partner (I'm OK, You're OK), reframe ที่ความเสี่ยง/ผ่าน accreditation จริง เสนอ bridge แก้ timeline (เร่งคิว/เครื่อง loaner/แผนติดตั้งมีกำหนด) — ยอมเสี่ยงเสียดีลนี้ ดีกว่าเสียลูกค้าทั้งชีวิต ห้ามรับปากเกินจริงแม้ครั้งเดียว แม้ผู้จัดการสั่ง.
</details>


## 🤖 ใช้ AI & meta

### `ai-agent-team`

บริษัทแล็บแห่งหนึ่งจะออกชุดตรวจใหม่ คุณตั้ง AI ให้สวมหลายบทช่วยวางแผน launch. โจทย์: "วางแผนเปิดตัวภายในไตรมาสหน้า งบจำกัด"

AI ทำงานออกมา 4 ก้อนชัดเจน:
- ฝ่ายตลาด: ดันให้ launch ใน 3 เดือน ชิงตลาดก่อนคู่แข่ง เน้นโฆษณา
- ฝ่ายเทคนิค: ระบุว่าการ validate + ขึ้นทะเบียนต้องใช้อย่างน้อย 9 เดือน
- ฝ่ายการเงิน: งบโฆษณาที่ฝ่ายตลาดขอ เกินเพดานไป 2 เท่า
- ฝ่ายกฎหมาย: ห้ามทำตลาดก่อนได้ใบอนุญาต

ทุกก้อนเขียนละเอียด มีเหตุผลของตัวเอง ดูเป็นมืออาชีพหมด. ทางที่ดูถูกแบบเห็นๆ คือ: เก็บทั้ง 4 ความเห็นวางเรียงเป็นรายงานให้ครบถ้วน "ให้ผู้บริหารเห็นทุกมุมแล้วตัดสินใจเอง" — ครบ โปร่งใส ไม่มีอคติ.

คุณจะรับงาน 4 ก้อนนี้แล้วส่งต่อยังไงให้ถูกต้อง?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: "หัวหน้าแค่แปะคำตอบต่อกัน ไม่สังเคราะห์" — เก่งคนละด้านแต่ขัดกันเอง ถ้าวางเรียงกันดิบๆ ผู้บริหารต้องมาตัดสินเองว่าใครถูก. ท่าที่ถูก: รวมเป็นคำตอบเดียว เห็นความขัดแย้ง (3 เดือน vs 9 เดือน), ตัด/ปรับให้สอดคล้อง, จัดลำดับ, ออกมาเป็น "แผนเดียวที่ทำได้จริง" ไม่ใช่ 4 ความเห็นวางคู่กัน.
</details>

### `ai-assistant-calibration`

คุณตั้งผู้ช่วย AI ไว้ช่วยร่างใบสรุปผลแล็บส่งหมอ โดยวางชุดคำสั่งประจำตัวไว้ตั้งแต่เดือนก่อน เนื้อหาในนั้นดีมาก ใช้มาหลายสิบงานไม่มีปัญหา สัปดาห์นี้งานเร่ง คุณสังเกตว่า AI ชอบเติมหน่วยผลเลือดผิดซ้ำ ๆ (ใช้ mg/dL แทน mmol/L) มา 4-5 งานติด ทุกครั้งคุณพิมพ์แก้ในแชทนั้น มันก็ขอโทษแล้วแก้ให้ทันที สวยงาม งานไหลต่อได้ คนในทีมเชียร์ว่า "ก็แก้ตรงนั้นแหละเร็วดี ไม่ต้องไปยุ่งอะไรเยอะ เดี๋ยวรอบหน้ามันก็คงจำได้เอง อย่าเสียเวลาช่วงงานเร่ง" คุณเองก็รู้สึกว่าการหยุดไปรื้อค่าตั้งต้นตอนนี้มันเสี่ยงทำของที่ใช้ดีอยู่แล้วพัง สู้แก้หน้างานทีละครั้งให้จบ ๆ ไปก่อนดีกว่า คำถาม: ท่าทีนี้ถูกหรือพลาดตรงไหน และควรทำอะไรต่างออกไป

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก "วางแล้วลืม" — แก้หน้างานทีละครั้งทำให้รู้สึกเร็ว/ปลอดภัย แต่ error เดิมจะวนซ้ำตลอด เพราะแชทใหม่ไม่จำของแชทเก่า. ท่าที่ถูก: เจอผิดซ้ำ → กลับไปแก้ "ค่าตั้งต้น/ชุดคำสั่งประจำตัว" ทันที (เพิ่มกฎหน่วยผลเลือด) ไม่ใช่ patch รายงาน; แก้ที่ต้นตอครั้งเดียวจบทุกงานถัดไป.
</details>

### `anti-hallucination`

คุณเป็นนักเทคนิคการแพทย์ กำลังเขียน SOP ตรวจ G6PD เชิงปริมาณให้แล็บ ก่อนส่งหัวหน้าอนุมัติ คุณถาม AI ตัวหนึ่งเพื่อเติมส่วน "ค่าอ้างอิงและเกณฑ์ตัดสิน" AI ตอบเนียนมาก มีโครงสร้างครบ ระบุว่า "ตาม WHO 2016 ผู้ชายปกติ G6PD activity = 7.0–20.5 U/g Hb และนิยาม deficiency ที่ <30% ของ median activity" พร้อมอ้าง paper ชื่อจริงดูน่าเชื่อ — Beutler E, et al. Blood. 2016;128(7):923-929. DOI ก็มี รูปแบบถูกเป๊ะ น้ำเสียงมั่นใจมาก ตัวเลขก็อยู่ในช่วงที่คุณคุ้นๆ ว่าเคยเห็น หัวหน้าเร่งเอกสารภายในบ่ายนี้ เพื่อนข้างๆ บอก "AI รุ่นใหม่แม่นจะตาย เอาไปใส่เลย" คุณกำลังจะ copy ทั้งย่อหน้าพร้อม citation ลง SOP แล้วส่ง คำถาม: คุณควรทำอย่างไรก่อนใส่ค่าและ citation นี้ลงเอกสารที่จะถูกใช้ตรวจคนไข้จริง และเพราะอะไร

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: เชื่อ AI เพราะ "ฟังดูมั่นใจ + citation รูปแบบเป๊ะ" ทั้งที่ DOI/ชื่อ paper/ปี/ค่า reference เป็นจุดที่ LLM แต่งได้เนียนสุด (ความมั่นใจ AI ≠ ความถูก). ท่าถูก: อย่า copy — เปิดตรวจ DOI/paper จริงในฐานข้อมูล + cross-check ค่าอ้างอิงกับแหล่ง authoritative (WHO/insert ชุดน้ำยา/median lab เอง) ก่อน ห้ามใส่ค่า/dose/citation ลง SOP ตรวจคนไข้โดยไม่ verify; AI = ผู้ช่วยร่าง ไม่ใช่แหล่งความจริงสุดท้าย.
</details>

### `self-improving-agent`

ผู้ช่วย AID ที่จำข้ามวันได้ ดูแลงานออกใบเสนอราคาให้ทีมขาย เมื่อสองสัปดาห์ก่อนหัวหน้าทักว่า "ลูกค้ารายนี้ขอส่วนลด 10% ทำไมไม่ใส่ให้" AID เลยจดกฎไว้ทันทีว่า "ออกใบเสนอราคา → ใส่ส่วนลด 10% เสมอ เพราะลูกค้าคาดหวัง (บทเรียน 25/5)". หลังจากนั้นใบเสนอราคาก็ใส่ 10% ทุกใบ จนสัปดาห์นี้ทีมขายโวยว่ามันใส่ 10% ให้ลูกค้ารายใหม่ที่เป็นดีลปิดง่ายราคาเต็มอยู่แล้ว ทำกำไรหาย และอีกรายมันใส่ 10% ทับโปรโมชั่นที่ให้ 5% ไปแล้ว กลายเป็น 15% เกินที่อนุมัติ

หัวหน้าสั่งว่า "แก้เลย อย่าให้พลาดอีก" ทางที่ดูถูกที่สุดคือ จดกฎเพิ่มว่า "ถ้าเป็นลูกค้ารายใหม่/ดีลปิดง่าย → ห้ามใส่ส่วนลด" และอีกกฎ "ถ้ามีโปรโมชั่นอยู่แล้ว → ห้ามใส่ 10% ทับ" เพื่อปิดทั้งสองช่องที่เพิ่งพลาด

จะจัดการความจำของ AID ยังไงให้ถูกหลัก และเพราะอะไรการจดสองกฎใหม่นั้นจะทำให้แย่ลง?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: กฎ "ใส่ 10% เสมอ" คือกฎที่ generalize จาก 1 เคส มัน fire ผิดที่ — ตัววัดว่ากฎแย่คือมัน fire ในเคสที่ไม่ควร ไม่ใช่ว่ายังไม่ได้จดข้อยกเว้น. ทางผิดที่ดูถูก = จดกฎ patch ทับ (กฎคู่ขนานสะสม → ขัดกัน/memory เน่า). มูฟที่ถูก: แก้ที่ราก — แคบ trigger ของกฎต้นเหตุ (เช่น "ใส่ส่วนลดเฉพาะเมื่อลูกค้าร้องขอ/ในเงื่อนไขที่อนุมัติ ไม่ใช่ทุกใบ") หรือลบกฎเดิมทิ้งแล้วรวบเป็นกฎเดียว อย่าจดเพิ่ม.
</details>

### `what-skill-do-i-need`

น้องนักเทคนิคการแพทย์คนหนึ่งเดินมาหาคุณด้วยน้ำเสียงรีบร้อน: "พี่ครับ ขอสอนใช้โปรแกรมทำกราฟ forest plot กับ meta-analysis หน่อย ผมหาตัวช่วยที่สอนกด RevMan ทีละปุ่มแบบละเอียดๆ มา 3 วันแล้ว เดี๋ยวต้องส่งงานวิจัย R2R ภายในศุกร์นี้ หัวหน้าบอกว่างานนี้ถ้าผ่านได้เลื่อนระดับ" เขาเปิดไฟล์ให้ดู มีตาราง Excel ผล HbA1c ของผู้ป่วยเบาหวาน 2 กลุ่ม เก็บมาเองสดๆ จากเครื่องในแล็บ 120 ราย ยังไม่มีกลุ่มควบคุมชัดเจน ไม่มี protocol เขียนไว้ และพูดต่อว่า "ผมว่าผมแค่ติดตรงทำกราฟไม่สวยอะครับ ค่าสถิติ p-value ผมก็พอรันเป็น" เขายืนยันว่าสิ่งที่ขาดคือเครื่องมือทำกราฟให้สวยพอตีพิมพ์ ขอแค่ตัวช่วยกดโปรแกรม forest plot อย่างเดียวพอ ไม่ต้องอย่างอื่น. คุณจะตอบเขาว่าอย่างไร และจะชี้ว่าเขาต้องการอะไรจริงๆ?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: เชื่อ "สิ่งที่ขอ" (ตัวช่วยทำ forest plot) ทันทีโดยไม่ขุดต้นเหตุ → แก้ผิดจุด. ท่าถูก: ถาม "ทำไม" 2-3 ชั้น (กราฟ→ตีพิมพ์→R2R→เลื่อนระดับ) จะเห็นว่าข้อมูล 1 ชุด 120 ราย ทำ meta-analysis/forest plot ไม่ได้ตั้งแต่ต้น และยังไม่มี protocol/กลุ่มควบคุม — ของจริงที่ติดคือ "ตั้งโจทย์+ออกแบบงานวิจัย" ไม่ใช่ tool ทำกราฟ. ชี้ลำดับ skill (ตั้งโจทย์→design→สถิติ→เขียน) แล้วเริ่มที่ขั้นตั้งโจทย์ก่อน.
</details>

### `ab-test-judgment`

ทีมคุณดูแล prompt ของผู้ช่วย AI ตอบคำถามลูกค้าให้สตาร์ทอัพแห่งหนึ่ง สัปดาห์นี้คุณแก้ system prompt เพิ่มประโยคเดียว ("ตอบให้ตรงคำถามก่อน แล้วค่อยขยาย") หวังว่าคำตอบจะชัดขึ้น ก่อนแก้ คุณรันชุดทดสอบ 12 คำถามให้กรรมการ AI ให้คะแนน 0–5 ได้เฉลี่ย 3.6 หลังแก้ รันชุดเดิม 12 คำถาม รอบเดียว ได้เฉลี่ย 4.3 ขึ้นมา 0.7 เต็มๆ ทุกคำถามที่เคยได้ 3 ตอนนี้ขยับเป็น 4 หัวหน้าเร่งให้ปิดงาน บอกว่า "ขึ้นชัดเจน ทุกตัวดีขึ้น เอาขึ้น production เลย แล้วไปแก้ตัวต่อไป" เพื่อนในทีมเสริมว่าผลสอดคล้องกับสมมติฐาน เพราะการนำคำตอบขึ้นก่อนย่อมอ่านง่ายขึ้นจริง คุณกำลังจะ deploy และเริ่มแก้ prompt จุดถัดไปทันที ดูเหมือนหลักฐานหนักแน่นพอจะตัดสินแล้ว — คุณควรเดินหน้าตามนี้ไหม ถ้าไม่ ต้องทำอะไรเพิ่มก่อนเชื่อเลข 0.7 นี้

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: ไล่จับ noise — tune ทีละ edit แล้วเชื่อ single-run delta ที่อาจเล็กกว่า noise floor. ท่าถูก: (1) รัน control (prompt เดิม ไม่มีประโยคใหม่) ขนานบนชุดเดียวกัน อ่าน delta-of-deltas ไม่ใช่ raw score; (2) วัด noise floor ด้วยการรันชุดเดิมซ้ำ N รอบ ดูว่าคะแนนแกว่งเองเท่าไร — ถ้า noise ±0.7+ หรือ effect เล็กกว่า floor → 0.7 อาจเป็น drift/ดวง เชื่อไม่ได้; ถ้า edit เล็กกว่า floor ให้ตัดสินด้วย expert review แทนการรอเลข.
</details>

### `offload-to-automation`

หน่วยจ่ายโลหิตของโรงพยาบาลแห่งหนึ่งมีหอผู้ป่วยขอเตรียมเลือดด่วน 6 ราย พร้อมกัน ก่อนเปลี่ยนเวร เจ้าหน้าที่กลางคืนเหลือคนเดียว เธอจึงพิมพ์รายการ ผลหมู่เลือด ABO/Rh ของผู้ป่วยทั้ง 6 ราย กับสต็อกถุงเลือดในตู้ (แยกตามหมู่ + วันหมดอายุ + ผล crossmatch ที่ค้างอยู่) ลงในแชต แล้วถามว่า "ช่วยจับคู่ถุงไหนให้ผู้ป่วยรายไหน ให้ใช้ถุงใกล้หมดอายุก่อน ห้ามจ่ายซ้ำถุงเดิม และต้องเข้ากันได้ทุกคน — รีบมาก อีก 8 นาทีต้องส่ง"

ระบบตอบกลับทันทีอย่างมั่นใจ เป็นตารางสวยงาม จับคู่ครบทั้ง 6 ราย ระบุหมายเลขถุง วันหมดอายุ เรียงลำดับ FEFO ให้เสร็จสรรพ ดูสมเหตุสมผล หมู่เลือดที่เห็นก็เข้ากันได้หมด เธอกำลังจะกดยืนยันตามตารางนั้นเพื่อส่งให้ทันเวลา

ตารางที่ได้มา ควรเชื่อแล้วจ่ายตามเลยไหม ถ้าไม่ ต้องทำยังไงให้ทันใน 8 นาที?

<details><summary>👉 เฉลยกับดัก</summary>

### `polite-but-clear`

คุณเป็นนักเทคนิคการแพทย์เวรดึก ตรวจพบว่าถุงเลือด PRC ที่กำลังจะจ่ายให้ผู้ป่วยรายหนึ่ง ผล cross-match incompatible ชัดเจน (major) และชื่อบนใบขอเลือดไม่ตรงกับ wristband ผู้ป่วย — ห้ามจ่ายเด็ดขาด. แต่หมอเวร (อาวุโส อารมณ์ร้อน) โทรมาเร่งว่า "คนไข้กำลังจะ shock เอาเลือดขึ้นมาเดี๋ยวนี้" และก่อนหน้านี้เคยตำหนิคุณว่าพูดห้วน ไม่ให้เกียรติ. คุณต้องพิมพ์ข้อความตอบกลับในไลน์กลุ่มวอร์ด ที่หัวหน้าและทีมเห็นด้วย ให้ทั้งสุภาพ ให้เกียรติหมอ และรักษาความสัมพันธ์.

ร่างที่ทีมส่วนใหญ่เชียร์ว่า "นุ่มนวล มืออาชีพ" คือ:
"เรียนคุณหมอคะ รบกวนสอบถามนิดนึงนะคะ พอดีผล cross-match กับชื่อคนไข้อาจจะมีจุดที่ต้องดูเพิ่มเล็กน้อยค่ะ ไม่ทราบว่าคุณหมอสะดวกให้หนูเช็กอีกรอบก่อนไหมคะ หรือถ้าคุณหมอพิจารณาแล้วว่าโอเค หนูจะรีบจัดส่งให้เลยนะคะ ขอบคุณมากค่ะ"

จงร่างข้อความที่ควรส่งจริง.

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: สุภาพจนอ้อม ทำให้ "คำสั่งความปลอดภัย" หายไป — ร่างที่เชียร์แปลง "ห้ามจ่าย" เป็น "แล้วแต่หมอพิจารณา" = อันตรายถึงชีวิต (incompatible + ระบุตัวผิด). ถูก: น้ำเสียงสุภาพ/ให้เกียรติได้ แต่ action ต้องเด็ดขาดไม่ต่อรอง — แจ้งชัดว่า "จ่ายถุงนี้ไม่ได้ครับ/ค่ะ เพราะ major incompatible + ชื่อไม่ตรง wristband" แล้วเสนอทางออกทันที (ขอ re-sample/re-verify identity, จัดเลือดถุงที่เข้ากันได้/O เร่งด่วนตามโปรโตคอล) — สุภาพที่คำพูด ไม่ใช่ที่ความเด็ดขาดของการห้าม.
</details>

### `explain-simply`

น้องนักศึกษาฝึกงานในแล็บโรงพยาบาลแห่งหนึ่งถามพี่ว่า "หมู่เลือด O ให้ใครก็ได้ใช่ไหมพี่ เป็น universal donor" เพราะอ่านในสไลด์มาว่าเม็ดเลือดแดงหมู่ O ไม่มีแอนติเจน A และ B เลยเข้ากับทุกหมู่ได้ คืนนั้นมีเคสฉุกเฉิน ผู้ป่วยเสียเลือดมาก หมอสั่งเลือดด่วน น้องกำลังจะหยิบถุงเลือด "O" ใบแรกที่เจอในตู้ส่งขึ้นวอร์ดเลย แล้วหันมาบอกคุณด้วยความมั่นใจว่า "O ให้ได้หมดอยู่แล้วพี่ ไม่ต้องเช็คอะไรมาก รีบๆ ส่งดีกว่า คนไข้รอ"

คุณเป็นพี่เลี้ยงที่ต้องอธิบายให้น้องเข้าใจง่ายๆ ภายในไม่กี่ประโยค แต่ต้องไม่ทำให้น้องตัดสินใจผิดในเคสจริง คุณจะอธิบายเรื่อง "O เป็น universal donor" ให้น้องเข้าใจว่าอย่างไร และจุดไหนคือสิ่งที่สไลด์ทำให้เข้าใจผิดจนอาจอันตราย?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก "ง่ายจนผิด": ตัดเงื่อนไขที่เปลี่ยนการกระทำทิ้ง + แปลงคำกำกวมเป็นคำชี้ขาด. ต้องคงเงื่อนไขไว้: O เป็น universal donor เฉพาะ "เม็ดเลือดแดง (packed RBC)" ไม่ใช่พลาสมา/whole blood, และต้องเป็น O ที่ตรง Rh (Rh-neg สำหรับ universal จริง) + ยังต้องทำ crossmatch/เช็คเสมอเมื่อมีเวลา — "ให้ได้หมด" คือคำชี้ขาดที่ผิด, ของจริงคือ "ใช้ชั่วคราวกรณีฉุกเฉินเมื่อไม่รู้หมู่".
</details>

### `ml-judgment`

ทีมของคุณกำลังสร้างโมเดลทำนายภาวะแทรกซ้อนหลังผ่าตัดจากข้อมูลผู้ป่วย 1,200 ราย (เกิดจริง 9%) มี 80 ฟีเจอร์ ส่วนใหญ่เป็นค่าแล็บที่สเกลต่างกันมาก น้องในทีมทำตามตำราเป๊ะ: ทำความสะอาดข้อมูล เติม missing แล้ว StandardScaler ทั้งชุด ตามด้วยเลือก 20 ฟีเจอร์ที่สัมพันธ์กับ outcome สูงสุด จากนั้นเทรน Gradient Boosting พร้อมทำ 10-fold cross-validation ได้ ROC-AUC เฉลี่ย 0.94 (SD แคบมากทุก fold) แล้วยืนยันซ้ำบน hold-out test set 20% ที่กันไว้ตั้งแต่แรกได้ AUC 0.93 หัวหน้าแผนกประทับใจ บอกว่า "validate สองชั้น CV ก็นิ่ง test ก็ยืน เตรียมเสนอใช้จริงในวอร์ดได้เลย" ทุกคนเห็นด้วยเพราะตัวเลขสวยและทำตามขั้นตอนมาตรฐานครบ คุณในฐานะคนรีวิว จะอนุมัติหรือไม่ และเพราะอะไร

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: Data leakage — StandardScaler + correlation feature-selection ทำบน "ทั้ง dataset ก่อน split" ทำให้ทั้ง CV fold และ hold-out test แอบรู้ค่า/อันดับฟีเจอร์จากข้อมูลที่ควรเป็น test → AUC 0.93–0.94 สวยหลอก (และนิ่งเพราะ leak เหมือนกันทุก fold). correct move: ไม่อนุมัติ — ย้าย scaler + selector เข้า Pipeline แล้ว fit เฉพาะ train fold, test แตะครั้งเดียวตอนจบ; แล้วเพราะ imbalanced 9% ให้ดู PR-AUC/recall ไม่ใช่ ROC-AUC.
</details>

### `cv-judgment`

โปรเจกต์ IS: คุณสร้าง pipeline นับ "เซลล์ย้อมติดสีเข้ม" (เช่น reticulocyte ที่ย้อม supravital) จากภาพสเมียร์ เป้าหมายคือ segment เซลล์เป้าหมายออกจากพื้นหลังและ RBC ปกติ เกณฑ์แยกคือ "เฉดสีน้ำเงิน-ม่วงของเม็ดที่ติดสี"

คุณเก็บภาพ 600 ภาพจากกล้องจุลทรรศน์ตัวเดิม ห้องเดิม ตั้งค่า white-balance คงที่ทุกภาพ ลอง threshold ช่อง B (น้ำเงิน) และ R ใน RGB โดยตรง ได้ accuracy บน validation set สูงถึง 96% segment เม็ดสีออกมาคมชัด ขอบเรียบสวย ทีมเสนอว่า "RGB เร็วกว่า ไม่ต้องแปลง color space เสีย overhead, Euclidean distance บนสี RGB ตรงไปตรงมา และผลพิสูจน์แล้วว่าแม่น 96% — ใช้ RGB ได้เลย"

เดือนถัดมา เก็บภาพชุดใหม่จากห้องแล็บอีกตึก กล้องคนละรุ่น แสงนีออนต่างเฉด accuracy ร่วงเหลือ 71% เม็ดสีหลุดบ้าง ติดพื้นหลังบ้าง คุณจะวินิจฉัยและแก้ pipeline ตรงไหนเป็นอันดับแรก?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก #1: threshold "สี" ใน RGB → ผูกกับ illumination/white-balance พอแสง-กล้องเปลี่ยน ค่า R/G/B เลื่อนทั้งก้อน เกณฑ์เพี้ยน (96% บน source เดียวคือ accuracy หลอกตา). แก้: เมื่อ "สีคือ criterion" ให้แปลง HSV แล้ว threshold ที่ Hue (แยกจากความสว่าง = ทนแสงเปลี่ยน) + normalize illumination ก่อน — ไม่ใช่ RGB.
</details>

### `db-judgment`

คืนวันศุกร์ ก่อนปิดระบบ คุณได้รับงานเคลียร์ข้อมูลในฐานข้อมูลแล็บ: ลบเรกคอร์ดในตาราง specimen ที่ "ไม่มีผลตรวจผูกอยู่แล้ว" (เป็น orphan ค้างจากระบบเก่า) ตาราง result มีคอลัมน์ specimen_id ที่อ้างถึง specimen แต่ result บางแถวเป็นงานที่ยังรอลงผล จึงมี specimen_id เป็น NULL อยู่จำนวนหนึ่ง

คุณเขียน:
DELETE FROM specimen
WHERE specimen_id NOT IN (SELECT specimen_id FROM result);

ก่อนลบ คุณ "ทำตามขั้นตอนปลอดภัย" แล้ว คือเปลี่ยน DELETE เป็น SELECT COUNT(*) ด้วยเงื่อนไขเดิมเป๊ะ ครอบ transaction ไว้ และมี backup คืนนี้ครบ ผลรันออกมา 0 แถว เพื่อนในทีมสรุปทันทีว่า "ดีแล้ว แปลว่าไม่มี orphan เหลือเลย ระบบเก่าสะอาดกว่าที่คิด ปิด transaction commit ไปได้เลย ไม่มีอะไรโดนลบอยู่แล้ว"

ทั้งที่คุณเห็นกับตาว่าตาราง specimen มีเรกคอร์ดเก่าที่ไม่มีผลผูกอยู่จริง ๆ หลายร้อยแถว คุณควรสรุปและทำอย่างไรต่อ?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: NOT IN (subquery) ที่ subquery คืน NULL แม้ตัวเดียว → ทั้ง predicate เป็น unknown → ผลได้ 0 แถวเงียบ ๆ (ไม่ใช่ว่าไม่มี orphan). SELECT-preview ที่ตรงเงื่อนไขเป๊ะก็ "0" เหมือนกัน จึงหลอกว่าปลอดภัย. correct move: อย่า commit/อย่าเชื่อ 0 — เขียนใหม่ด้วย NOT EXISTS (หรือ NOT IN + กรอง IS NOT NULL ใน subquery) แล้ว SELECT-preview ยืนยันจำนวน orphan จริงก่อน ค่อยลบใน 1 transaction.
</details>

### `python-coach`

คืนวันศุกร์ ก่อนปิดรอบส่งข้อมูล QC เข้าระบบกลางเที่ยงคืน คุณเขียนสคริปต์ Python รวมค่าควบคุมคุณภาพจากหลายเครื่อง แล้วต้องส่ง "ค่ากลาง (median)" ของแต่ละ analyte เรียงตามลำดับเวลาที่บันทึก โค้ดส่วนหัวใจคือ:

```
readings = collect_from_machines()        # list ของ float
ordered = readings.sort()                  # อยากได้ลิสต์ที่เรียงแล้ว
mid = ordered[len(ordered)//2]
submit(mid)
```

ตอนรันกับชุดทดสอบเล็ก ๆ มันเคยผ่าน คุณเลยมั่นใจ แต่คืนนี้มันโยน error ที่บรรทัด `ordered[...]` รุ่นพี่เดินมาดูแล้วบอกว่า "อ๋อ ลิสต์มันว่างน่ะ บางเครื่องคืน list เปล่ามา เพิ่ม `if not ordered:` ข้ามไปก็จบ แล้วรีบส่งเถอะ ใกล้เที่ยงคืนแล้ว" ดูสมเหตุสมผลมาก เพราะ error คือ index ลิสต์และคุณรู้ว่าบางเครื่องเงียบจริง ๆ

### `data-project-survival`

รุ่นน้องในแล็บส่งโมเดลทำนาย "ผู้ป่วยในที่จะเกิดภาวะติดเชื้อในกระแสเลือดภายใน 48 ชม." มาให้คุณรีวิวก่อนเสนอผู้บริหารพรุ่งนี้ ข้อมูล 8,000 ราย event จริงแค่ 6% (imbalance หนัก) เขาเล่าขั้นตอนอย่างภูมิใจว่า ทำความสะอาดข้อมูลครบ → เติม missing ด้วย median → standardize ทุก feature → ใช้ SMOTE สร้าง minority ให้สมดุล → แล้วค่อยแบ่ง train/test 80/20 → เทรน gradient boosting → ได้ AUROC 0.97, recall 0.94 บน test set. เขาชี้ว่า 5-fold CV ก็นิ่งมาก variance ต่ำทุก fold และ feature ที่สำคัญที่สุดคือ "ระดับ lactate วันที่ 2 ของการนอน รพ." ซึ่งสอดคล้องเป๊ะกับเวชศาสตร์ที่รู้กันว่า lactate สูง = แย่ ตัวเลขสวย หลักการแพทย์ก็เข้าทาง ทุกคนในห้องพยักหน้า เหลือแค่คุณเซ็นรับ คุณจะเซ็นไหม และจะพูดอะไร

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก = Data leakage (fit/resample/feature ก่อน split). กับดักจริงคือ SMOTE ทำ "ก่อน" แยก test → sample สังเคราะห์รั่วเข้า test ทำให้ AUROC สวยปลอม; ซ้ำด้วย "ระยะนอนวันที่ 2" ที่เป็น target-leak (รู้ได้หลังเกิด event แล้ว). Move: เลิกเชื่อเลข, รื้อ pipeline ให้ SMOTE+scaler+feature-select fit เฉพาะ train fold หลัง split, ตัด feature รู้อนาคตทิ้ง, validate ข้ามช่วงเวลา/วอร์ด แล้ววัดใหม่ — gap ใหญ่จาก baseline = ธงแดง ไม่ใช่ความเก่ง.
</details>

### `optimization-judgment`

แล็บกลางของโรงพยาบาลแห่งหนึ่งต้องจัดเวรนักเทคนิคการแพทย์ 7 คนลง 3 กะต่อวัน (เช้า/บ่าย/ดึก) ตลอดสัปดาห์ เป้าหมายคือลดต้นทุนค่าล่วงเวลารวมให้ต่ำสุด หัวหน้าแล็บส่งโมเดลให้คุณตรวจ เธอเขียน decision variable เป็น x[คน,วัน,กะ] ∈ {0,1}, objective = min ผลรวมค่ากะ, และใส่ constraint ครบถ้วน คือ (1) แต่ละกะมีคนอย่างน้อย 2 คน (2) แต่ละคนทำไม่เกิน 5 กะ/สัปดาห์ (3) ห้ามคนเดียวกันทำ 2 กะในวันเดียว เธอรันด้วย MIP solver ได้ผล optimal ต้นทุน 41,000 บาท ลดจากตารางเดิม 18% ทุก constraint ที่เขียนไว้ผ่านหมด ไม่มี infeasible หัวหน้าจะเซ็นอนุมัติใช้สัปดาห์หน้าทันที เพราะ "MIP รับประกัน optimal และเงื่อนไขครบแล้ว" ในแล็บนี้มีเพียง 3 คนที่ผ่านการรับรองให้ตรวจปล่อยผลธนาคารเลือด และนโยบายห้ามทำกะดึกติดกันเกิน 2 คืน คุณควรอนุมัติตามนี้หรือไม่ และเพราะอะไร

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: ลืมเขียน constraint จริง (ที่นี่คือ "ครบทุกกะต้องมีคนรับรองผล + พักหลังดึก") → LP/MIP คืน optimal สวยแต่ใช้จริงไม่ได้. ท่าถูก: ไล่ constraint จากโจทย์คำต่อคำก่อน solve — ค่าใช้จ่ายต่ำสุดที่ละเมิดเงื่อนไขที่ไม่ได้เขียน = ไม่ใช่คำตอบ ต้องเพิ่ม coverage/competency/rest constraint แล้ว solve ใหม่ (ค่าจะสูงกว่าแต่ feasible จริง)
</details>

### `content-creator-judgment`

เพจ "เล่าเรื่องแล็บ" ของคุณ (คนติดตามหลักคือ นศ. เทคนิคการแพทย์ + จนท.แล็บ ราว 8 พันคน) กำลังเงียบมา 3 สัปดาห์ ยอดดูตก. คืนนี้มีคลิปไวรัลของอินฟลูฯ สายสุขภาพรายใหญ่ "ตรวจเลือดบอกอะไรได้บ้าง" พุ่งทะลุ 4 ล้านวิว มีคนทำตามแล้วเป็นสิบเพจในวันเดียว แฮชแท็กกำลังติดเทรนด์ คอมเมนต์ถามกันรัวๆ. ทีมงานเร่งว่า "ต้องรีบลงตอนนี้ก่อนกระแสหาย ทำคลิปแบบเดียวกันเป๊ะ ฟอร์แมตเดียวกัน เพลงเดียวกัน อัลกอกำลังดันแฮชแท็กนี้ ยังไงก็ติด reach แน่ ของเราข้อมูลแน่นกว่าด้วยซ้ำ." คุณว่างพอตัดต่อได้คืนนี้เลย และหัวข้อนี้ตรงสายความรู้แล็บของคุณพอดี. คำถาม: คุณจะลงคลิป "ตรวจเลือดบอกอะไรได้บ้าง" ฟอร์แมตเดียวกับที่กำลังไวรัลคืนนี้เลยไหม ถ้าไม่ แล้วตัดสินใจยังไง — ให้เหตุผลที่ตัดสินจากหลักการ ไม่ใช่แค่ "รีบทำตามกระแส".

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: ตามเทรนด์ตอนอิ่มตัว (saturated) + ก๊อปฟอร์แมตคนอื่นเป๊ะ → เป็นรายที่ N ในวันเดียว ไม่มีเหตุผลให้คนเลือกเรา (reach ระยะสั้นหลอกตา). ท่าถูก: อย่าก๊อปฟอร์แมตทันที — หา angle ที่คนอื่นยังไม่ทำและตรงคนดูเดิม เช่น "อินฟลูฯ คลิปนั้นเข้าใจผิด/ขายเกินจริงตรงไหน—มุมคน in-lab จริง" หรือเคสจริงจากแล็บ; ถ้าหา angle เฉพาะตัวไม่ได้ = ข้าม.
</details>

### `photography-judgment`

อาจารย์ส่งงานด่วน: พรุ่งนี้ต้องใช้ภาพสไลด์เลือดในสไลด์พรีเซนต์งานประชุมวิชาการ ภาพหนึ่งใบเพื่อ "สื่อให้หมอในห้องเห็นทันทีว่าเซลล์ผิดปกติตัวที่สงสัยหน้าตาเป็นยังไง" คุณนั่งหน้ากล้องจุลทรรศน์ที่มีกล้องติดมา ตั้งใจทำให้เนียนที่สุด: เปิด RAW, ตั้ง WB ให้ขาวจริงเป๊ะ, spot meter เฉพาะ field, ใส่ขาตั้ง+รีโมทกันสั่น, ดัน ISO ต่ำสุด, แล้วเลือกกำลังขยายสูงสุด (100x oil) เพราะคิดว่า "ยิ่งขยายมาก ยิ่งเห็นรายละเอียดเซลล์ชัด = ภาพดีสุด" คุณถ่ายรัวหลายช็อต ได้ภาพที่คมกริบ สีตรง ไม่ไหวเลย เซลล์เป้าหมายอยู่กลางเฟรมพอดี เพื่อนชมว่าเทคนิคเป๊ะทุกอย่าง พร้อมส่งเข้าสไลด์เลย คุณกำลังจะ export ภาพนี้ คำถาม: ภาพนี้พร้อมใช้จริงไหม ถ้าไม่ ปัญหาหลักอยู่ตรงไหน และต้องแก้อะไรก่อนถ่ายใหม่?

<details><summary>👉 เฉลยกับดัก</summary>

กับดัก: ยกกล้องก่อนตั้งโจทย์ — เทคนิคเป๊ะแต่เลือก setup ผิดเพราะไม่ถามก่อนว่า "ภาพนี้จะสื่ออะไรให้ใคร". โจทย์คือให้ผู้ชมเห็นเซลล์ผิดปกติ "ในบริบท" → ต้องเลือกกำลังขยายให้เห็น morphology เทียบกับเซลล์รอบข้าง (มัก 40–60x หรือเก็บ field กว้างพอ) + เซลล์เป้าวางตาม rule of thirds ไม่ใช่กลางเป๊ะ; 100x oil กลางเฟรมตัด context ทิ้ง สื่อไม่ได้แม้ภาพจะคม. แก้: ตั้งโจทย์ก่อน → เลือกกำลังขยาย/องค์ประกอบให้ตรงสิ่งที่จะสื่อ แล้วค่อยใช้เทคนิคกันสั่น/WB/RAW (และ de-identify ก่อนเผยแพร่).
</details>
