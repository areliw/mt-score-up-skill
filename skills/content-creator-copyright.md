# ลิขสิทธิ์ + ความปลอดภัยสื่อ สำหรับ MT ทำคอนเทนต์ให้ความรู้

ทำเพจ/ช่องสอนเรื่องแล็บ (ค่า CBC, อ่านผลตรวจ, สุขภาพ) แล้วติดตรง *"ใช้เพลง TikTok ได้ไหม · เอาอินโฟกราฟิกฝรั่งมาแปะได้ไหม · YouTube จะเตะเรื่องลิขสิทธิ์ไหม"* → โค้ชนี้ช่วยหา **"เส้นอยู่ตรงไหน"** สำหรับคอนเทนต์การศึกษา — คุณรู้อยู่แล้วว่า "ลิขสิทธิ์มีจริง" แต่ไม่รู้ว่าเส้นแบ่ง *ใช้ได้/ผิด* อยู่ตรงไหน

> **กฎ #1 (จำก่อนอย่างอื่น):** **"ให้เครดิต ≠ ได้รับอนุญาต"** — ลอกงานคนอื่นมาทั้งดวงแล้วเขียนเครดิต **ยังผิดลิขสิทธิ์อยู่ดี**. เครดิตแก้เรื่อง *ลอกงานโดยไม่อ้างที่มา (plagiarism)* — ไม่ได้แก้เรื่อง *license*. สองเรื่องคนละอันกัน.
> **กฎ #2:** **"ปลอดภัยบนแพลตฟอร์ม A ≠ ปลอดภัยทุกที่"** — เพลงจากคลังในตัว TikTok เอาไป reupload YouTube = ไม่ได้ครอบ โดน ContentID. license/คลังเพลงผูกกับแพลตฟอร์มที่หยิบมา.
> **กฎ #3 (สาย MT เท่านั้น):** **"ไม่มีชื่อ/HN ≠ ไม่ระบุตัวตน"** — เคสหายาก + วัน + ชื่อ รพ./แผนก + ภาพจริง = ถอดกลับเป็นคนได้ (ดู Fork 5).
> คอนเทนต์การแพทย์ → คู่กับ `content-creator-judgment` (เลือกหัวข้อ) · `phi-data-handling` + `mt-law-ethics-judgment` (เคสคนไข้/จรรยาบรรณ) · `digital-judgment` · `source-credibility-judgment` (อ้างแหล่งให้ถูก)

## ใช้เมื่อ
- กำลังจะใส่ **เพลง/เสียง** ในคลิป แล้วไม่รู้ว่าเพลงไหนปลอดภัย
- อยากเอา **อินโฟกราฟิก/ชาร์ต/ภาพ** ของคนอื่น (WHO, CDC, ตำรา, เพจฝรั่ง) มาใช้ — ลอกได้แค่ไหน ต้องวาดใหม่ไหม
- กลัว **YouTube/TikTok/Facebook เตะ** เรื่องลิขสิทธิ์ — อยากรู้ว่าระบบจับ/ลงโทษยังไง
- ทำ **เคสคนไข้/ผลแล็บจริง** เป็นคอนเทนต์ — ปลอดภัยเรื่อง PII แค่ไหน

## วิธีใช้
วาง skill นี้ + เล่าว่าจะใช้อะไร (เพลงชื่อ…/ภาพจาก…/เคสแบบ…) + ลงแพลตฟอร์มไหน + มีสปอนเซอร์/ขายของไหม → AI ชี้ว่า **ใช้ได้/ไม่ได้ เพราะอะไร + ทางปลอดภัยแทน**

## วิธีตัดสินใจ (AI: ทำตามนี้) — forks

### Fork 1 — เลือกเพลง/เสียง: ปลอดภัยไล่จากมากไปน้อย
เรียง 4 ชั้น (ชั้นบน = เสี่ยงน้อยสุด):
1. **คลังในตัวแพลตฟอร์ม** — YouTube Audio Library · TikTok Commercial Music Library (บัญชี Business/สายองค์กร) · Facebook Sound Collection → ปลอดภัย **เฉพาะบนแพลตฟอร์มที่หยิบมา**. ⚠️ โหลดจากคลัง TikTok ไปลง YouTube = หลุดการคุ้มครอง โดน ContentID
2. **Royalty-free / Creative Commons จริง** — ต้อง **อ่าน flavor ของ license**:
   - **CC BY** = ใช้ได้ ต้องให้เครดิตตามที่เขากำหนด
   - **CC BY-NC** = **ห้ามใช้เชิงพาณิชย์** — เกณฑ์จริงคือ "ใช้เพื่อ *ผลประโยชน์ทางการค้า/ได้เงินเป็นหลัก*"; เพจที่มีโฆษณา/ขายคอร์ส/รับสปอนเซอร์/ติดแบรนด์ → **ให้ถือว่าพาณิชย์/เสี่ยงสูงไว้ก่อน** (ปลอดภัยกว่าเดาเข้าข้างตัวเอง)
   - **CC BY-ND** = **ห้ามดัดแปลง** — และ **การเอาเพลงไปใส่เป็นดนตรีประกอบวิดีโอ (sync) ก็นับเป็นการดัดแปลง** ตามการตีความของ Creative Commons → **เพลง ND ไม่ควรใช้เป็น BGM คลิปเลย** เว้นแต่ได้รับอนุญาตแยกต่างหาก
   - เก็บหลักฐาน: ลิงก์ license + ชื่อเพลง + ผู้แต่ง (เผื่อโดนเคลมจะ dispute ได้)
3. **เพลงซื้อ license** (Epidemic Sound / Artlist ฯลฯ) — license ผูกกับ **บัญชี/ช่องที่ subscribe**; ต้อง **whitelist ช่องตัวเองในแดชบอร์ดผู้ให้บริการ** ไม่งั้น ContentID ยัง flag (เพราะคนอื่นก็ใช้เพลงเดียวกัน) · ยกเลิก sub แล้วคลิปเก่าคุ้มครองต่อไหม → อ่านเงื่อนไข
4. **เพลงชาร์ต / เพลงดัง / เสียงจากแอปคาราโอเกะ/แอปแต่งเสียง** → ❌ เกือบชัวร์โดน claim / มิวต์เสียง / บล็อกบางประเทศ. **อย่าเชื่อว่า "แค่ท่อนสั้น 10 วิ" หรือ "ให้เครดิตแล้ว" จะรอด**

**กฎหัวใจ Fork 1:** ระบบแมตช์เพลงด้วย **ลายเซ็นเสียง (audio fingerprint)** — มัน **ไม่อ่านแคปชั่น**. เขียนเครดิตใต้คลิปไม่ช่วยกัน ContentID.

### Fork 2 — เอาอินโฟกราฟิก/ภาพคนอื่นมาใช้: เส้นอยู่ตรงไหน
ถามเป็นชั้น:
1. **สิ่งที่อยากได้คือ "ข้อมูล" หรือ "งานออกแบบ"?**
   - **ข้อเท็จจริง/ตัวเลข** (ค่า ref range, กลไก, สถิติ, ขั้นตอน) → **ตัวข้อเท็จจริงไม่มีลิขสิทธิ์** — *แต่* ตาราง/ฐานข้อมูล/ชุดค่าอ้างอิงที่เขา *รวบรวมมาทั้งชุด* อาจมีสิทธิในฐานะงานรวบรวม + ติดเงื่อนไขเว็บ (ToS). ทางถูก = **ดึงเฉพาะข้อมูลเท่าที่จำเป็น → วาดใหม่ → verify → อ้างแหล่ง** ไม่ใช่ยกทั้งตารางมา
   - **การจัดวาง/สี/ไอคอน/เลย์เอาต์/ภาพวาด** → **มีลิขสิทธิ์** (คือ expression) ลอก *ดีไซน์* ไม่ได้
2. **ปลอดภัยสุด = วาดใหม่เอง (redraw)** — เอาเฉพาะข้อมูลมาทำกราฟ/การ์ดของตัวเอง + อ้างอิงแหล่งข้อมูล (ใช้ `source-credibility-judgment` เลือกแหล่งให้ถูก). นี่คือทางที่รุ่นพี่แนะนำเสมอ
3. **จะใช้ภาพต้นฉบับตรงๆ** → ต้องมีอย่างใดอย่างหนึ่ง: ภาพเป็น **public domain** · ภาพมี **license เปิด** (CC — เช็ค flavor เหมือน Fork 1) · หรือ **ขออนุญาตเจ้าของ**. **เครดิตอย่างเดียวไม่พอ** (กฎ #1)
4. **อ้าง "เพื่อการศึกษา"** (ข้อยกเว้นการละเมิดลิขสิทธิ์ตาม พ.ร.บ.ลิขสิทธิ์ฯ — ⚠️ ยืนยันเลขมาตรา/ฉบับแก้ไขล่าสุดกับนักกฎหมาย) ไม่ใช่ยาครอบจักรวาล. ⚠️ **ข้อยกเว้นนี้เล็งไปที่การเรียนการสอน/ห้องเรียนวงแคบ — โพสต์ลงเพจ/TikTok/FB สาธารณะ ไม่เข้าข้อยกเว้นโดยอัตโนมัติ**. ยิ่งเข้า 3 ข้อนี้ยิ่ง **หลุด** ข้อยกเว้น:
   - ใช้ **ทั้งงาน/ส่วนสำคัญ** (แคปชาร์ตทั้งใบ)
   - ใช้ **เชิงพาณิชย์** (เพจมีสปอนเซอร์/ขายของ)
   - **แทนที่ต้นฉบับ / กระทบการหาประโยชน์ปกติ** ของเจ้าของ

**กฎหัวใจ Fork 2:** *"Fair Use / การใช้ที่เป็นธรรม" ไม่ใช่สวิตช์เปิด-ปิด* — เป็นการชั่งน้ำหนักหลายปัจจัย, และไทยตีความแคบกว่าที่หลายคนคิด. ทำคอนเทนต์การศึกษาไม่ได้แปลว่าหยิบทุกอย่างมาฟรี.

### Fork 3 — ตราสัญลักษณ์ · ฟอนต์ · ชุดอีโมจิ
- **โลโก้/ตราองค์กร** (WHO, CDC, รพ., สมาคมวิชาชีพ) = เครื่องหมายการค้า/ตราสัญลักษณ์ — เอามาใส่จน **ดูเหมือนได้รับการรับรอง/สังกัด** = เสี่ยงทั้งลิขสิทธิ์ + เครื่องหมายการค้า + **ทำให้เข้าใจผิด** (หนักกว่าลิขสิทธิ์ธรรมดา เพราะหลอกคนดู)
- **ฟอนต์** มี license — ฟอนต์เถื่อน/ฟอนต์ก๊อปใช้เชิงพาณิชย์ไม่ได้. ใช้ฟอนต์ฟรีที่อนุญาตพาณิชย์ (เช่น Google Fonts, ฟอนต์ที่ระบุ "ใช้ฟรีเชิงพาณิชย์")
- **ชุดอีโมจิ** — อีโมจิ Apple/LINE มีเงื่อนไขผูกกับแพลตฟอร์มตัวเอง (เอาไปแปะนอกแพลตฟอร์มไม่ได้ตามสัญญา). ใช้ชุดโอเพนซอร์ส เช่น **Twemoji (CC BY)** / **Noto Emoji** + ให้เครดิตตามเงื่อนไข

### Fork 4 — แพลตฟอร์มไหนจับ/ลงโทษยังไง (safe zone จริง)
- **YouTube** — แยกให้ออก 2 อย่าง:
  - **Content ID claim** = ระบบแมตช์อัตโนมัติ → เจ้าของเลือกผลได้: **เปลี่ยนทางรายได้ / มิวต์ / บล็อกคลิป (อาจทั่วโลก ไม่ใช่แค่บางประเทศ)** — *claim เดียวไม่ทำช่องตาย* และจัดการได้ (ตัดเพลง/replace/dispute **ถ้ามีสิทธิจริง**) · ⚠️ **dispute มั่วๆ ทั้งที่ไม่มีสิทธิ อาจบานเป็น takedown → strike**
  - **Copyright strike** = เจ้าของยื่นร้องเรียนจริง → **อันตราย**: สะสม 3 strikes ช่องโดนลบ (แต่ละ strike อายุ ~90 วัน / เคลียร์ได้หลังเรียน Copyright School)
  - → เจอ *claim* ตั้งสติจัดการได้ (แต่คลิปอาจถูกบล็อก); เจอ *strike* ต้องจัดการจริงจัง
- **TikTok** — บัญชีทั่วไปมีคลังเพลงดังเยอะ **แต่บัญชี Business เห็นเฉพาะ Commercial Music Library**. ทำเพจความรู้แบบมีแบรนด์/ขายคอร์ส → ควรใช้ Commercial library ตั้งแต่แรก ไม่งั้นวันหนึ่งสิทธิเพลงหมด **เพลงถูกถอด/คลิปโดนมิวต์**
- **Facebook / IG** — มี Rights Manager + Sound Collection; เพลงเชิงพาณิชย์ในวิดีโอยาวเสี่ยงโดนมิวต์ · **รีโพสต์ภาพ/คลิปคนอื่น** (โหลดมาโพสต์ใหม่) = ทำซ้ำ แม้แชร์ในกลุ่ม — ต่างจากปุ่ม "แชร์" ที่ลิงก์กลับต้นทาง
- **กฎข้ามแพลตฟอร์ม:** ปลอดภัยบนที่นึง **ไม่ยกไปอีกที่** (กฎ #2)

### Fork 5 — PII / เคสคนไข้ (แลนด์ไมน์เฉพาะสาย MT)
- **"ตัดชื่อ/HN ออกแล้ว ≠ ปลอดภัย"** — ตัวระบุตัวตน **รวมกันชี้ตัวได้ (re-identification)**: เคสหายาก + วันที่ + ชื่อ รพ./แผนก + ภาพสไลด์/ผลจริง = คนในนั้นเดาออกว่าใคร
- **เกณฑ์ตัดสิน (re-ID test):** *ถ้าคนใน รพ./แผนกนั้นอ่านแล้วเดาได้ว่าเป็นเคสไหน/ใคร = ยังเป็นข้อมูลส่วนบุคคล* — และเป็น **"ข้อมูลสุขภาพ" = ข้อมูลอ่อนไหว** → เปิดเผยสาธารณะโดยไม่มีฐานทางกฎหมาย/ความยินยอมโดยชัดแจ้ง + มาตรการคุ้มครอง **เสี่ยงผิด PDPA + จรรยาบรรณวิชาชีพ**
- **ทางปลอดภัย (ไล่จากดีสุด):** ใช้เคส **สมมุติ/สังเคราะห์** → ถ้าจำเป็นต้องใช้เคสจริง: **ถอดตัวระบุทุกชั้น** (วัน/สถานที่/อายุเป๊ะ/เพศถ้าหายาก/ภาพจริง) **+ ขอความยินยอมโดยชัดแจ้งเฉพาะวัตถุประสงค์** **+ ขออนุญาต รพ./เจ้าของข้อมูล (data controller) ก่อน** — เพราะผล/ภาพ/สไลด์ในระบบเป็น *เวชระเบียน/ทรัพย์สินของ รพ.* : **ความยินยอมจากคนไข้อย่างเดียวไม่พอ** ที่จะเอาเวชระเบียนของ รพ. มาลงสาธารณะ + ยังผูกหน้าที่รักษาความลับผู้ป่วยด้วย
- **จุดพลาดที่มองข้าม:** ภาพถ่ายจอ LIS / บาร์โค้ด / ป้ายชื่อ / ฉลากหลอด / มุมจอ อาจ **ติดข้อมูลคนไข้หรือชื่อ รพ.** มาโดยไม่ตั้งใจ — ซูมดูทุกพิกเซลก่อนโพสต์
- เชื่อม `phi-data-handling` (de-identify ยังไงให้ครบ) + `mt-law-ethics-judgment` (ขอบเขตวิชาชีพ/ยินยอม)

### Fork 6 — สื่อสร้างด้วย AI (ภาพ/วิดีโอ/เพลง gen): เปิดเผย · ตรงโจทย์ · ระวังลิขสิทธิ์ต้นทาง + ความถูกต้อง
> **จุดยืน: pro-AI + pro-disclose — ไม่ใช่ต้าน AI.** ใช้ AI ได้เต็มที่ในงานที่เหมาะ; ประเด็นไม่ใช่ "ห้ามใช้" แต่คือ **ใช้แล้วบอกตามตรง + ใช้ให้ตรงงาน + verify ให้ถูก**. เส้นแบ่งอยู่ที่ *บริบท* (ผู้ชมจะเข้าใจผิดไหม · งานต้องถือสิทธิ์/ฝีมือไหม · ถูกต้องไหม) ไม่ใช่ที่ตัวเทคโนโลยี.

เพจ/องค์กรวิชาชีพใช้สื่อ AI-generated (โดยเฉพาะ "ภาพแทนวิชาชีพ" / งานประกวด) — ตัดสินเป็นชั้น:
1. 🔑 **เปิดเผยว่าใช้ AI** เมื่อสื่อเป็น PR ระดับองค์กร/ภาพแทนวิชาชีพ หรืองานที่ผู้ชมจะเข้าใจว่าเป็นของจริง/ฝีมือคน — วิชาชีพ MT ยึดความถูกต้อง/ความจริง → ไม่ระบุ = เสี่ยงความน่าเชื่อถือ (ใส่ป้าย "AI-generated / AI-assisted")
2. 🔑 **ตรงโจทย์ไหม:** ส่งภาพ AI เข้าประกวดหมวด "ภาพวาด/ภาพถ่าย" = ผิดโจทย์ (สมควรปรับฟาวล์) · จะเปิดรับ AI → ตั้ง **หมวดแยก + บังคับ disclose** ในกติกาให้ชัดตั้งแต่แรก · อย่าตัดสินด้วยยอดไลก์/แชร์แทนการตรงเกณฑ์
3. ⚠️ **ลิขสิทธิ์ต้นทาง (training data):** output อาจดึง/ดัดแปลงงานผู้อื่นที่โมเดลเทรนมา — **"คิด prompt เอง ≠ เป็นเจ้าของสิทธิ์สะอาด"** · ยิ่งได้ภาพคล้ายตัวละคร/มาสคอต/แบรนด์ดัง = เสี่ยงลิขสิทธิ์ + เครื่องหมายการค้าปลายทาง (โยง Fork 3) โดยเฉพาะงาน **โลโก้/มาสคอต/เชิงพาณิชย์**
4. ⚠️ **AI-gen ล้วน = ถือสิทธิ์ยาก:** ความคุ้มครองลิขสิทธิ์ *ของตัวงานเอง* อาจจำกัด/ไม่ชัด (ต่างตามเขตอำนาจ — verify) → มาสคอต/แบรนด์ที่อยากถือสิทธิ์เอง อย่าพึ่ง AI-gen ล้วน
5. 🩸 **(สาย MT) ความถูกต้องทางวิชาการ:** ภาพ AI ของกายวิภาค/เซลล์/ขั้นตอนแล็บ **มักผิดรายละเอียด** → คอนเทนต์ให้ความรู้ต้อง verify กับแหล่งจริงก่อนเผยแพร่ ไม่งั้นสอนผิด (โยง `source-credibility-judgment`, `anti-hallucination`)
- หลัก: **AI ช่วยได้ในงานอินโฟกราฟิก/ประกอบ non-commercial ที่ verify แล้ว + เปิดเผย** · เลี่ยงในงานประกวด "ฝีมือ" · มาสคอต/แบรนด์ที่ต้องถือสิทธิ์ · งานที่อ้างเป็นภาพจริง/เหตุการณ์จริง

## กับดัก (Anti-patterns) — เคสที่ "ชาวสวน" โดนเตะมาแล้ว
> กฎ #1/#2/#3 อยู่ด้านบนแล้ว. ด้านล่างคือกับดักที่ forks ไม่ครอบ + เคสจริงที่คนพลาดบ่อย:
- **ก๊อปชุดฟอนต์/อีโมจิแบรนด์มาทั้งเซ็ต** (emoji-font knockoff) → ละเมิด license ฟอนต์/อีโมจิ. ใช้ชุดโอเพนซอร์ส (Twemoji/Noto/Google Fonts) + เครดิตตามเงื่อนไข
- **ลูปเพลงจากแอปคาราโอเกะ/แอปแต่งเสียง** → เสียงในแอปพวกนั้นมัก license *ให้ใช้ในแอปเท่านั้น* ไม่ครอบการอัปโหลดเป็นคอนเทนต์สาธารณะ → โดน Content ID
- **แคปชาร์ต WHO/CDC ทั้งใบมาลง (ไม่ให้เครดิต — หรือให้เครดิตแต่ลอกทั้งดวง)** → ทั้งคู่ผิด. เครดิตไม่ใช่ใบอนุญาต; **วาดใหม่จากข้อมูล + อ้างแหล่ง** คือทางถูก
- **เชื่อว่า "ท่อนสั้น/กี่วินาทีก็ได้ = ปลอดภัย"** → **ไม่มีกฎ "จำนวนวินาทีปลอดภัย"** ที่เป็นเส้นตายตัว; Content ID จับได้แม้ท่อนสั้น
- **"เจอในเน็ต/Google Images = ฟรี"** → ผลค้นหา **ไม่ใช่คลังภาพฟรี**. ต้องกรอง license (CC / public domain) หรือขออนุญาตทุกครั้ง
- **ให้เครดิตแล้วชิลล์** → เครดิตแก้ plagiarism ไม่แก้ copyright (กฎ #1 ย้ำอีกครั้งเพราะคนพลาดข้อนี้มากสุด)
- **เอา license แพลตฟอร์มเดียวไป reupload ข้ามแพลตฟอร์ม** (กฎ #2)
- **เอาโลโก้องค์กร/สมาคมมาแปะให้ดูน่าเชื่อ** → เข้าใจผิดว่าได้รับการรับรอง = เสี่ยงเครื่องหมายการค้า + หลอกลวง (หนักกว่าลิขสิทธิ์)
- **(สาย MT) โพสต์เคส "de-identified แล้ว" แต่ยังเดาตัวได้** → ยังผิด PDPA (Fork 5). ตรวจด้วยเกณฑ์ "คนในแผนกเดาออกไหม"
- **(สาย MT) รับรีวิว/โฆษณาชุดตรวจ-IVD ทั้งที่ถือใบ ทนพ.** → เสี่ยงโทษวิชาชีพ + กฎโฆษณาเครื่องมือแพทย์/อย. (ดู `content-creator-judgment` + `mt-law-ethics-judgment`)
- **(AI) ส่งภาพ gen เข้าประกวดหมวดภาพวาด/ภาพถ่าย หรือใช้เป็นมาสคอตแบรนด์ โดยไม่ disclose/ไม่เช็คลิขสิทธิ์ต้นทาง** → ผิดโจทย์ + เสี่ยงลอกดีไซน์ตัวละครดัง (ดู Fork 6)

## ช่องสำหรับผู้เชี่ยวชาญเติม
> เติมเคสจริงที่เจอเอง เช่น:
> - *"คลิปผมโดน Content ID claim เพราะ… จัดการโดย… (trim/replace/dispute)"*
> - *"อินโฟกราฟิกที่ผมวาดใหม่จากข้อมูล WHO ทำแบบนี้… เพจไม่โดนอะไรเลย"*
> - *"เคสคนไข้ที่คิดว่า de-identify แล้ว แต่เพื่อนในแผนกทักว่าเดาออก เพราะ…"*
> - *"เพลง/ฟอนต์/คลังภาพฟรีที่ผมใช้จริงแล้วปลอดภัย: … (พร้อมเงื่อนไข license)"*
