# ล้างข้อมูลรกๆ ก่อนวิเคราะห์

ตัวช่วยตัดสินใจตอนได้ข้อมูล lab/วิจัยรกๆ (export จาก LIS, Excel กรอกมือ) — เน้น "ล้างอะไรก่อน-หลัง + กับดักที่ทำข้อมูลเสียถาวร" ไม่ใช่สอน pandas

> **กฎ #1:** **ดูข้อมูลดิบด้วยตา + นับ ก่อนเขียนกฎล้างเสมอ** — เปิดดู ~20 แถวจริง + นับ unique/missing/ช่วงค่า ก่อน. ล้างก่อนดู = ล้างผิดทั้งชุดโดยไม่รู้
> **กับดัก #1 (ขั้น hard):** **ล้างทับของเดิม (in-place) โดยไม่เก็บ raw** → กฎผิด = กู้ไม่ได้ + ไม่รู้ว่าเปลี่ยนอะไรไป. เก็บ raw แยก + log ทุก transformation (reproduce ได้) เสมอ

> **verify-first:** decision-support ไม่ใช่คำตอบสุดท้าย — เช็คข้อเท็จจริงก่อนเชื่อ (คู่กับ `anti-hallucination`) · ตรวจผลล้างกับข้อมูลดิบเสมอ

## ใช้เมื่อ
- ได้ CSV/Excel รกๆ จะวิเคราะห์/ทำ dashboard แต่ข้อมูลไม่สะอาด
- date format ปนกัน, หน่วยปน, ชื่อ test สะกดมั่ว, ค่า missing/blank, แถวซ้ำ
- ไม่แน่ใจจะ drop หรือ impute / ใช้ regex หรือ AI ล้าง

## วิธีใช้
วาง skill นี้ + ตัวอย่างข้อมูลดิบ (โครงคอลัมน์ + 10–20 แถว, **de-identified**) → AI ช่วยจัดลำดับปัญหา + เลือกวิธีล้าง + เตือนกับดัก แล้วชี้ให้คุณ verify ผลกับ raw เอง

## วิธีตัดสินใจ (AI: ทำตามนี้)

### Fork 1 — จัดลำดับปัญหา (อย่าสุ่มแก้)
**structural ก่อน** (ชื่อคอลัมน์/ชนิดข้อมูล/encoding/แถว-คอลัมน์เพี้ยน) → **ค่า** (date/หน่วย/สะกด) → **missing** → **duplicate** → **outlier** สุดท้าย

### Fork 2 — date = นรกอันดับ 1
- พ.ศ. vs ค.ศ., d/m/y vs m/d/y, Excel serial number, ข้อความปนเลข → แปลงเป็น **ISO (YYYY-MM-DD)** + **sanity check ช่วงปี** (เจอ 2110 = พ.ศ.ไม่แปลง; เจอ 1900 = Excel ว่าง)
- ระวัง Excel autoconvert วันที่ตั้งแต่ตอน export (เชื่อม `spreadsheet-judgment`)

### Fork 3 — regex หรือ AI
- **เริ่ม regex** สำหรับ pattern ชัด (รหัส/วันที่/หน่วย/HN) — เร็ว, ตรวจสอบได้, ฟรี, deterministic
- **ใช้ AI เฉพาะ low-confidence edge case** (ชื่อ test สะกดหลายแบบ, free-text comment) → แล้ว **verify ผล** (เชื่อม `regex-vs-llm-structured-text` หลักการ)
- อย่าให้ AI ล้างทั้งชุดแบบ blackbox โดยไม่สุ่มตรวจ

### Fork 4 — missing values
- แยก **MCAR / MAR / MNAR** ก่อนตัดสิน — สุ่มหาย vs หายอย่างมีระบบ (เชื่อม `data-project-survival`, `ml-judgment`)
- **blank ≠ 0** (glucose ว่าง ≠ glucose 0; "ไม่ได้ตรวจ" ≠ "ตรวจแล้วเป็นลบ")
- drop เมื่อหายน้อย+สุ่ม; impute อย่างระวัง (อย่าเดาค่าแล็บมั่ว) + บันทึกว่า impute

### Fork 5 — duplicate / dedup
- **นิยาม "ซ้ำ" ให้ชัดก่อน**: same HN+date+test? หรือ re-run ที่ต้องเก็บ "อันล่าสุด"? — dedup ผิดนิยาม = ข้อมูลหายจริง
- เก็บหลักฐานว่าลบแถวไหนไป

### Fork 6 — unit / standardize
- หน่วยปน (mg/dL ↔ mmol/L) → แปลงด้วย factor ที่ถูก (อย่าเดา) + ระบุหน่วยเดียวทั้งคอลัมน์
- ชื่อ test/หน่วยงานไม่ standard → ทำ **mapping table** (canonical name) แล้ว map

## กับดัก (Anti-patterns)
- #1 ล้างทับ raw / ไม่ log transformation → กู้ไม่ได้, reproduce ไม่ได้ (กับดัก #1)
- #2 ไม่ดูข้อมูลดิบก่อน → เขียนกฎผิดทั้งชุด
- #3 date ไม่ sanity-check ช่วงปี → พ.ศ./ค.ศ./serial ปนเงียบ
- #4 ถือ blank = 0 → สถิติเพี้ยน
- #5 impute ค่าแล็บมั่วๆ โดยไม่ดู mechanism (MCAR/MAR/MNAR)
- #6 dedup ผิดนิยาม → ลบ re-run ที่ควรเก็บ / เก็บอันเก่า
- #7 แปลงหน่วยผิด factor → ค่าผิดทั้งคอลัมน์
- #8 ให้ AI ล้างทั้งชุดแบบ blackbox ไม่สุ่ม verify
- #9 ข้อมูลคนไข้จริง paste ขึ้น AI สาธารณะตอนขอให้ช่วยล้าง

## ช่องสำหรับผู้เชี่ยวชาญเติม
> - LIS/เครื่องที่ export มี quirk อะไรประจำ (date format, ชื่อ test, encoding ภาษาไทย)?
> - คอลัมน์ไหนที่ทีมคุณเจอ missing/ปนหน่วยบ่อย + กฎที่ใช้ตัดสิน drop/impute
> - นิยาม "ข้อมูลซ้ำ" ในชุดข้อมูลคุณคืออะไรกันแน่

NOTE: syntax การล้าง (pandas/regex/Power Query) → ถาม AI แยก/ดูคู่มือ; ทฤษฎี missing-data + วิธีทางสถิติลึก → ดูตำราสถิติ ไม่ใช่หน้าที่ของ skill นี้
