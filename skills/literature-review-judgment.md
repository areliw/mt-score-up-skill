# รีวิววรรณกรรมให้เป็นระบบ

วาง **กระบวนการ** รีวิวเปเปอร์ "ทั้งกอง" ให้ครบและทำซ้ำได้ — ตั้งคำถาม → ค้น → คัด → สังเคราะห์ → หา gap ไม่ใช่ค้นคำเดียวแล้วเขียนเลย

> **กฎข้อ 1:** ตั้ง **คำถาม + ขอบเขต + เกณฑ์ include/exclude ให้ชัดก่อนเริ่มค้น** — รีวิวคือ "กระบวนการที่ทำซ้ำได้" ไม่ใช่ "หาเปเปอร์ที่ถูกใจ". ลำดับถูก = แคบคำถาม (PICO) → ตั้งเกณฑ์ → ค้นหลายแหล่ง → คัด 2 ชั้น → สกัดลงตาราง → สังเคราะห์ theme/gap.
> **กับดักข้อ 1:** **ค้น Google Scholar คำเดียว เจอ 5 อันที่หนุนความคิดตัวเอง แล้วเขียน** = cherry-pick + ไม่ทำซ้ำ. ของจริง: หลายแหล่ง + boolean + คัดตามเกณฑ์ที่ตั้งไว้ก่อน + จด "ค้นวันไหน คำว่าอะไร" ทุกครั้ง.
> นี่คือชั้น **"รีวิวหลายเปเปอร์ (process)"** — ประเมิน/อ่านลึก **1 เปเปอร์** (เชื่อได้ไหม, sens/spec, หา gap) → `critical-appraisal-judgment` · กันอ้างมั่ว/citation ปลอม → `anti-hallucination` · ค้นเว็บลึกหลายแหล่ง → `deep-research`

## ใช้เมื่อ
- เริ่มทำ literature review / บทที่ 2 thesis / R2R / proposal — ต้องสำรวจเปเปอร์ทั้งกอง ไม่ใช่อ่านทีละอัน
- จะหา research gap ว่า "อะไรยังไม่มีใครทำ" ก่อนล็อกหัวข้อ
- ต้องสรุป "ที่ผ่านมาเขาทำอะไรกันบ้าง" ให้ครบ ไม่ตกประเด็นสำคัญ
- ใช้ AI ช่วยค้น/ย่อเปเปอร์ แต่กลัวมันแต่ง citation หรือสรุปเปเปอร์ที่ไม่ได้อ่าน
- งานต้อง **ทำซ้ำได้** (reproducible) — อาจารย์/reviewer ถามว่า "ค้นยังไง" ต้องตอบได้

## วิธีใช้
วาง skill นี้ + บอกคำถามวิจัย/หัวข้อคร่าวๆ → AI ช่วยแคบเป็น PICO, เสนอคำค้น + boolean + แหล่งที่ควรค้น, ตั้งเกณฑ์ include/exclude, ทำตารางสกัด, แล้วช่วยหา theme/gap. **ทุกเปเปอร์ที่ AI อ้าง = คุณต้องเปิดต้นฉบับจริงเอง**

## ขั้นตอน (AI: เดินตามลำดับ อย่าข้าม)

### 1 — แคบคำถาม + ขอบเขต ก่อนแตะ search box
- แปลงหัวข้อกว้างเป็น **PICO/ตัวแปรชัด**: ประชากร/ตัวอย่าง · วิธี/test ที่สนใจ · เทียบกับอะไร · ผลที่วัด.
  เช่น "AI ตรวจเลือดดีไหม" (กว้างเกิน) → "ML จำแนก thalassemia trait จาก CBC vs HPLC ในผู้ใหญ่ไทย" (ค้นได้จริง)
- คำถามแคบพอ = คำค้นชัด + เกณฑ์คัดง่าย. กว้างไป = เจอหมื่นเปเปอร์คัดไม่ไหว; แคบไป = เจอ 2 อัน

### 2 — ตั้งเกณฑ์ include/exclude **ก่อนค้น** (ห้ามตั้งตอนเจอ)
- ล็อกล่วงหน้า: ช่วงปี · ภาษา · ชนิดงาน (RCT / diagnostic-accuracy / review / case report) · ประชากร · มี full-text ไหม
- ⚠️ ตั้งเกณฑ์ "หลังเห็นผล" = เปิดช่องเลือกเฉพาะอันที่ถูกใจ (cherry-pick). เขียนเกณฑ์เป็นลายลักษณ์อักษรก่อน แล้วคัดตามนั้นแม้เจ็บใจ

### 3 — เลือกแหล่ง + วิธีค้น (อย่าใช้แหล่งเดียว)

| แหล่ง | ใช้เมื่อ | จุดเด่น / ข้อควรระวัง |
|---|---|---|
| **PubMed** | งาน clinical/biomedical, MT, diagnostics | คุม MeSH ได้แม่น; แต่ไม่ครอบ vendor/engineering |
| **Scopus / Web of Science** | ต้องการ coverage กว้าง + cited-by + นับ impact | ครอบสหสาขา; มักต้องสิทธิ์มหาลัย |
| **Google Scholar** | ตามรอย grey literature, วิทยานิพนธ์, snowball | กว้างสุด+ฟรี; แต่ noise เยอะ, คุณภาพปนกัน — ห้ามใช้เดี่ยว |

- **MeSH** (PubMed) = ค้นตามแนวคิด จับ synonym ให้อัตโนมัติ → recall สูง; **keyword** = จับคำใหม่/เฉพาะที่ MeSH ยังไม่มี → ใช้คู่กัน
- **Boolean:** `AND` แคบ (ทุกคำต้องมี) · `OR` ขยาย (รวม synonym เช่น "thalassemia OR thalassaemia") · `NOT` ตัด (ระวัง ตัด relevant ทิ้งโดยไม่ตั้งใจ)
- **อย่าลืม grey literature** (thesis, conference, preprint, registry, IFU) — เปเปอร์ที่ "ผลไม่ significant" มักไม่ได้ตีพิมพ์ → ค้นแต่ journal = ได้ภาพเอียง (publication bias)

### 4 — Screen 2 ชั้น (อย่าอ่าน full-text ทุกอันแต่แรก)
- **ชั้น 1 — title + abstract:** คัดเร็วตามเกณฑ์ข้อ 2 (เข้า/ไม่เข้า/สงสัย). เร็ว แต่ตัดสินจาก abstract ล้วน
- **ชั้น 2 — full text:** เฉพาะที่ผ่านชั้น 1 → อ่านเต็มเพื่อยืนยันเข้าเกณฑ์จริง + ดึงข้อมูลไปสกัด
- **จดเหตุผลที่ exclude** (เช่น "ไม่มี gold standard", "ภาษาอื่น", "n<20") — ทำ flow ได้ (เริ่ม N → เหลือ n) = reproducible

### 5 — สกัดลง **ตาราง** ไม่ใช่ย่อทีละเปเปอร์
| คอลัมน์ | จดอะไร |
|---|---|
| Author/ปี | อ้างอิง (เปิดต้นฉบับยืนยัน) |
| Population/n | ใคร, กี่ราย |
| Method/Test | data → วิธี → metric (ให้ทำซ้ำได้) |
| Key finding | ตอบคำถามไหม (ตัวเลขจากเปเปอร์จริง) |
| Limitation | จุดอ่อนที่จับได้ = lever ของเรา |

- ตารางบังคับให้เทียบ "ข้ามเปเปอร์" → เห็น pattern; ย่อทีละอัน = ได้แค่ list สรุป ไม่ใช่รีวิว

### 6 — สังเคราะห์เป็น theme/gap (หัวใจของรีวิว)
- จัดกลุ่มตาราง → **theme** (เช่น "กลุ่มที่ใช้ CBC index", "กลุ่มที่ใช้ molecular"): เห็นความเหมือน/ขัดแย้ง/ช่องว่าง
- **gap = contribution:** domain A × method B ที่ยังไม่มีใครจับคู่, หรือ "ทุกงานขาด external validation" → ที่เราจะตี (เจาะลึกการประเมิน gap → `critical-appraisal-judgment`)
- เขียนเป็น "narrative ตาม theme" ไม่ใช่ "เปเปอร์ 1 ทำ..., เปเปอร์ 2 ทำ..."

### 7 — รู้ว่า "พอ" เมื่อไหร่ (saturation) + เช็ค bias
- **อิ่มตัว** = ค้นคำใหม่/ไล่ reference (snowball) แล้วเจอแต่ของเดิม ไม่มี theme ใหม่ → พอได้. **ไม่ใช่** "อ่านครบทุกเปเปอร์ในโลก" (เป็นไปไม่ได้) แต่ก็ไม่ใช่ "ครบ 5 อันพอแล้ว"
- เช็ค bias ก่อนปิด: **publication** (ขาดผล negative ไหม) · **ภาษา** (ค้นแต่อังกฤษ ตกงานไทย/จีนไหม) · **เลือกเฉพาะที่หนุนตัวเอง**

### 8 — Log การค้น (ทำซ้ำไม่ได้ = ใช้ไม่ได้)
- จดทุกครั้ง: **แหล่ง · คำค้น/boolean เป๊ะ · วันที่ค้น · จำนวนที่เจอ**. วันนี้ค้นได้ 50 พรุ่งนี้ได้ 60 = ฐานข้อมูลอัปเดต ต้องระบุวันที่
- ⚠️ AI ค้นให้ = **ยังต้อง log + เปิดต้นฉบับเอง**; AI สรุปได้แต่ห้ามเชื่อ citation/ตัวเลขดิบโดยไม่ตรวจ (ดู `anti-hallucination`)

## กับดัก (Anti-patterns)
- **ค้นคำเดียว/แหล่งเดียว แล้วคิดว่าครบ** — ต้องหลายแหล่ง + synonym (OR) + grey literature
- **เริ่มเขียนก่อนตั้งเกณฑ์** → เลือกเฉพาะที่หนุนตัวเอง (cherry-pick); ตั้ง include/exclude เป็นลายลักษณ์อักษรก่อนค้น
- **ให้ AI สรุปเปเปอร์ที่ไม่ได้เปิดอ่าน** / ที่อาจไม่มีจริง — AI แต่ง citation เนียนมาก ต้องเปิดต้นฉบับทุกอัน
- **สรุปทีละเปเปอร์ ไม่สังเคราะห์** — list ≠ review; ต้องจัด theme + ชี้ gap
- **ลืม grey literature / ผล non-significant** → publication bias ภาพเอียง
- **ไม่ track วันที่ค้น + คำค้น** → ทำซ้ำไม่ได้ reviewer ถามตอบไม่ได้
- **อ่าน full-text ทุกอันตั้งแต่แรก** — เปลือง; คัด title/abstract ก่อน

## ช่องสำหรับผู้เชี่ยวชาญเติม
> เติมเคสจริงในสายงานคุณ เช่น:
> - *"(R2R/thesis) คำค้น + boolean ที่ผมใช้บน PubMed สำหรับหัวข้อ... คือ..."*
> - *"แหล่งที่คนมักลืมในสาย MT คือ... (เช่น registry/IFU/วิทยานิพนธ์ไทย)"*
> - *"theme/gap ที่ผมจัดจากกองเปเปอร์ แล้วกลายเป็น contribution คือ..."*
