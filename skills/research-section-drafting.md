# โค้ชร่าง 5 ส่วนงานวิจัยจากไอเดีย

มีไอเดีย/โจทย์วิจัยแล้ว อยากให้ AI ช่วย **ร่างบทนำ วิธี ผล อภิปราย** เป็นภาษาเขียนวิชาการให้เป๊ะ — แต่ต้องไม่โดน AI แต่งตัวเลข/อ้างอิงจนกลายเป็น misconduct → โค้ชนี้แบ่งให้ว่า **ส่วนไหนร่างได้เลย ส่วนไหนต้องรอข้อมูลจริง**

> **กฎ #1 (ด่านกันตาย): AI ร่างได้เฉพาะจาก "สิ่งที่คุณมีจริง"** — ผล ตัวเลข n p-value ค่า reference และ **citation/DOI** ที่ยังไม่มี = **ห้ามให้ AI แต่ง** (แต่งข้อมูล/อ้างอิง = fabrication/plagiarism = จบเห่ ทั้งตีพิมพ์และ ว.19). ทุกช่องที่ยังไม่มีจริง → เขียนเป็น **placeholder** `[ใส่ค่าจริง]` เสมอ ไม่ใช่ตัวเลขสมมติ.
> **กฎ #2: 3 ส่วนหน้า ร่างจากไอเดียได้เลย · 2 ส่วนหลัง ร่างได้แค่ "โครง+placeholder"** — บทนำ/ทบทวนวรรณกรรม/วิธี เขียนล่วงหน้าได้ (ยังไม่เก็บข้อมูลก็เขียนได้) · **ผล/อภิปราย เนื้อต้องรอ data จริง** ก่อนตีความ.
> **กฎ #3: objective = results = conclusion ต้องตรงกัน 3 ชั้น** — objective ถามอะไร ผลตอบอันนั้น สรุปแค่อันนั้น (รายละเอียดการกัน over-claim → `manuscript-judgment`).
> ลำดับ pipeline: `r2r-research-proposal` (ปั้นโจทย์) → `research-design-judgment` (design) → `choose-stat-test` + `r2r-stats` (สถิติ) → **ตัวนี้ (ร่างแต่ละส่วน)** → `manuscript-judgment` (กันโดน reviewer ตีกลับ)

## ใช้เมื่อ
- มีไอเดีย/objective แล้ว อยากได้ **ร่างแต่ละส่วน** (บทนำ/วิธี/ผล/อภิปราย) เป็นภาษาเขียนวิชาการ
- ไม่รู้ว่า **อะไรควรอยู่ส่วนไหน** / เขียนส่วนไหนได้ก่อนตอนยังไม่มีผล
- ต้องส่งแบบ **ว.19 เล่ม 5 ส่วน / thesis 5 บท / บทความวารสาร (IMRaD)** แต่งงว่า format ต่างกันยังไง

## วิธีใช้
วาง skill นี้ + บอก AI **3 อย่าง**:
1. **ไอเดีย/objective** (ศึกษาอะไร เพื่ออะไร)
2. **format เป้าหมาย** (ว.19 5 ส่วน · thesis 5 บท · journal IMRaD)
3. **สิ่งที่มีจริงแล้ว** (design, n, ผลเบื้องต้น, reference ที่อ่านจริง) — อันไหนยังไม่มี บอกว่า "ยังไม่มี"

→ AI จะ **ร่างเฉพาะส่วนที่ข้อมูลพอ** และ **ใส่ placeholder** ในช่องที่ยังไม่มี ไม่เดาแทน

## วิธีตัดสินใจ (AI: ทำตามนี้)

### Fork A — เลือก format ให้ตรงงาน (แล้ว map หัวข้อ)
เลือกก่อนร่าง เพราะ "5 ส่วน" กับ IMRaD **ไม่ใช่อันเดียวกัน** — ยัดผิดแบบ = ตีกลับ

| ว.19 เล่ม 5 ส่วน | thesis 5 บท | journal IMRaD |
|---|---|---|
| 1. บทนำ | บทที่ 1 บทนำ | Introduction (+ Objective) |
| 2. เอกสารและงานวิจัยที่เกี่ยวข้อง | บทที่ 2 ทบทวนวรรณกรรม | *(ยุบรวมใน Intro)* |
| 3. วิธีดำเนินการวิจัย | บทที่ 3 ระเบียบวิธีวิจัย | Methods |
| 4. ผลการวิจัย | บทที่ 4 ผลการวิจัย | Results |
| 5. สรุป อภิปรายผล ข้อเสนอแนะ | บทที่ 5 สรุป/อภิปราย | Discussion + Conclusion |
| *(+ บทคัดย่อ ขึ้นก่อน)* | *(+ บทคัดย่อ)* | Title + Abstract (≤250–300 คำ) + References |

- **ว.19 / thesis:** แยก "ทบทวนวรรณกรรม" เป็นส่วน/บทของตัวเอง · **ว.19 (งานราชการ)** มักให้เน้น **การนำไปใช้จริง (implementation)** + ผูกมาตรฐาน/ยุทธศาสตร์ (thesis/journal ทั่วไป **ไม่บังคับ** ส่วนนี้ — ใส่เมื่อ rubric ขอ service impact)
- **journal:** ทบทวนวรรณกรรมยุบเข้า Intro · คุม Abstract ~250–300 คำ · ref format ตามวารสาร (Vancouver/APA)
- ⚠️ **ตารางนี้ = ค่า default ที่พบบ่อย ไม่ใช่กฎตายตัว** — จำนวนส่วน/บท ความยาว abstract style อ้างอิง ต่างกันตามหน่วยงาน/วารสาร → **ยึดคู่มือ ว.19 ฉบับหน่วยงาน / author guidelines ของวารสารเป็นหลักเสมอ**

### Fork B — "ร่างได้ตอนนี้ไหม" (ด่านกัน fabrication — สำคัญสุด)
เช็คทุกส่วนก่อนลงมือ:

> **โหมดอ้างอิง (เลือกก่อน):** AI **ค้นเว็บ/เปเปอร์ไม่ได้ → no-source mode** — ใส่ `[ต้องหา ref จริง]` ทุกจุด **ห้ามเดา author/ปี/DOI** · AI ค้นได้ หรือคุณป้อน source เอง → **source-grounded** — อ้างเฉพาะจากที่ verify แล้ว + แนบที่มา

**🟢 ร่างจากไอเดียได้เลย (ยังไม่ต้องมี data):**
- **ชื่อเรื่อง** — กระชับ บอกได้ว่าศึกษาอะไร ไม่ claim เกิน
- **บทนำ** — ที่มา/ความสำคัญ/ปัญหา → gap → objective (แต่ **ทุกประโยคที่อ้างข้อเท็จจริง/ตัวเลข ต้องมี citation จริง** ตามโหมดข้างบน)
- **objective / คำถามวิจัย / ขอบเขต / นิยามศัพท์ / ประโยชน์ที่คาดว่าจะได้รับ**
- **ทบทวนวรรณกรรม** — โครง + กรอบแนวคิด (citation ต้องเป็นเปเปอร์จริงที่คุณอ่าน)
- **วิธีดำเนินการวิจัย** — เฉพาะ **โครง/แผน** (รูปแบบวิจัย ชนิดข้อมูล ลำดับขั้น) ร่างก่อนเก็บข้อมูลได้ · แต่ **ค่าเฉพาะ — n จริง, เลข EC, รุ่นเครื่อง/reagent/lot, ชื่อสถิติที่ใช้จริง = placeholder** จนกว่าจะมี protocol อนุมัติ/บันทึกจริง

**🟡 ร่างได้แค่ "โครง + placeholder" (เนื้อรอ data จริง):**
- **ผลการวิจัย** — วางหัวข้อ/ตารางเปล่าตาม objective ได้ แต่ค่า = `[n=__]` `[mean±SD=__]` `[p=__]` `[r=__]` **ห้ามใส่เลขสมมติ**
- **อภิปราย** — วางโครง "สรุป→เทียบงานเดิม→contribution→ข้อเสนอแนะ" ได้ แต่ **การตีความต้องรอผลจริง** (จะเทียบว่า "สูง/ต่ำกว่างานเดิม" ได้ต่อเมื่อมีเลขของตัวเอง)
- **บทคัดย่อ** — เขียนจริงเป็นอันสุดท้าย หลังมีผลครบ (ห้ามมีข้อมูลที่ไม่อยู่ในเล่ม)

**🔴 AI ห้ามสร้างเองเด็ดขาด:**
- ตัวเลขผล / p-value / n / ค่าเฉลี่ย / ค่า reference range จริง
- **citation / DOI / ชื่อผู้แต่ง / ปี** — ถ้า AI ให้มา = สงสัยไว้ก่อน **เปิดเช็คทุกอันว่ามีจริง** (ดู `anti-hallucination` · `source-credibility-judgment`)
- **เลข/สถานะ EC** — ห้ามแต่งเลข approval และ **ห้ามให้ AI ตัดสินเองว่า "exempt"** · เขียนตามจริง: ชื่อ EC + ประเภทมติ (approval/exempt/waiver) + เลข + วันที่ · ยังไม่ได้ → "อยู่ระหว่างยื่น/พิจารณา" (ไม่ใช่ approved) — ดู `r2r-research-proposal`
- **PII** — ไม่ใช่แค่ชื่อ/HN · **cell เล็ก, วันที่, ชื่อ รพ./หน่วยงาน ก็ re-identify ได้** → de-identify/aggregate (ดู `phi-data-handling`)

### Fork C — แต่ละส่วนต้องมีอะไร (เช็กลิสต์ตอนร่าง)
- **บทนำ:** ที่มา/ความสำคัญ → **ช่องว่าง (gap) ชัด** → objective คม · ไม่ใช่ review ยาว
- **ทบทวนวรรณกรรม (ว.19/thesis):** เกณฑ์ ว.19 มักขอ **~10 เรื่องขึ้นไป** — แต่ **เน้นตรงประเด็น/ทันสมัยพอชี้ gap ได้ ไม่ใช่ไล่นับให้ครบ** (ยึดจำนวนขั้นต่ำที่หน่วยงานกำหนดถ้ามี) + gap analysis + กรอบแนวคิด · citation จริงเท่านั้น
- **วิธีดำเนินการ:** รูปแบบวิจัย · ประชากร/กลุ่มตัวอย่าง (ที่มาของ n → `sample-size-power`) · ช่วงเวลา · **เครื่องมือ** (รุ่น/reagent/lot/QC/calibration) *แยกจาก* **บริบทมาตรฐาน/accreditation** (เช่น ISO 15189 = ระบบคุณภาพแลป ไม่ใช่สเปกเครื่อง) · การเก็บข้อมูล · **การวิเคราะห์สถิติ** (ระบุ test → `choose-stat-test`; รายงาน effect size/CI ไม่ใช่แค่ p; assumption/missing data → `r2r-stats`) · **จริยธรรมวิจัย/EC** — ละเอียดพอ **ทำซ้ำได้**
- **ผลการวิจัย:** เรียง **ตาม objective** · เชิงพรรณนา → เชิงวิเคราะห์ · **รายงานทุกตัวแปรที่ตั้งไว้ ไม่ใช่เฉพาะตัวที่ sig** · ตาราง/รูป **ไม่ซ้ำข้อมูลกัน** · **รายงานผลเฉยๆ ไม่แปลผล** (ยกไป discussion)
- **สรุป/อภิปราย:** สรุปตาม objective → **เทียบงานเดิม (เหมือน/ต่าง + ทำไม)** → ชี้ **สิ่งที่งานนี้เพิ่ม (contribution ในขอบเขตงาน)** → ข้อเสนอแนะใช้จริง + วิจัยต่อ · **ไม่ over-claim**
- **เลือก reporting guideline ตามชนิดงาน** (กัน reject เชิงรูปแบบ): observational → STROBE · diagnostic accuracy → STARD · RCT → CONSORT · systematic review → PRISMA · case report → CARE · QI → SQUIRE

### Fork D — tense / น้ำเสียง
- **tense ขึ้นกับว่าเขียนตอนไหน:** proposal/ก่อนเก็บข้อมูล → Methods = **อนาคต** ("จะเก็บ...") · manuscript/เล่มจบ → Methods & Results = **อดีต** ("เก็บ...", "พบว่า...") · Intro/Discussion = **ปัจจุบัน** เสมอ (thesis บางที่มี style เฉพาะ — ยึดคู่มือ)
- **ไทยวิชาการ = impersonal/passive** ("ผู้วิจัยได้ทำการ..." / "พบว่า...") ไม่ใช่ "ผม/ฉันคิดว่า"
- โทน **สุขุม อย่าโม้** — เลี่ยง "ครั้งแรกของโลก / ground-breaking / พิสูจน์ได้แน่นอน" (reviewer จับโทนเกินจริง)

## กับดัก (Anti-patterns)
- **ให้ AI เขียน Results/Discussion ทั้งที่ยังไม่มี data** → AI เติมตัวเลขสมเหตุผลให้ = **fabrication** (ร้ายแรงสุด จบเห่)
- **เอาเลขจากเปเปอร์ตัวอย่างมาใส่เป็นผลของตัวเอง** — เช่นเห็น "FVIII 131.81 IU/U" ในเปเปอร์คนอื่นแล้ว AI ยกมาใส่ = ผิดทั้งข้อมูลผิดทั้ง plagiarism
- **AI แถ citation/DOI มาเอง** → มักครึ่งหนึ่งไม่มีจริง/มั่วปี-ผู้แต่ง · ต้องเปิดเช็คทุกอัน
- **แปลผลใน Results** / **เอาผลใหม่ไปโผล่ครั้งแรกใน Discussion** (ผลต้องอยู่ Results ก่อน)
- **objective ≠ result ≠ conclusion** · **conclusion over-claim** (correlation→causal, n เล็ก/pilot→generalize, in-vitro→ฟันธงคน)
- **HARKing — เห็นผลก่อนแล้วค่อยเขียน objective/สมมติฐานให้ตรงผล** = ผิดจริยธรรม (objective ต้องตั้งก่อน) · การวิเคราะห์ที่คิดทีหลังให้ label ว่า exploratory
- **รายงานเฉพาะตัวที่ significant (selective reporting)** — ซ่อนตัวแปรที่ตั้งไว้แต่ไม่ sig = bias · ต้องรายงานทุกตัวที่ pre-specify
- **ลืมจริยธรรมวิจัย/EC ในวิธี** → ว.19/reviewer/วารสารตีกลับ (ต้องมีก่อนเก็บข้อมูลด้วย — ดู `r2r-research-proposal`)
- **paraphrase / paste จากเปเปอร์ใกล้เกินไป** — เอาตาราง/รูป/ย่อหน้าเต็มไปให้ AI rewrite = ยังเสี่ยง plagiarism/ลิขสิทธิ์ · สรุปจากความเข้าใจ + cite
- **ทบทวนวรรณกรรมต่ำกว่าเกณฑ์หน่วยงาน / ไม่มี gap analysis** (ว.19 มักขอ ~10+ แต่วัดที่ตรงประเด็น ไม่ใช่จำนวนล้วน)
- **ใช้ format ผิดประเภท** — ยัด IMRaD ลงเล่ม ว.19 (ที่ต้องแยกบททบทวนวรรณกรรม) หรือกลับกัน
- **เขียนสวยหรูจน AI-สำนวน** — humanize + ให้ MT ตรวจให้เป็นเสียงตัวเอง (ดู `humanize-ai-writing` · `writing-judgment`)

## ตัวอย่างจริง (worked example — cryoprecipitate)
ไอเดีย: *"ปัจจัยที่มีผลต่อปริมาณ FVIII และ fibrinogen ใน cryoprecipitate ที่ผลิตในภาคบริการโลหิตของเรา"* (retrospective) — format ว.19
- 🟢 **บทนำ** ร่างได้เลย: CRYO คืออะไร, FVIII/fibrinogen = ตัวชี้วัดคุณภาพ, เกณฑ์ AABB/EU, **gap:** ปัจจัยการผลิตในบริบทเรายังไม่ได้วิเคราะห์เป็นระบบ → objective (citation อ้าง review/เปเปอร์จริงที่อ่าน)
- 🟢 **วิธี** ร่างได้เลยเป็นแผน: retrospective, `[N=__]` units, ตรวจ FVIII/fibrinogen ที่ QC, สถิติ Pearson correlation, **EC: exempt/approval `[เลข__]`**
- 🟡 **ผล** วางโครงได้ แต่ค่าเป็น placeholder: ค่าเฉลี่ย FVIII = `[__ IU/U]`, fibrinogen = `[__ mg/U]`, ปัจจัยที่ sig = `[__ (r=__, p=__)]` — **ห้าม** ใส่ 131.81 IU/U จากเปเปอร์ตัวอย่าง
- 🟡 **อภิปราย** วางโครง "เทียบเกณฑ์มาตรฐาน + งานเดิม" ได้ แต่ตีความ ("ผ่านเกณฑ์/ปัจจัยไหนเด่น") **รอผลจริง**
