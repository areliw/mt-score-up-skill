# Feedback — บอกเราหน่อยว่าใช้แล้วเป็นไง

คลังนี้เป็น **กองกลางที่ทุกคนช่วยกันลงขัน** — ไม่ใช่รุ่นพี่สอนรุ่นน้องทางเดียว แต่ทุกคนเป็นทั้งคนให้และคนรับ
feedback ของคุณคือวิธีที่กองกลางฉลาดขึ้น: skill ผิด → คนต่อไปไม่โดนพา, skill ขาด → มีคนเติม, skill ช่วยจริง → เรารู้ว่าอะไร work แล้วทำเพิ่ม

> ทุก skill ตอนนี้ = `draft` ยังไม่ผ่าน clinical peer-review · เป็น **ตัวช่วยคิด ไม่ใช่คำสั่งทางคลินิก**
> ยิ่งคุณบอกว่ามันพลาดตรงไหน ยิ่งช่วยให้คลังนี้ปลอดภัยขึ้นสำหรับ MT คนต่อไป

## 1. เจอจุดผิด / อันตราย (เร่งด่วน)

เนื้อหาผิด · อ้าง guideline ตกรุ่น (ISO/AABB/CLSI edition เก่า) · breakpoint/dose/ค่าผิด · ตรรกะ fork พาผิดทาง

**ทำไมต้องด่วน:** correction ของงานคลินิก = **ปกป้องคนไข้โดยตรง** ถ้า skill บอกให้ release K⁺ จากตัวอย่าง hemolyzed หรือ under-call MRSA แล้วมีคนเชื่อตาม คนที่เจ็บคือคนไข้ ไม่ใช่เรา เพราะงั้นจุดผิดเชิงคลินิก **เราจัดเป็นลำดับแรกเสมอ**

➡️ **[เปิด Correction issue](../.github/ISSUE_TEMPLATE/correction.md)** — บอก: ไฟล์/fork ไหน · ผิดตรงไหน · ที่ถูกควรเป็นอะไร + แหล่งอ้างอิง · ระดับความเสี่ยง (🔴 กระทบความปลอดภัย / 🟡 ตกรุ่น / ⚪ พิมพ์ผิด)

ไม่มี GitHub → ดู[ด้านล่าง](#ช่องสำหรับคนไม่มี-github) (ถ้าเป็น 🔴 บอกในข้อความว่า "ด่วน-เชิงคลินิก" จะได้ดูก่อน)

## 2. ใช้แล้วเป็นไง (ช่วยหรือไม่ช่วย)

นี่คือ **adoption signal** — บอกเราว่า skill ไหนช่วยตัดสินใจได้จริงหน้างาน อันไหนถูกทางแต่ยังไม่ครบ อันไหนทำให้งง

เราอยากรู้เป็นพิเศษ:
- เอาไป**ใช้กับงานอะไร** (เคสจริง / เตรียมสอบ / ซ้อมตอบ reviewer / สอนน้อง)
- **fork ไหน กับดักข้อไหน** ที่ตรงจุด หรือที่ขาด
- ใช้กับ **AI ตัวเล็ก/มือใหม่** หรือ **ตัวท็อป** — เพราะจากการ eval ภายใน skill มักช่วย model เล็ก/คนมือใหม่ได้มากกว่า ส่วน model ตัวท็อปมักเสมอ (ดู [`eval/`](../eval/)) เราเลยอยากเก็บหลักฐานจากคนใช้จริงว่ามัน rescue มือใหม่ได้แค่ไหน

➡️ **[เปิด Skill feedback issue](../.github/ISSUE_TEMPLATE/skill-feedback.md)**

ไม่มี GitHub → **[Google Form](https://forms.gle/cWivk9zh6hJ5vdiy5)** หรือ**ทักเพจ Score UP** — ดู[ด้านล่าง](#ช่องสำหรับคนไม่มี-github)

> 💡 วิธีสมทบที่มีค่าสุดคือเติม **"ช่องสำหรับผู้เชี่ยวชาญเติม"** ที่มีอยู่ท้าย skill ทุกอันด้วยเคสจริงของคุณ (de-identify ก่อน) — ดู [`contributions/README.md`](../contributions/README.md)

## 3. อยากได้ skill ที่ยังไม่มี

มีการตัดสินใจในสายงานคุณที่ยังไม่มีใน 94 skill? อยากแชร์วิจารณญาณหน้างานเข้าคลัง?

**ไม่ต้องเขียน skill เอง** — แค่เล่า "เลือกอะไรเมื่อไหร่ + กับดักที่คนพลาด" เดี๋ยว maintainer + AI เรียบเรียงให้ (พร้อม credit ชื่อคุณ)

- **ไม่รู้จะใช้ skill ตัวไหนอยู่แล้ว?** แปะ [`prompts/triage.md`](../prompts/triage.md) ลงแชต AI → มัน route ให้ ถ้าไม่มีตรง มันจะช่วยสร้างลิงก์เสนอ skill ใหม่ให้
- ➡️ **[เปิด Skill proposal issue](../.github/ISSUE_TEMPLATE/skill-proposal.md)** — ตอบตามหัวข้อ ไม่ต้องจัดรูปแบบ
- รายละเอียดเต็ม + ตัวช่วยร่างด้วย AI → [`CONTRIBUTING.md`](../CONTRIBUTING.md)

## ช่องสำหรับคนไม่มี GitHub

MT หน้างานส่วนใหญ่ไม่เล่น GitHub — ไม่เป็นไร ส่งได้ทั้ง **ข้อความ / เสียง / รูปโน้ตมือ**

1. *(ไม่บังคับ แต่ช่วยมาก)* ร่างให้เนียนก่อนด้วย AI — แปะ [prompt ตัวช่วยร่างใน CONTRIBUTING.md](../CONTRIBUTING.md#-ตัวช่วยร่างด้วย-ai) ลง ChatGPT/Claude/Gemini แล้วเล่าปัญหา → ได้ draft พร้อมส่ง + มันเตือนให้ลบข้อมูลคนไข้ก่อน
2. ส่งทาง **[Google Form](https://forms.gle/cWivk9zh6hJ5vdiy5)** (เร็วสุด · ไม่ต้อง login)
3. หรือ **ทักเพจ Score UP** ก็ได้

> ⚠️ **ก่อนส่งทุกครั้ง: ลบข้อมูลที่ระบุตัวตน** — ชื่อคนไข้ / HN / ชื่อ รพ. / ชื่อบุคลากร · ใช้ placeholder แทน (`[ผู้ป่วย]`, `[รพ.]`). คลังนี้เป็นของสาธารณะ ถ้าไม่แน่ใจ consult MT head / QC manager ก่อน

## feedback แล้วเกิดอะไรต่อ (loop)

```
คุณส่ง feedback
   │
   ▼
maintainer triage  ──► dup? · ต้อง verify กับ MT อีกคน? · เป็น judgment ไม่ใช่ knowledge?
   │
   ▼
แก้ / เพิ่ม skill   ──► correction = แก้ตรง · feedback = ปรับ fork/กับดัก · proposal = AI แพ็กเป็น skill ใหม่
   │
   ▼
บันทึกใน CHANGELOG.md  +  credit คุณ
```

- **maintainer playbook** (วิธี triage form submission → issue → PR) อยู่ที่ `contributions/INTAKE.md`
- ทุกการแก้/เพิ่มที่ลงคลังจะถูกบันทึกใน [`CHANGELOG.md`](../CHANGELOG.md) — โปร่งใส ตรวจสอบย้อนได้
- correction เชิงคลินิก (🔴) เข้าคิวก่อน
- คนที่ส่งจะได้ credit (เมื่อมี contributor คนแรก คลังจะเปิด `CONTRIBUTORS.md`)

## หลักการที่เราถือ

- **honesty มาก่อน:** ทุก skill เป็น `draft` ยังไม่ผ่าน clinical peer-review เราจะไม่เคลม "verified/validated/รับรองทางคลินิก" — credibility ของกองกลางมาจากความซื่อสัตย์
- **judgment ไม่ใช่ knowledge:** เราเก็บ "เลือกอะไรเมื่อไหร่ + กับดักที่ผู้เชี่ยวชาญรู้แต่ตำราไม่เน้น" ไม่ใช่ตำราที่ AI รู้อยู่แล้ว
- **กันห้องสมุดถูกเผา:** วิจารณญาณของ MT ที่กำลังเกษียณคือสิ่งที่ feedback แบบ proposal ช่วยเก็บไว้ไม่ให้สูญ — feedback ของคุณคืออิฐก้อนหนึ่งที่ทำให้ MT รุ่นใหม่ "ไม่เคว้ง ไม่โดนเจื๋อน"
