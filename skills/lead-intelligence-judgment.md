# หา+คัดกรอง+เข้าหา lead B2B

MT ที่ย้ายไปสายขาย IVD/diagnostics ต้องหาเองว่า **แล็บ/รพ.ไหนคุ้มที่จะวิ่ง** แล้วเข้าให้ถูกคน-ถูกจังหวะ — skill นี้ช่วยให้คะแนน lead จากสัญญาณ, จัดลำดับว่าใครคุ้มก่อน, หาทางเข้าแบบ warm, และร่าง outreach ให้ตรงคน ไม่ใช่หว่าน

> **แกนตัดสิน:** อย่าวิ่งทุกแล็บเท่ากัน — คะแนน lead = ICP ตรง **และ** มี buying signal ตอนนี้ **และ** เหมาะกันสองทาง (mutual fit). คัดออกเร็วสำคัญพอๆ กับหาเข้า. (รายละเอียด Fork 1-2)
> **⚖️ ก่อนเริ่มเก็บ/ใช้ข้อมูล lead:** ต้องมีฐานทางกฎหมาย (PDPA) + เคารพนโยบายองค์กรลูกค้า — **ห้ามใช้ข้อมูลส่วนบุคคลที่ได้มาโดยมิชอบ หรือข้อมูลภายในของนายจ้างเดิม**; ยึดข้อมูล professional/สาธารณะ. (ดู `digital-judgment`)

## ใช้เมื่อ
- มีรายชื่อแล็บ/รพ. กองหนึ่ง ไม่รู้จะเริ่มวิ่งใครก่อน — อยากจัดลำดับ
- กำลังสร้าง target list ใหม่ในเขต/จังหวัดที่รับผิดชอบ
- รู้จักที่หมายแล้ว แต่ไม่รู้จะเข้าหาใคร/ผ่านใคร (หา warm path)
- จะร่างข้อความเปิด (LINE/อีเมล/เข้าพบ) ให้ตรงคน ไม่ใช่ก๊อปหว่าน
- อยากรู้ว่าควร follow-up เมื่อไหร่ จี้แค่ไหนถึงไม่น่ารำคาญ

## วิธีใช้
วาง skill นี้ + เล่ารายชื่อ lead ที่มี (ประเภทแล็บ, ใช้เครื่องเจ้าไหน, รู้จักใครข้างใน, จังหวะที่รู้) → AI ช่วยให้คะแนน + จัดลำดับ + เสนอ warm path + ร่างข้อความเปิด พร้อมเตือนกับดักที่ทำให้เสียดีล/เสียเครดิต

## วิธีตัดสินใจ (AI: ทำตามนี้) — forks

### Fork 1 — ให้คะแนน lead จากสัญญาณ (signal scoring)
ให้คะแนนแต่ละ lead แล้วเรียง สูง→ต่ำ ก่อนลงแรง:

| สัญญาณ | น้ำหนัก | ดูจากอะไร (สาย Dx) |
|---|---|---|
| ICP fit — ประเภท/ขนาดแล็บตรงของที่เราขาย | 30% | รพ.ระดับไหน, volume test, แผนกที่มี |
| buying signal ตอนนี้ | 25% | กำลังต่อ ISO 15189, สัญญาเครื่องเจ้าเดิมจะหมด, เปิด test ใหม่, ขยายแล็บ |
| pain ที่ของเราแก้ได้ตรง | 20% | TAT ช้า, QC เปลือง, คนไม่พอ, ของขาด |
| อำนาจ/ความง่ายในการตัดสิน | 15% | หัวหน้าแล็บเซ็นเองได้ vs ต้องเข้า e-bidding ยาว |
| งบช่องที่อนุมัติเร็ว | 10% | งบดำเนินงาน(น้ำยา) > งบลงทุน(เครื่อง) |
> สัญญาณสด (ข่าวต่อ accreditation, ประกาศจัดซื้อ, เพิ่มเตียง) ถ้า AI ดึงเน็ตได้ให้ดึง; ถ้าไม่ได้ ให้ผู้ใช้เติมจากที่รู้หน้างาน

### Fork 2 — mutual ranking: เขาเหมาะกับเราไหม ไม่ใช่แค่เราอยากได้
ก่อนจัดลำดับ ตัดเกรดด้วยคำถาม "เหมาะกันสองทางไหม":
- ของเรา **แก้ pain เขาได้จริง** หรือแค่เราอยากขาย? (แก้ไม่ได้ → ดึงออก)
- งบเขาอยู่ช่องที่เราเสนอลงได้ไหม? (เครื่องก้อนใหญ่ให้แล็บงบลงทุนตัน = ไม่เหมาะ)
- ผูกสัญญาเจ้าเดิม **ยาว/เพิ่งเซ็น** ไหม? → ใส่ "nurture ยาว" ไม่ใช่ "วิ่งปิดตอนนี้"
- LIS/ระบบเขาเชื่อมของเราได้ไหม? เชื่อมไม่ได้ = deal breaker → ลดเกรด

VERDICT: lead จริงที่ควรวิ่ง = **ICP ตรง + มี signal + แก้ pain ได้ + งบเข้าช่อง + เชื่อมระบบได้**. ขาดข้อใดข้อหนึ่งหนักๆ → ย้ายไปถัง nurture/ตัดออก ไม่ใช่ดันต่อ

### Fork 3 — หา warm path (ทางเข้าที่อุ่นกว่า cold)
เรียงความ "อุ่น" ของทางเข้า มาก→น้อย:
1. **คนรู้จักในวงเดียวกันแนะนำ** — เพื่อน MT ที่ทำงานแล็บนั้น/เคยเรียนด้วยกัน/เครือข่ายวิชาชีพ
2. **เคยเจอกันจริง** — งานประชุมวิชาการ, อบรม, EQA workshop, สัมมนาบริษัท
3. **อ้างอิงลูกค้าเดิม** — แล็บข้างเคียงที่ใช้ของเราอยู่แล้ว พูดถึงได้
4. **คนกลางในองค์กร** — เคยคุยกับ จนท.แผนกอื่น/จัดซื้อที่รู้จัก
5. **cold ตรง** — ไม่มีสะพานเลย → เปิดด้วยสิ่งที่เจาะจง+สดของแล็บนั้น
> มี path อุ่นกว่าเสมอ → ใช้อันบนสุดก่อน. ขอแนะนำตัวผ่านคนกลาง: ขอชัดข้อเดียว + บอกเหตุผลที่ intro นี้สมเหตุผล + แนบข้อความสั้นให้เขา forward ง่าย

### Fork 4 — personalize outreach (เปิดให้ตรงคน ไม่หว่าน)
ก่อนร่าง: ดึงของจริงเฉพาะ lead นั้น (ต่อ accreditation อยู่, เพิ่ง publish, เปิดแผนกใหม่) มา 1 จุด
- **เปิดจากสิ่งเจาะจง+สด** ของแล็บเขา ไม่ใช่ "เรียนผู้เกี่ยวข้อง"
- **บอกว่า fit จริงตรงไหน** (เชื่อมกับ pain เขา ไม่ใช่อวดสเปก)
- **ขอแบบ low-friction ข้อเดียว** (ขอเข้าไปคุย 15 นาที / ส่งข้อมูลให้ดู) ไม่ใช่ขอลอยๆ "อยากทำความรู้จัก"
- **เลือกช่องทางเดียวเป็นหลัก**: warm intro > เข้าพบ/โทร > อีเมล > LINE/ข้อความ. หลายช่องพร้อมกัน = ดูสแปม

### Fork 5 — จังหวะ follow-up (จี้แค่ไหนถึงพอดี)
| สถานการณ์ | จังหวะ | ระวัง |
|---|---|---|
| หลังเปิดครั้งแรก ยังเงียบ | ตาม 1 ครั้ง ใน 3-5 วัน เพิ่มมูลค่าใหม่ (ไม่ใช่ "ตามอีกครับ") | ส่งซ้ำคำเดิม = น่ารำคาญ |
| คุยแล้วบอก "ไว้ก่อน" | ถามจังหวะที่เหมาะ + ใส่ nurture ยาว | จี้ถี่ = ปิดประตู |
| ใกล้ช่วงต่อ accreditation/หมดสัญญาเครื่อง | เข้าจังหวะนั้นพอดี = จังหวะทอง | พลาดหน้าต่าง = รออีกรอบงบ |
| ตอบ "ไม่สนใจ" ชัด | หยุด + ขอกลับมาทักรอบหน้า | ดันต่อ = เสียเครดิตถาวร |

## กับดัก (Anti-patterns)
- **วิ่งทุก lead เท่ากัน** — ไม่ให้คะแนน/ไม่จัดลำดับ → หมดแรงกับ lead ที่ไม่มีวันปิด
- **จัดลำดับด้านเดียว** (เราอยากได้) ไม่เช็ค mutual fit → ดันดีลที่ของเราแก้ pain เขาไม่ได้
- **ข้าม warm path ไป cold ทันที** — ทั้งที่มีเพื่อน MT อยู่ในแล็บนั้น = ทิ้งแต้มต่อฟรี
- **outreach ก๊อปหว่าน** — ข้อความเดียวส่งทุกที่ เห็น merge field/ไม่มีอะไรเจาะจง = โดนเมิน
- **ขอเยอะ/ขอลอยในข้อความแรก** — หลาย ask หรือ "อยากทำความรู้จัก" → ไม่มีใครตอบ
- **follow-up ถี่/ส่งคำเดิมซ้ำ** — จี้จนน่ารำคาญ = ปิดประตูถาวร แทนที่จะ nurture
- **ลืม PDPA/ความยินยอม** — เก็บ/ใช้ข้อมูลติดต่อบุคคลต้องมีฐานทางกฎหมาย + เคารพนโยบายองค์กรลูกค้า (ดู `digital-judgment`); ห้ามใช้ข้อมูลที่ได้มาโดยมิชอบ

> - *"(MT sales) lead ที่ผมจัดว่าน่าวิ่งสุด ดูจากสัญญาณ... แล้วปิดได้เพราะ..."*
> - *"warm path ที่เวิร์กสุดของผม คือเข้าผ่าน... เพราะ..."*
> - *"ข้อความเปิดที่ลูกค้าตอบกลับบ่อย คือเปิดด้วย... / จังหวะ follow-up ที่พอดีคือ..."*
>
> เชื่อมต่อ: ขายผลลัพธ์บริหารให้ตรง pain → `ivd-sales-judgment` · จิตวิทยาโน้มน้าว/เปิดใจ → `sales-psychology-judgment` · เก็บ-จัดการข้อมูล lead/ลูกค้าให้เป็นระบบ → `crm-judgment` · PDPA/จริยธรรมข้อมูล → `digital-judgment`
